1. 研究定位

逻辑层上放几个 SM，GPU 近存论文在 TOM 之前已经做过。这篇管的是后面两步：哪段指令下沉，以及下沉之后数据落在哪一栈。编译器按片外带宽收支标候选块；运行时用 kernel 开头一小段执行学会栈映射，并且这套映射只打在候选块会碰到的页上。CUDA 源码不用改。

基线 68 个 SM；近存配置是 64 个主 SM 加 4 个逻辑层 SM，总数没变。加速来自把访存密集段挪到数据旁边，不是多给算力。仿真平台是 GPGPU-Sim 3.2.0 + BookSim，能耗用 GPUWattch 和 Rambus 的 3D DRAM/TSV 模型。

2. 片外带宽，以及两道题

GPU 应用经常被主存带宽卡住。三维堆叠把很宽、更省能的接口接到处理器，逻辑层还可以就近放计算，用 TSV 吃到比片外引脚更高的带宽。先前工作已经给出性能和能效数字，但落地时有两道题要一起解；已有方案多半把它们甩给程序员。

图 1. 两道题互相牵制。访存密集块适合下沉，但下沉之后如果数据仍按主 GPU 的打散映射铺开，逻辑层 SM 大量走栈间交叉链路，近存等于白做。

动机实验把上限先量出来。无卸载开销、代码与数据完全共址的理想系统里，只靠静态选出的候选就能平均加速 1.58×（最高 2.19×）。近存已经打开时，只用最好的连续两地址位做栈映射，相对当时 GPU 的打散映射还能再加速 13%。数字够大，所以他们做透明机制，而不是再加一套 API。

3. 主 GPU + 栈上 SM

近存 GPU 在这里不是“整个 kernel 搬进内存”。主 GPU 留大量 SM 做高算术强度段；每个 3D 内存栈的逻辑层放一个 SM，就近跑带宽密集块。栈与主 GPU 之间是类似 HMC 的单向高速链路；栈与栈之间另有交叉链路，给远程访存用。

图 2. 四个内存栈，每栈逻辑层一个 SM。片外链路吃引脚预算；栈内 TSV 提供更高内部带宽。Offload Controller 和 Channel Monitor 一直在；映射分析器只在学习期工作。

4. 编译器怎么选候选

估的不是延迟，是片外带宽收支。一块代码卸到栈上，收益是这块里的 load/store 不再走 GPU↔栈链路；代价是把 live-in 寄存器送进栈、把 live-out 送回主 GPU。静态扫描指令块，总带宽变化为负就标成候选。

图 3. 卸载改的是片外链路上走什么。单向链路上 load 走 TX 发地址、RX 收回数据；store 走 TX 发地址加数据、RX 收回确认。

4.1 先按线程、再按 warp 修正

单线程近似：

BWTX = REGTX − (NLD + 2 · NST)
BWRX = REGRX − (NLD + ¼ · NST)

GPU 以 warp 锁步执行，还会合并访存、按 cache line 取数。warp 粒度公式引入 warp 宽度 SW（如 32）、cache line 相对地址的倍数 SC（128B line / 4B 地址 = 32）、合并比 Coal 和 load 缺失率 MissLD：

BWTX = (REGTX · SW) − [NLD · CoalLD · MissLD + NST · (SW + CoalST)]
BWRX = (REGRX · SW) − [NLD · CoalLD · SC · MissLD + ¼ · NST · CoalST]

live-in / live-out 编译器本来就要做寄存器分配，适合静态算。合并比和缺失率静态不知道，于是用保守估计：完美合并（Coal = 1）、缺失率 50%。宁可少选。更激进的阈值能多找出候选，实验里看不到稳定收益。

4.2 循环

循环的卸载代价几乎固定（live-in/out 一次），收益随迭代次数放大。编译器分三种情况。

图 4. 循环候选的三种处理。LIBOR 是中间那种：两段循环各 5 个 live-in、1 load、1 store，阈值写进硬件提示。

4.3 块不能跨过的东西

逻辑层 SM 碰不到主 GPU 的 shared memory，再走片外就和近存目标反了。SIMT 分歧若跨过卸载边界，控制栈要分布在主 GPU 与各栈之间，所以所有控制流目的地必须仍在候选块内。主 GPU 与逻辑层之间也没有 barrier / sync / atomic。含这些东西的块不下沉。

图 5. 候选是指令块，不是整个 kernel。实现上分析的是 CUDA 编译器产出的 PTX（GPGPU-Sim 吃 PTX）；同一套收支也可以做到 SASS。每个候选附一张元数据：起止 PC、live-in/out 位图、TX/RX 是否省带宽的 2-bit 标签、条件卸载谓词。表放在 shared memory，给 Offload Controller 读。

5. 近存页和其余页两套映射

页落在哪一栈，由驱动、运行时、内存控制器在运行期决定，静态编译解不了。观察是：85% 的卸载候选存在固定偏移访存；其中六个应用的候选几乎全是固定偏移。偏移若含 2 的幂因子，若干低位地址恒定，用连续地址位做栈索引就能把同一块访问钉在同一栈。

图 6. 四栈系统只需 2 bit 选栈。候选位落在固定偏移能提供的恒定位、与 cache line 偏移之间。

5.1 用开头 0.1% 实例预测

执行中途再搬页，栈间拷贝很容易把近存收益吃光。GPU 访存多由线程 / 线程块索引生成，模式在线程间高度一致。只看前 0.1% 卸载实例选出的映射，单栈命中率已达 72%，距全量先知的 75% 只差 3 个点。0.5%、1% 再看一点，收益递减。

5.2 双轨：近存页一套，其余页另一套

近存单元要数据靠近计算；主 GPU 要数据打散以吃满带宽。同一套映射满足不了两边。做法是推迟 CPU→GPU 物理拷贝，先在学习期看哪些分配区间会被候选块碰到，再在本来就要做的那次拷贝里分两套映射写下去。

图 7. 学习期走 PCIe，延迟按实测计入。拷贝仍是那一次 HtoD，只是写物理页时用了两套栈索引。

6. 运行时闸门

编译器只提名。真卸载由硬件在发射前拍板。无控制地卸光候选会让系统变慢 3%–7%：逻辑层 SM 的 warp 槽先满，主 SM 空等。LIBOR 最极端，无控制 −64%，加上控制则 +52%。被卸载指令占比从 46.4% 降到 15.7%。少卸、卸对，比卸满重要。

图 8. 两道闸门先滤掉会把系统卡死的候选，再用第一条访存定目的栈。控制把卸载指令占比从 46.4% 压到 15.7%。

7. 流水线、一致性、虚地址

7.1 三个新硬件件

插在典型 GPU 流水线旁。Offload Controller 做最终决策、打包请求、收 ACK 后恢复 warp；Channel Busy Monitor 报 TX/RX 忙；Memory Map Analyzer 只在学习期工作。ISA 增加一条“候选块开始”指令；元数据表由编译器生成。

7.2 不做全系统缓存一致性

把传统一致性扩到主 GPU 与各栈缓存，状态和片外一致性流量可能比卸载省下的带宽还多。GPU 编程模型帮了忙：CTA 绑在特定 SM 上，CTA 之间无序、无一致性保证；CTA 内要靠程序员显式 barrier。卸载块不含同步指令，于是只需保证“请求者 SM 与代执行的栈 SM”这一对看到最新值。

图 9. 作用域停在“这一对 SM”，不做芯片级目录。栈 SM 要记本块写过哪些 line，结束时随 ACK 送回。

7.3 虚地址在栈内翻译

逻辑层 SM 自带小型 TLB/MMU（约 1–2K 触发器加少量逻辑，不到栈 SM 面积的 2%）。页表若不在本栈，走已有交叉链路。卸载发生在内存拷贝和页表更新完成之后，不需要栈侧 TLB shootdown。

7.4 面积

主要是存储：每 SM 的映射分析器 1920 bit（40 bit × 48 warp，覆盖 10 种四栈映射）、共享分配表约 9700 bit（最多 100 条）、每 SM 元数据表 10320 bit（40 项，按工作负载最大值的 2 倍）。40nm CACTI 合计 0.11 mm²，约所建模 GPU 面积的 0.018%。

8. 评测

工作负载取 Rodinia 3.0、GPGPU-Sim 科学核和 CUDA SDK 中带宽利用率 >50% 的应用。计算密集型没有候选，性能不受影响。跑完或 20 亿指令取齐。主指标是相对无近存基线的 IPC。

8.1 控制 + 透明映射要一起开

图 10. 理想共址给出上限。全套 TOM（动态控制 + tmap）平均 +30%，全部应用正加速。无控制把 LIBOR 打到 −64%；闸门打开后同一应用变成 +52%。

图 11. 左：KM、RD 对共址极敏感。右：能耗下降主要来自更短的执行时间和更少的片外翻转；只降流量、拉长墙钟时间会把漏电吃回去。

8.2 逻辑层算力：寄存器比完整 SM 更值钱

卸载块最大 live 寄存器 26，整线程 49。逻辑层寄存器堆若做到与主 SM 同规模，理论上可跑约 2× warp。把 warp 容量提到 4×（ctrl-4×-warp）：平均仍约 +29% 加速，流量再多省约 20 个点，达到 −34%，接近无控制的 −38%。RD 是例外——卸载块里过半是 ALU，并行 warp 一多，逻辑层计算流水线先满。作者认为下一步应把 ALU 占比也纳入卸载闸门。

8.3 并不依赖“TSV 内部带宽远大于引脚”

许多 3D 近存论文默认栈内带宽远高于片外。TOM 在内部=外部（1×）时平均仍 +28%，相对 2× 内部带宽只差约 2 个点。原因是主 GPU 经常被 TX 或 RX 单方向卡住；逻辑层 SM 经封装内互连直连内存控制器，能把另一方向空着的内部带宽用上。

图 12. 默认 0.5× 交叉链路已经接近饱和。内部带宽打平片外时，加速几乎不掉，靠的是方向不对称，不是“TSV 一定比引脚宽很多”。

9. 相关工作与边界

作者自认是第一份在多栈 GPU 近存上同时做到：(1) 从未经修改的程序自动找出下沉指令块；(2) 把这些块访问的数据映射到同一栈。先前 PIM / 3D 近存（Tesseract、PEI、NDA、HRL、TOP-PIM 等）要么要程序员标、要么不管多芯片映射、要么不是 GPU。最接近的 Lee 等 FlexRAM 编译调度估的是延迟而非 GPU 的带宽，且假设单内存芯片。

数据靠近计算在 NUMA/NUCA 里研究很多。这里的差别主要是执行引擎异构，映射目标互相冲突；近存 SM 上不跑系统软件，页在启动前分配完毕，复杂的运行期迁移不划算，所以用“短学习 + 推迟拷贝”这种一次性放置。

候选粒度为指令块而非 kernel；不含同步与 shared memory，复杂协作 kernel 能下沉的比例有限。学习期走 PCIe，短 kernel 或高度不规则图应用可能学错。评测没有计算密集型，也没有现代 LLM 那种巨型权重 / KV 工作集。仿真是 2016 年 Maxwell 量级，HBM 时代的绝对带宽数字不能直接外推。结构上能留下来的是：带宽收支编译、异构双映射、运行时闸门。

10. 同封装近存推理能借什么

对照形态：中央通用处理器裸片 + 多个 3D-DRAM 近存张量模块；权重与 KV 驻留近存；预填充注意力核心留中央，译码注意力下沉近存。TOM 的 SM 卸载不能照搬，但几处判断仍然有用。按这个形态展开的部署方案（8 栈、Decode / Prefill 两种拼法）写在 8栈近存大模型部署.html。

图 13. 能借的是“提名 / 映射分轨 / 运行时限流”这张分工，不是 2016 年的 SM 和 2-bit 栈索引。

预填充的 QKV / 输出投影可以双侧分担；注意力核心算术强度高、还要全局 Softmax，默认不要下沉。译码 KV 与历史键值同栈，默认强制下沉。FFN 扩展维中间激活不要上送。权重是静态主副本，加载时按头 / 通道 / 专家固定下来，不必等 kernel 学习期。近存侧需要矩阵引擎和向量非线性，不是缩小版 CUDA SM。

KV 按头（或头组）绑定模块，专家按张量并行分片，中央只做归约与路由。这比学连续地址位更硬，也好验证。会话和前缀缓存不规则时，才用得上 TOM 那种短观测。近存打满时切第二模式（局部 Softmax 统计量上送中央合并），而不是把历史 KV 拉回中央——LIBOR 已经演示过，无控制会让近存算力先成为瓶颈。

程序员透明在推理栈上大概会变成框架透明：模型图和 KV 布局由运行时 / 编译器处理，算子作者不必手写模块亲和。对象从 CUDA kernel 换成 Transformer 图，机制从指令块收支换成子层落点与所有权。
