1. 一句话与数字

Hopper 上打满 Tensor Core，必须写「DMA warp 喂 TMA、四个 warp 一起发 wgmma、共享内存 barrier 串流水线」。Cypress 让程序员只写顺序任务 + 张量划分，把「跑在哪一级线程、数据落在哪块内存、管多深」单独写成映射；编译器推出全部拷贝与同步，生成接近 CUTLASS 主循环的静态代码。

目标不是再做一个「全自动、启发式决定一切」的 Triton，也不是再做一个「模板里全是 barrier」的 CUTLASS。主张是：难写且易错的（拷贝、同步、warp 特化）交给编译器；决定峰值的（切块、层级、内存落点、流水深度）留给人。映射只影响性能，不影响正确性。

2. Ampere 还能 bulk-sync，Hopper 不行了

Tensor Core 六年从 Volta 的 8×8×4 长到 Hopper 的 64×256×16。Volta/Ampere 是 8 或 32 个线程对寄存器发 MMA；Hopper 每个 SM 一块 Tensor Core，必须 128 线程（一个 warpgroup）协同发出，操作数拆在寄存器和共享内存两边。要喂饱它，还得用异步搬数单元 TMA。

图 1. 论文 Figure 1 的结构对照。Ampere 主循环仍是全体线程同一套预取–计算；Hopper 必须把线程拆成专职 DMA 与专职计算，再用 prod/cons barrier 对齐两条异步流水线。

图 2. Hopper 峰值要求深流水：TMA 吞吐量高、Tensor Core 吞吐量也高，任一侧露出延迟都会掉峰值。线程自己还要一边等固定功能单元、一边干 SIMT 活（softmax、reduction）。

CUTLASS / ThunderKittens

人写拷贝、barrier、warp 特化。模板拼 GEMM 很省事；一离开 GEMM 主循环（比如 Flash Attention），细节全砸在人身上。漏同步就是数据竞争。

Triton

人只写 block 级 tile，编译器启发式决定其余。省事，但 TMA 默认不用好、张量常被塞进次优内存。第 5 节融合核因此掉到 Cypress 的一半。

Cypress

人决定怎么切、映射到哪一级、数据落哪块内存；编译器保证顺序语义并插入全部异步与同步。中间道路。

3. 中间道路：逻辑任务 + 映射规格

多数任务系统（Legion、StarPU）靠运行时调度任务图。SM 里指令级没有这份开销的空间。Cypress 学 Sequoia：任务树必须能被完全静态分析，最后消掉任务抽象，只剩静态循环。

图 3. 程序两半。inner 变体禁止读张量内容，避免在「还没决定落哪块内存」时偷偷访问；leaf 不再 launch，可以把 PTX 交给 CuTe。NONE 内存表示「这一层不要物化整块累加器」，只允许往下分区后出现在寄存器里——做不到编译器报错。

构件作用为什么必须有
privilege（read / write / rw） 声明任务对张量的效应 依赖分析据此插事件；只读并行、写后读串起来
prange vs srange 算法上的并行 vs 必须按序（如 K 归约） 语义上 prange 效果等于 srange；实现上才能静态并行
blocks 划分 规则切块（SM / warpgroup 面板） 层级分解的通用手段
mma 划分 Hopper wgmma 规定的非连续花式布局 输出按 16 行分给 4 个 warp，列在 warp 内 swizzle，避免 bank 冲突
variant + tunable 同一任务名、不同层级不同算法 host 切大块、block 沿 K 累加、thread 发 wgmma，签名保持一致

4. 机器模型与 GEMM 任务树

不把 Tensor Core 画成单独处理器，而引入 warpgroup：能对 Tensor Core 发活的那一组线程。Blackwell 上「两 SM 共享更大 Tensor Core + 新的输出内存」可以用再加一层处理器、再加一种内存来接——模型故意做成可长层级的。

图 4. H100 机器模型（论文 Figure 2）。层级是给程序员对齐切分用的概念，不是再引入一套动态调度器。

Hopper GEMM 在 Cypress 里长什么样

同一任务名 gemm，每一级换一个变体。映射把树钉死：host 256×256 并行切块 → block 沿 K 顺序累加并请求 warp 特化、3 级流水 → tile 再按行分给 2 个 warpgroup → mma 划分到 warp/thread → leaf 调 CuTe_warpgroup_gemm。

图 5. 论文 Figure 5 的 GEMM 任务树。GLOBAL→SHARED 的映射变化本身就意味着通信；编译器用 TMA 实现。这就是「映射只改性能」的具体含义：换内存层级会改变插入的拷贝，但顺序语义由事件图兜住。

5. 编译器：从事件图到静态循环

原型走 MLIR，生成 CUDA C++（生产实现可以下到 NVVM）。SM 内没有动态运行时：任务抽象必须被消掉。

图 6. 编译器通路（论文 Figure 6）。事件只活在 IR 里，运行时不做依赖跟踪。

依赖分析：先无脑 copy-in/copy-out

按映射钉好的任务树先序遍历。每个 launch：为被调任务在指定内存新建一块；读则 copy-in；递归降被调变体；写则 copy-out。这样分析始终局部，编译器简单；多余拷贝交给后面消。并行组用事件数组的 [:] 广播表示「这一维全部完成」。

向量化：GPU 里那些隐式的 pfor

warp / thread 上的并行循环在 SIMT 里本来就是「每条线程跑自己那份」。压扁后，循环变量换成 warp_id() / thread_id()，事件数组多一维。点对点依赖写成 e[i,j]；循环后同步写成 e[i,:]。

图 7. 事件数组是向量化能保住依赖的关键（论文 Figure 9）。索引模式决定最后落到哪种硬件同步。

消拷贝：连同步一起偷走

模式类似 Sequoia：自拷贝删除、重复 copy-in 删除、spill 消除（子←父←子同一划分）、spill 外提（循环里反复父子互拷）。同一划分上的 copy-out 紧跟 copy-in，不但能删拷贝，还能把「先折叠事件数组再继续」还原成点对点——否则会留下多余的全员同步。模式顺序有讲究：能消事件的 spill 类要先于必须保留依赖的自拷贝类。作者提到 e-graph 等式饱和可以去掉这套启发式，但 MLIR 当时还没接。

共享内存：从完全干涉图往回松

Tensor Core 一块 tile 已经占掉很大一份 SMEM，多 CTA 占用还要再切。用户在映射里给每 block 一个 SMEM 上限；编译器先给所有张量两两加辅助边（强迫各用各的缓冲），再按 Knight 等人的静态分配策略逐步去掉辅助边，直到塞得进上限——等价于在预算内最少别名。别上同一物理缓冲的逻辑张量，要在「上一块最后读者」和「下一块第一写者」之间补事件，避免 WAR。

warp 特化 = 依赖图二分

图 8. 论文 Figure 12。全局到共享的拷贝一律划给 DMA；其余给计算。换一种划分策略就可以换一种特化（例如更多专职 warp）。作者发现「按 PIPE 压回」比真展开循环更省寄存器和 I-cache。

生成阶段：TMA 完成事件 → TMA 会 arrive 的 shared barrier；Tensor Core 完成 → wgmma 等待指令；跨 warp 边 → shared barrier（Hopper 多 CTA TMA multicast 必须用这种，而不是老的 named barrier）。仅含处理器下标的事件数组可以直接删——点对点已被 SSA 顺序满足。

6. 评测：能打专家库，打赢 Triton 启发式

平台：H100 80GB SXM5。GEMM 类用同一随机分布，压掉功耗墙抖动。Flash Attention 各系统对 CUDA 版本敏感，各自取最好的（FA3/cuDNN 偏爱 12.3.1）。Cypress 的映射是作者按已有算法手工调的，不是自动搜索。

内核对照Cypress说明
FP16 GEMM / Batched-GEMM cuBLAS、Triton cuBLAS 的 0.88–1.06×；Triton 的 1.05–1.11× 块内多 warpgroup 喂独立流水；最大 batched 甚至略超 cuBLAS
Dual-GEMM（GLU：A·B1 与 A·B2） Triton 1.36–1.40×，吞吐接近普通 GEMM Triton 没把 B2 的 load 和 A·B1 部分重叠，默认也不走 TMA
GEMM+Reduction Triton 2.02–2.18× Triton 等 Tensor Core 完才做 reduction，还把累加器启发式放进 SMEM；Cypress 映射进寄存器。把 Cypress 映射改糟，就能复现 Triton 的慢
Flash Attention 2 ThunderKittens、Triton TK 的 0.87–1.06×，明显快于 Triton 人看不见 warp 特化 / TMA / barrier
Flash Attention 3 官方 FA3、cuDNN 最好实现的 0.80–0.98× 算法里手写的交错通信，编译器从流水化后的主循环推断出来。短序列落后主要因为还没做 persistent CTA

图 9. 第 5 节格局。标准 BLAS 打平专家库；Triton 的启发式在 Dual-GEMM / GEMM+Reduction 上露馅。这正是「映射必须能被程序员拧」的实验证据。

一个反直觉结果：FA2 用三个消费 warpgroup（ThunderKittens 那套参数），靠调度器交错 Tensor Core 与 SIMT，不再保存第一段 GEMM 累加器副本，就能接近 FA3。说明这条性能地貌很陡，最快内核不好搜。短序列差距来自 persistent kernel——把映射到 BLOCK 的 prange 降到「每 SM 一个常驻 CTA」在模型里是说得通的，只是还没做。

7. 和 Sequoia / Halide / Triton 怎么站

图 10. Cypress 把 Triton「只在 block 切一刀」递归做到每一级，再用单独映射代替启发式；同时把 CUTLASS 里那些 barrier 藏进编译器。

写起来怎样

  • 加功能不怕和新划分打架：编译器维持顺序语义。
  • 单 warpgroup 改双 warpgroup：加变体、改映射，旧代码不动。
  • 代价是啰嗦——每次用张量都要写清划分，映射里多棵树会重复。CUTLASS 划分一次就能复用，但也因此一改就容易漏同步。
  • 调优主要改映射：变体组合、是否特化、流水深度、数据落点。CUTLASS 里数据落点往往要改代码；Triton 里这些旋钮根本拧不到。
结论可以收成一句：固定功能单元会继续变（Blackwell 已经在变），bulk-synchronous 不够用了。把计算写成顺序任务，把机器写成可长的层级，把异步交给静态事件图——这是 Cypress 给「库作者 / 新内核作者」的中间层，不是给最终用户再包一层框架。
