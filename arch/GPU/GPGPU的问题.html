GPGPU 的问题

程序员写的是「单线程」，机器执行的是「一捆线程」。错位出在哪，四类开销怎么长出来。

1. 错位：取指只做一次，别的各做一遍

SIMT 只把前端（取指、译码、一个 PC）做成一份；后端仍按 32 个独立线程付账——相同的 a、相同的基址、相同的循环计数，各存一份、各算一遍。这就是错位：看起来像向量机，用起来还是 32 份标量程序。

先看一句会误导的话

GPU 常被说成「32 条线程锁步执行同一条指令」。这句话只对了一半。对的是：warp 共用一个程序计数器，I-cache 只取一次、mul 只译码一次。错的是：人们以为「同一条指令」等于「相同的数据也只做一次」。硬件并没有标量通路——它不知道 a 对 32 条线程是同一个数，于是 32 个寄存器文件里各放一份 a，32 条 ALU 各乘一次。

只做一次 = 前端像向量

32 条线程共享 1 个 PC。取指、译码、发射各一次，结果广播给 32 条 lane。这是 SIMT 相对「32 个独立 CPU 线程」真正省下来的东西。

各做一遍 = 后端仍是 SPMD

每条线程自己的寄存器、自己的地址、自己的 if (i < n)。即便值相同，硬件也当 32 个私有变量。没有地方写「这份只做一次」。

图 1. 同一条 mul：取指是 1，a 的存放和无关地址计算仍是 32。错位 = 前端按向量计费，后端按线程计费。

对照着想：32 个 CPU 线程跑同一段 SAXPY，取指也是 32 次，更贵。SIMT 把这一层修好了。论文要说的是下一步还没修——和元素无关的那些活（系数、基址、循环记账、越界比较）在向量机上属于标量核，在 GPU 上仍混在每条线程里。后面「跨线程冗余」「没有标量通路」都是这条缝的具体表现。

图 2. 三层分工。程序员写单线程；编译器按单线程编；硬件只在取指这一层把 32 条捆在一起。错位发生在「捆在一起」没有继续传到寄存器和标量计算上。

四种模型：SIMD / SIMT / 向量 / 向量线程

同一段 CSAXPY（if (cond[i]) y[i] = a*x[i]+y[i]）可以落到四种汇编模型上。差别不在「能不能算」，而在：宽度写在哪、标量放哪、控制流谁管、指令流切几段。

先看一张总图：四种机器在干什么

图 A. 四种模型一句话。SIMD 把宽度写死；SIMT 把元素当成线程；向量用 VLR 动态定长；向量线程再把算术从剥带循环里拆出去。

同一次剥带，谁在执行什么

剥带（stripmine）= 把长度为 n 的应用向量切成硬件一次能吃下的块。四种模型切法不同。

图 B. n=100 时四种切法。SIMD 留下 0–3 的尾巴；SIMT 多启动空线程再自己 if 掉；向量把尾巴收进最后一次 vsetvl。

CSAXPY 四种汇编长什么样

图 C. 同一 CSAXPY 的四种汇编骨架。红/橙色是该模型多付的税：SIMD 的宽度和尾巴，SIMT 的越界和地址，向量线程则把税换成「两段指令流」。

标量放哪、分歧谁管

图 D. 两个正交轴。上：标量是一份还是 32 份。下：分歧是硬件栈、编译器谓词，还是 vf 块里的线程分支。

向量线程为什么要拆成两段（以及 Hwacha 改了什么）

图 E. 向量线程要解决的是：让访存跑在算术前面。Maven 用「访存留循环、算术进 vf」换预取，但把分歧和标量搞砸了。Hwacha 把整段向量指令都放进 vf，用 va 只读保证预取安全，用谓词和 vs 把 Maven 的两个弱点补上。

元素是什么 打包进一条宽指令的 lane 一条线程 向量寄存器里的第 i 个元素 vf 块对每个元素跑一遍

2. 问题一：跨线程冗余

程序员只能写 kernel 和网格尺寸，无法声明「这段对所有线程相同」。于是每条线程各自保存循环计数、基址、标量 a，各自做地址计算，各自加载同一份系数。

CSAXPY：同一条指令，32 份记账

条件 SAXPY：if (cond[i]) y[i] = a*x[i]+y[i]。向量机上 a、三个基址只存一份，地址加一次。SIMT 上每条线程自己做。

图 3. CSAXPY。SIMT 里每条线程复制 a 和三个基址，再各自做 tid 寻址和越界检查。向量机把这些留在标量核，每条向量指令只做一次。

FIR：共享系数被加载 32 遍

图 4. FIR。系数数组在内存里只有一份，SPMD 编码却让每条线程每轮都 load 一次。标量化后系数进共享标量，每 warp 只 load 一次。

SIMT 的取指是一份，执行和寄存器仍按线程复制。这是 SPMD 编码方式的结构性开销，不是写得不够好那么简单。

3. 问题二：用多线程藏延迟

地址流常常已知，但 GPU 选择切线程而不是预取：load 没回来就换另一条线程。代价是除了目的寄存器，其余线程状态都得停在片上。

图 5. 藏延迟的两种付费方式。GPU 用并发 warp 填空洞，所以寄存器文件必须装下所有停着的线程；向量机用预取填空洞，片上只缓存数据。

occupancy 被寄存器卡死

图 6. 吞吐量机器用 occupancy 藏延迟。谓词化或未经标量化的冗余一旦多占寄存器，能同时驻留的 warp 变少，切线程策略自己把自己卡死。

4. 问题三：硬件分歧栈

SPMD 允许任意嵌套 if、循环、虚函数、goto。对向量化编译器这是「优化失败就退回标量核」；对 GPU 这是功能正确性，没有退路。

if-then-else：一边跑、一边压栈

图 7. 分歧栈把「看起来并行的 if」做成「先跑一半线程、再跑另一半」。灰色格子是关闭的通道，ALU 仍在，只是被掩掉。

越分越窄，直到一次只跑一条

图 8. 有效 SIMD 宽度随嵌套分歧指数下降。这不是「有的线程没事做」那么简单，而是整个 warp 被锁进一条串行路径队列。

短接：部分会合点被串行掉

图 9. 短接表达式。硬件栈在立即后支配点才会合，中间的 N4 即使两边都会走到，也被序列化。谓词化按控制依赖生成掩码，可以在 N4 重新并起来。

语义也不真

warp 内线程并非真正异步。同步只能按 warp/CTA。硬件选哪条边先走不确定，编译器无法对路径做强分析。

和谓词同构

GPU 已有谓词和 cbranch.ifnone，与向量机 popcount 后标量分支同构。当时后端几乎只用于小 if。

不是性能必须

系统谓词化相对纯栈只慢 2.7%。栈留下是因为「让编译器当普通线程编译」这条哲学，不是因为更快。

5. 问题四：没有标量通路，地址也各算各的

论文做标量化实验时，真实 NVIDIA GPU 没有标量寄存器、也没有标量执行通路，只能跑内部模拟器。动态 coalescer 是同一症状：每线程自己算地址，硬件再把相邻访问拼回去。

图 10. 动态 coalescing 是在运行时修复 SPMD 造成的假象。单位步长本该是编译期事实，却被做成硬件通路。

图 11. Packed-SIMD 和 SIMT 的缺陷互补。传统向量用 VLR 同时要动态宽度和标量控制核。论文认为 GPU 为可编程性把分界划得太靠硬件。
