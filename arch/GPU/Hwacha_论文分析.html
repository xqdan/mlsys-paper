1. 一句话结论与研究定位

GPU 为了让程序员写单线程 kernel，把跨线程冗余和控制流分歧都压进了硬件。这篇论文的主张是反过来：编译器把 SPMD 程序里的标量部分抠出来、把复杂控制流压成谓词，硬件就可以回到更干净的向量机——这就是 Hwacha：解耦向量取指架构。

这篇不是一篇会议短文，而是 Yunsup Lee 的博士论文（157 页）。它把三件事钉在一起：对数据并行 ISA 的系统盘点、在 NVIDIA 生产 CUDA 编译器里做出来的标量化/谓词化、以及接到 RISC-V Rocket 上、走完 28 nm VLSI 并和 ARM Mali GPU 对打的 Hwacha 加速器。Maven 项目证明向量比 MIMD 更省面积和能量；Hwacha 则进一步把分歧管理从硬件拿回编译器，并加上轻量访问-执行解耦。

2. 问题：暗硅时代怎么做数据并行

Dennard 缩放在 90 nm 左右失效，晶体管不再能按比例降压；28 nm 之后单门成本开始上升。架构师仍能拿到更多晶体管，但它们既“暗”又不便宜。应对路径有两条：铺大量专用固定功能加速器（窄应用、百倍收益），或放少数可编程的通用特化单元（更宽覆盖、约十倍收益）。论文选择后者：向量、packed-SIMD、GPU 这类数据并行加速器。

关键设计问题随之变成：往这条红线上加什么特征，才能既抬高已有应用的性能/能效，又扩大可编程覆盖面，同时不把尾巴压回去？GPU 的答案是纹理缓存、超越函数单元、硬件分歧栈。论文的答案是：先把现有汇编模型和分歧方案的代价算清楚，再把一部分复杂度推回编译器。

Maven 留下的教训

向量架构确实比 MIMD 更省面积和能量；解耦能做非推测预取来藏访存延迟；分 bank 的向量寄存器文件面积效率高。失败点是：硬件分歧管理极难做对（一半以上调试时间花在这里）；缺少标量寄存器会伤性能和能效；多端口触发器寄存器文件面积差。

NVIDIA 实习带来的分界线

Maven 之后作者在 NVIDIA 做了三年生产 CUDA 编译器。结论是：编译器-架构边界可以重划——让编译器承担更多，硬件更简单也更高效。第 3–5 章的标量化与谓词化，就是这条分界线的实验证据。

3. 四种汇编模型：SIMD / SIMT / 向量 / 向量线程

上层语言主要是两类：隐式并行的自动向量化（写串行循环，编译器抽并行），以及显式并行的 SPMD（CUDA / OpenCL，程序员写单线程 kernel 再网格启动）。SPMD 对程序员友好，但把大量负担甩给硬件：跨线程冗余无法表达、复杂控制流必须被正确执行。汇编层则决定这些负担落在谁身上。

论文用带条件的 SAXPY（CSAXPY：if (cond[i]) y[i] = a*x[i] + y[i]）把四种模型摊开对比。

图 1. 四种汇编模型的核心取舍。Packed-SIMD 把宽度写死；SIMT 丢掉标量；传统向量两者都要；Hwacha 再把向量指令从控制核流里拆出去，换来访问-执行解耦。

Packed-SIMD 和 SIMT 的缺陷几乎互补：前者死在静态宽度，后者死在没有标量。传统向量用向量长度寄存器（VLR）同时解决这两件事——vsetvl 取应用向量长和硬件向量长的较小值，同一份代码能跑在任意宽度上，尾部也不再需要特殊代码。Hwacha 在此之上把整段向量指令抬进独立的 worker thread。

4. 标量化编译器：向量化的镜像

向量化编译器从单线程循环里抽出可并行部分，放到数据并行单元，把记账、地址、共享数据留在标量核上。标量化编译器方向相反：从已经显式并行的 SPMD 程序里，找出其实该只做一次的部分，映射回标量资源，再把剩下的并行部分高效铺到向量/SIMT 单元。

图 2. 向量化从串行里挖并行；标量化从并行里挖“其实该标量做”的部分。两者最终都要把工作拆到标量核和数据并行单元，只是起点相反。

SPMD 有两类隐藏开销，对应标量化编译器的两道 pass：

开销 1：跨线程冗余

程序员只写 kernel 和网格尺寸，无法声明“这段对所有线程相同”。循环计数、基址、系数加载、共享行向量会被每条线程各做一遍。SIMT 只摊了取指，执行和寄存器仍然按线程复制。

开销 2：复杂控制流

嵌套 if、循环、虚函数、goto 在 SPMD 里是功能正确性要求，不能像向量化那样放弃并退回标量核。GPU 因此做了分歧栈。论文用谓词 + 一致分支把这件事交回编译器。

5. 机制一：收敛 + 方差分析做标量化

要把每线程一份的寄存器/指令收成每 warp 一份，编译器必须同时证明两件事：收敛（这一组线程现在停在 CFG 的同一点）和不变（这个变量在各线程上取值相同）。论文的关键观察是：这两件事必须在同一趟分析里互相传播，不能拆开。

FIR 滤波器：冗余长什么样

每个线程算一个输出点：把 flen 个输入和同一组系数做卷积。常规编译结果里，每条线程都保存循环计数、结束条件、基址，并且每轮都重复加载同一份系数。32 线程 warp 上，常规代码用 9 个私有寄存器/线程（288 个寄存器槽）；标量化后是 2 个私有 + 6 个共享（70 个槽），少 76%。动态源操作数少 79%，执行操作少 85%，每轮地址从 64 个降到 2 个。

图 3. FIR 例子里，系数、基址、循环记账对所有线程相同，应收成每 warp 一份；只有 sample 和累加器是私有的。单位步长访存变成 ldvec / stvec，不再依赖硬件动态合并。

联合分析算法

  1. 乐观初始化。所有基本块标为收敛，所有指令标为线程不变。工作表只放入：读线程号、原子操作、volatile 访存。
  2. 沿 SSA 传播方差。弹出一条线程可变指令，把它的数据流后继加入工作表。
  3. 沿控制依赖传播分歧。若该指令是条件分支，则把它迭代控制依赖的后继块标为分歧（含 syncthreads 的块除外），块内指令全部入表。
  4. 不动点结束。没被访问到的块/指令分别保持收敛和线程不变，即可标量化。

收敛的形式定义比“立即后支配点”更强：在该点放线程组屏障永远不会失败——要么全到，要么全不到。仅看 CFG 形状只能证明 32% 的动态指令收敛；耦方差分析升到 57%；“提前退出线程可视为收敛”再升到 66%。再加一个极简硬件机制（各线程动态走向相同时不让 warp 分歧），可到 97%，与动态神谕持平。

仿射分析再进一步：若地址能写成 base + sizeof(T) * tid.x，就把标量/线程访存改成向量 load/store。这既省地址生成，也为后面 Hwacha 的非推测预取提供了静态可识别的单位步长流。

6. 机制二：线程感知谓词化

NVIDIA 用分歧栈隐式管理控制流：warp 在分支处分叉，一边继续、一边把 PC 和掩码压栈，在立即后支配点会合。编译器也可以显式做：谓词守卫 + 一致分支（所有线程谓词相同时才跳）。向量机上的 vpopcnt + 标量分支，和 GPU 上的 cbranch.ifnone 是同构的。

图 4. 分歧栈把路径序列化进硬件；谓词化让编译器按控制依赖图生成守卫，用一致分支跳过全假区域。会合点两者相同（立即后支配点 / 循环所有出口的后支配点），只是谁来调度不同。

线程感知之处

经典 if-conversion 只优化单线程。SPMD 还要：所有路径都必须被部分执行（正确性）；分歧后必须再会合（效率）；寄存器压力直接决定 occupancy；以及能标量的控制/数据应尽量不谓词化。算法建立在带标签的控制依赖图上：

  • 谓词节点插在基本块之间，明确“这段代码由哪个谓词守卫”。
  • 循环加上 loop mask（谁还在圈内）、exit mask（从哪个出口离开）、continue mask（本轮是否该跳回）。
  • 静态分支一致性：能证明谓词线程不变，就保留原控制流、去掉守卫，减轻寄存器压力。
  • 运行时分支一致性：对无法静态证明的 SESE 区域插入一致分支，谓词全假时整段不取指。
  • 用结构分析把 if/loop/acyclic 层次化，再反向 DFS 后序遍历，把同一结构的块排成连续线性序，避免多余跳转。
  • 不可约区域走逃生舱：入口/出口处把活跃线程一个个串过去。
在 Tesla K20c（Kepler GK110）上，相对纯分歧栈基线：裸谓词化慢 11.3%；加上静态一致性优化快回 4.7%；再加运行时检查再快 3.9%。最终平均只慢 2.7%；若逐 kernel 挑最好配置，只慢 0.6%。NVIDIA 自带的有限 if-conversion 启发式几乎不改变平均性能。软件方案的主要收益不是立刻更快，而是拿掉硬件分歧栈、让执行顺序对编译器确定——短接表达式可以在部分会合点并行，方差分析也更强，从而给标量化让路。

谓词化会抬高寄存器压力（分配器不能轻易在分支两侧复用同一寄存器），部分 kernel occupancy 下降，这是少数明显变慢案例（bfs、b+tree、srad）的主因。虚函数调用可用一条 find_unique 把唯一目标地址和对应线程掩码拆出来，按约定用入口掩码谓词化被调函数，直到所有活跃线程都序列化完。

7. Hwacha：控制线程 + 工作线程

有了标量化编译器，传统向量机可以保持和 GPU 同级的可编程性，同时更高效、也更好编译。Hwacha 再进一步：用 vf（vector-fetch）把向量指令流拆成独立工作线程，换来轻量的访问-执行解耦。它是 RISC-V 的非标准扩展，挂在 Rocket 的 RoCC 口上。

用户可见状态

向量侧

vv0–255 数据寄存器（8/16/32/64 位整数，半/单/双精浮点）；vp0–15 1 位谓词。硬件向量长可按寄存器用量重配，但至少保证 8；vlen=0 时所有向量指令空操作。

两种标量

vs0–63 向量共享寄存器（vs0 硬连线 0），工作线程可读写；va0–31 地址寄存器，工作线程只读。这个只读约束让 VRU 能非推测地预取，且不会和执行单元互相等待而死锁。

图 5. CSAXPY 在 Hwacha 上的形态。相对传统向量，剥带循环里的向量操作全部抬进 worker；对这个例子标量指令大约少 15%，更复杂的循环收益更大，控制核也更能跑在前面。

六条架构决策

1. 用预取藏延迟

GPU 靠多线程：整份线程状态都得停在片上。地址流已知时，预取只需缓存数据本身。Hwacha 的 VRU（访问）和 VXU（执行）解耦；worker 不能写 va，所以 VRU 不必等执行单元做决定，无死锁风险。

2. 用标量化吃均匀操作数

约三分之一的操作和寄存器访问可静态标量化。共享值进 vs，向量指令可直接读它们。控制核也可用 vmcs 写入。

3. 用谓词管控制流

所有向量指令（含 gather/scatter）可谓词化。一致分支支持 ifnone / ifall / ifany。谓词逻辑是三输入 + 8 项真值表。谓词可溢出到内存。

4. 可重启异常做虚存

vf 块里地址都是虚地址。保存/恢复微架构状态以支持可重启异常，也供 OS 抢占。另有 fence 规定控制线程与工作线程之间的访存序。不靠重命名，允许向量指令部分完成。

5. 可重配硬件向量长

vsetcfg 按 64/32/16 位向量寄存器和谓词数量重切寄存器文件。寄存器少则向量更长；寄存器多用完编码空间也不轻易溢出。比 GPU 按 warp 量子化 occupancy 更细，也更不敏感。

6. 混合精度

宽数据通路按元素切开，窄类型更密地填进同一份 VRF，吞吐上升、向量更长、更利于解耦藏延迟。单个向量寄存器的精度可独立配置，不像 VPW 一刀切。

8. 解耦微架构：VRU / VXU / VMU

Hwacha 作为独立加速器插在 Rocket Chip 的 RoCC 插座里，有自己的前端和 4 KB 向量指令缓存。Tile 经 TileLink 接到分 bank、对 L1 全包含的共享 L2。向量单元走 uncached TileLink（不持有私有副本），但与 L1 D$ 保持一致性，所以控制核和加速器共享同一虚地址空间，汇编模型不必拆两套内存。连 L2 而非 L1，是用更高带宽换更长平均延迟，因此合并访存更重要。

图 6. Hwacha 解耦加速器。控制核只把命令丢进队列；VRU 跑在前面预取；标量单元消化 vf 块里的标量指令；各 lane 的 VXU/VMU 独立滑行，只在归约和一致分支时由主 sequencer 对齐。

收缩期银行：用 1R1W SRAM 冒充多端口

每个 lane 四个 bank，每个 bank 一块 256×128-bit 的 1 读 1 写 8T SRAM，外加操作数锁存器。微操作（读寄存器、写入锁存、送到交叉开关、启动功能单元、写回）从 bank0 注入，每周期向下一个 bank 走一步。经过 n 拍启动延迟后，共享功能单元可持续每拍拿到 n 个操作数。向量链式执行来自不同 sequencer 操作的 μop 交错；lane sequencer 像非推测的乱序发射窗，按条带（8 个 64 位元素，即一轮扫过四个 bank）挑选无冲突操作。

VRU 的预取在多数情况下是非推测的：地址寄存器和向量长不能被 worker 改写。它最多占用 L2 未完成跟踪资源的三分之一。启动时故意丢掉前一两个 vf 块的预取，换稳态下更大的领先距离；再用“已解码但尚未被执行单元消耗的字节数”做节流，并在每个 vf 块结束时与谓词/一致分支造成的未执行访存对账。

9. 评测：面积、性能、能耗

目标是用同一套 OpenCL 源码，比较真实 VLSI 数字和商业 GPU，而不是手写汇编自嗨。Hwacha 走 Chisel → 综合/布局布线 → 门级仿真拿周期和翻转，再结合版图做功耗；对照物是 ODROID-XU3 上的 Samsung Exynos 5422（ARM Mali-T628 MP6，同为 28 nm 量级）。SoC 参数按 Mali 对齐：16 KB L1、4×64 KB L2、双通道 933 MHz LPDDR3。Mali 以两核设备（Mali2）和四核设备（Mali4）分别跑；论文因时间只完整评了单 lane Hwacha，对 Hwacha 并不占便宜。

性能格局

axpy：访存受限

混合精度几乎没用。Mali2/Mali4 快 1.5–2×。论文归咎于外层内存调度器与 DRAMSim2 默认参数不匹配，而不是向量模型本身。

gemm：计算 + 寄存器复用

双精两边一样（FMA 数量相同）。半精提升最明显，但受 Amdahl 限制达不到理想 4×。手优汇编可把数据留在 VRF 跨 vf 块复用，比 OpenCL 快一个数量级（sdgemm-opt 约 14×，hsgemm-opt 最高 19×）——这被看作 OpenCL 编程模型的根本限制。

filter / mask-filter

基线与混合精度接近；半精有可见加速。Mali2 大约是 Hwacha 的一半，Mali4 与 Hwacha 持平。谓词化路径被 mask 版本直接练到。

单 lane Hwacha 的算术带宽低于 Mali4（不到一半），也略低于 Mali2（时钟没到理想 1.2 GHz）。在这个前提下，gemm 和 filter 已经能打平或超过 Mali，说明效率来自更少的冗余、更好的寄存器利用和解耦预取，而不是堆执行单元。gemm 上 Mali 异常慢，论文怀疑工作集没进缓存，这一组对照不能算完全公平。

能耗与性能大体同形。Hwacha 用 1 V 超驱换 1 GHz，Mali 是 0.9 V。axpy 上 Mali 更省（与它更快一致）；降低精度时混合精度 Hwacha 的能耗优势逐渐显现。额外功能单元的时钟门控不够好，是混合精度在“没有性能收益”的双精 kernel 上更费能量的原因。

10. 贡献、边界与对后续架构的含义

三条贡献

  1. 盘点数据并行汇编模型和分歧方案。Packed-SIMD、SIMT、传统向量、向量线程各自把宽度、标量、控制流放在不同层；分歧管理往往决定整机组织。
  2. 标量化编译器。收敛+方差联合分析，把 SPMD 里的冗余收成每 warp 一份；线程感知谓词化把任意嵌套控制流映射到谓词和一致分支。两者都在 NVIDIA 生产 CUDA 工具链里落地，并在硅上量过。
  3. Hwacha 解耦向量取指。控制/工作双线程、非推测访问-执行解耦、可重配向量长、混合精度、可重启异常，Chisel 实现并在 28 nm 与 Mali 对照。

不要过度解读的边界

  • Hwacha 评测是微基准，不是完整应用；完整评测只有单 lane。
  • OpenCL 无法表达跨 vf 块的寄存器驻留，手优汇编和编译器代码之间有巨大鸿沟。
  • 相对 Mali 的面积对比含估算（缩放到 6-lane、扣除图形单元），不是同功能单元的精确 iso-area。
  • 软件分歧管理在占用率敏感的 kernel 上仍会输给硬件栈；论文自己也说寄存器分配和自适应一致性检查还没做完。
  • Hwacha ISA 后来没有成为 RISC-V 标准 V 扩展。论文第 7.3 节已预告：标准 V 会走传统向量（向量指令混在控制流里、32 位编码），以便和 AVX/NEON 类实现竞争。Hwacha 的 vf 解耦是更激进的另一条设计点。

对同封装 / 近存 / 加速器设计的含义

这篇论文真正可迁移的不是“再做一个 Hwacha”，而是那条编译器-硬件分界线：SPMD 的可编程性不必用硬件分歧栈和巨大线程状态来买。如果编译器能证明收敛和不变，硬件只需要一份标量、一份谓词和可重配的长向量；如果地址流在 vf 边界上冻结，预取可以既准确又便宜。后续 RISC-V Vector、以及各种把 SIMT 往“更像向量”拉的 GPU/NPU 设计，都走在这条线上。代价也同样清楚：编译器必须把控制流线性化做好，编程模型若不允许跨块寄存器复用，峰值效率会留在桌上。

谱系上，Hwacha 是 Berkeley 向量线的第四代：T0（1990s）→ Scale 向量线程（MIT）→ Maven（硬件管分歧）→ Hwacha v1–v4（本学位论文记录的是 v4：全部向量指令进 vf 块、全谓词、一致分支、四块 128-bit SRAM 翻倍吞吐）。它和 Raven（28 nm 片上 DC-DC）以及 EOS（45 nm）多次流片绑在一起，是 RISC-V 早期加速器生态里最完整的一次“编译器 + RTL + VLSI + 对照商业 GPU”闭环。
