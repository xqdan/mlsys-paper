1. 一句话结论

HIP/OpenCL 程序员看到的是 SIMT：每个 work-item 好像有自己的 PC，可以独立走 if/else。 CDNA5 硬件并没有给 32 条 lane 各配一套取指。它发的是一条向量指令，用一张 EXEC 位掩码决定哪些 lane 真正写结果、哪些当成 NOP。 分歧控制流由编译器用 SALU 改 mask、用标量分支跳过整波，而不是硬件为每条线程改 PC。

ISA 原文（§2）：「Conceptually, the shader program is executed independently on every work-item, but in reality the processor groups up to 32 work-items into a wave, that executes the shader program on all 32 work-items in one pass ("wave32"). … Active work-items execute the vector instruction, and dormant ones treat the instruction as a NOP.」

2. 硬件把 SIMT 拆成什么

CDNA5 的调度粒度是 wave，不是单条线程。一条 wave 绑在某一个 SIMD32 上， 共享一份 PC、一份 SGPR 文件、一份 EXEC。VGPR 才是 per-lane 的：每条 work-item 有自己的 v0…v1023（32-bit × 32 lane）。

2.1 层次

图 1. ISA 给出的网格层次：Grid → Cluster → Work-group → Wave → Work-item。SIMT 幻觉发生在最底层 wave 内部。

2.2 一个 WGP 里有什么

ISA 把 Work-group Processor 定义为「基本计算单元」，有时也叫 Double Compute Unit。 每个 WGP 有 4 个 SIMD32（两个 CU，每个 CU 两条 SIMD32 共享一条访存通路）。 同一 work-group 的 wave 可以分布在这 4 个 SIMD 上，靠 LDS / WGP$ 通信、靠 barrier 同步。

图 2. WGP 内部：向量算在 SIMD32 上，控制流算在 SALU 上。EXEC 是 wave 状态，不属于单条 lane 的「私有 PC」。

标量侧（整波一份）

SALU、SMEM、PC、SGPR、SCC、EXEC、分支、barrier。ISA 明确：EXEC 不影响 标量执行和分支。

向量侧（32 lane 一份数据）

VALU、VMEM、LDS。受 EXEC 过滤：mask=0 的 lane 当 NOP，不写 VGPR / 不发有效访存。

3. EXEC mask：真正的「线程开关」

EXEC 是 64-bit 寄存器，每位对应一条 lane：1 = 执行，0 = 不执行。 Wave32 只用 EXEC[31:0]，高 32 位硬件不看。配套有一位摘要 EXECZ （低 32 位是否全 0），专门给 s_cbranch_execz 做「整波都没人活着，直接跳过这段」的快路径。

3.1 一条向量指令实际在干什么

图 3. 同一条 v_add_f32 对 32 条 lane 一起发射。灰色 lane 的加法硬件可以算也可以不算，但写回被禁止，看起来就像这条线程没执行。

ISA §3.2.2：EXEC 影响 VALU、向量访存、LDS；不影响标量执行和分支。 所以 s_add、s_cbranch_* 永远按「整波」语义走——分歧不能靠标量指令「只跳一部分线程」。

3.2 EXEC==0 时硬件可以整条跳过

若当前 EXEC 全 0，再跑 then/else 体是浪费。ISA §3.2.2.1 允许硬件把部分向量指令直接 skip， 效果与「执行但 EXEC=0」相同：波状态不变。规则很细：

  • 普通 VALU：EXEC==0 时可跳过；但写 SGPR/VCC 的 VALU 不跳（比较结果仍要写 mask）。
  • WMMA 不跳；V_NOP / V_READLANE / V_WRITELANE 等不跳。
  • VMEM 仅当 EXEC==0 且相关 outstanding 计数为 0 才可跳，以免搞乱 LOADcnt / STOREcnt。
  • V_CMPX 之后是否跳过取决于时序，不保证。

编译器通常还会先发 s_cbranch_execz，从软件上把「全灭」的基本块剪掉。 硬件 skip 是锦上添花，不是控制流的主机制。

4. 例子：if / else 如何被 mask 模拟

下面用 8 条 lane 把 wave32 缩起来看（真实 CDNA5 是 32 位，算法一样）。 源程序每个线程都像有自己的 if；机器上是：先向量比较得到 VCC，再把 EXEC 切成 then-mask 和 else-mask， then 和 else 串行各跑一遍，最后把 EXEC 还原。

4.1 时间线：同一 PC，换 mask 跑两遍

时刻 T0 — 汇合处，所有人活着

EXEC = 1 1 1 1 1 1 1 1　　PC 指向比较指令

时刻 T1 — 向量比较：写出 VCC，PC 仍是整波一份

v_cmp_gt_i32 vcc, v0, 0     ; VCC[i] = (x[i] > 0)。写的是 mask，不是跳转

VCC = 1 1 1 0 0 1 1 0

比较本身受当时 EXEC 约束，但 ISA 规定写 VCC 的 VALU 在 EXEC==0 时也不会被 skip，保证 mask 语义完整。

时刻 T2 — 进入 then：保存旧 EXEC，新 EXEC = 旧 EXEC ∧ VCC

s_and_saveexec_b32 s0, vcc
; 原子地：s0 = EXEC;  EXEC = EXEC & VCC;  SCC = (EXEC != 0)
s_xor_b32 s0, s0, exec
; s0 变成 else-mask = 旧EXEC ⊕ then-mask = 旧EXEC ∧ ¬VCC
s_cbranch_execz ELSE        ; 若 then 全灭，整波跳过 then 体

s0 = 0 0 0 1 1 0 0 1　（else 的人，稍后用）
EXEC = 1 1 1 0 0 1 1 0　（只留下 then 的人）

此时执行 v_mul_i32 v1, v0, 2：lane 3/4/7 的 y 保持原值，假装「没走进 if」。

时刻 T3 — 切换到 else：用保存的 mask 把 then 关掉、把 else 打开

ELSE:
s_or_saveexec_b32 s0, s0
; s0' = 当前 EXEC（then 残留）; EXEC = EXEC | else-mask  → 暂时全开
s_xor_b32 exec, exec, s0
; EXEC = 全开 ⊕ then残留 = 只剩 else
s_cbranch_execz JOIN        ; else 全灭则跳过

EXEC = 0 0 0 1 1 0 0 1

执行 v_sub_i32 v1, 0, v0。then 的 lane 被关掉，不会把刚才的 2x 覆盖成 -x。

时刻 T4 — 汇合：OR 回保存的 mask，整波重新对齐

JOIN:
s_or_b32 exec, exec, s0     ; EXEC |= 进入分支前还活着的人

EXEC = 1 1 1 1 1 1 1 1　　PC 再次对所有人相同

结果 y = [6, 10, 2, 2, 4, 16, 4, 1]，与「每条线程自己走 if」完全一致——代价是 then 和 else 的向量指令都发过一遍。

EXEC=1，正在执行 then EXEC=1，正在执行 else EXEC=0，向量指令当 NOP

4.2 控制流图：不是两套 PC，是一条 PC 扫过两块代码

图 4. 软件 SIMT 的本质：CFG 上 then/else 是时间上先后的两段向量代码，靠 mask 保证各 lane 只提交自己那一段的写回。

这就是「SIMD + mask 模拟 SIMT」：SIMD 提供 32 路数据并行；mask 提供「这条线程不该写」； 编译器提供 mask 的压栈/切分/还原。没有任何一条 lane 拥有独立 PC。

5. 关键 ISA：SAVEEXEC、CMPX、CBRANCH

5.1 SAVEEXEC 家族：一拍完成「压栈 + 切 mask」

ISA §6 / §15.3 把这类 SOP1 写成统一语义（B32 用于 wave32）： 

saveexec = EXEC
EXEC     = S0  <op>  EXEC
D        = saveexec          ; 旧 mask 存进 SGPR
SCC      = (EXEC != 0)
指令新 EXEC典型用途
s_and_saveexec_b32 D, S0S0 & EXEC进入 if：只留下条件为真的 lane
s_or_saveexec_b32S0 | EXECelse 切换时先并上另一半
s_xor_saveexec_b32S0 ^ EXEC切到互补集合
s_and_not0_saveexec_b32~S0 & EXEC关掉 S0 里为 1 的 lane（离开 then）
s_and_not1_saveexec_b32S0 & ~EXEC从 S0 里取出当前没在跑的那些
s_*_wrexec_b32结果同时写入 D 和 EXECwaterfall：D 与 EXEC 必须相同

注意：WREXEC 与 SAVEEXEC 的差别是目的寄存器。SAVEEXEC 的 D 是旧 EXEC； WREXEC 的 D 是新 EXEC。ISA 写明 WREXEC「intended to help accelerate waterfalling」。

5.2 V_CMP 写 VCC，V_CMPX 直接写 EXEC

§3.4.7：V_CMP 产生 per-lane 1-bit 结果，可写到 VCC、任意 SGPR、或 EXEC，但不能同时写 EXEC 和 SGPR。 Wave32 只写低 32 位。VCCZ 是「当前波宽下 VCC 是否全 0」，给 s_cbranch_vccz 用。

V_CMPX_* 把比较结果直接打进 EXEC（EXEC[laneId] = pred），少一次 SAVEEXEC， 适合已经不需要旧 mask、或旧 mask 已另存的场景。ISA 警告：CMPX 之后的 EXEC==0 skip 是时序相关的。

5.3 分支改的是整波 PC

ISA §5.5：「Branching … affects the entire wave, not just individual work-items。」可用条件：

指令何时跳SIMT 角色
s_cbranch_execz / execnzEXEC 全 0 / 非全 0剪掉空的 then/else/loop 体
s_cbranch_vccz / vccnzVCC 全 0 / 非全 0比较后整波 early-exit
s_cbranch_scc0 / scc1标量条件wave-uniform 的 if（所有 lane 同一决策）
s_branch无条件汇合、循环回边

偏移按「下一条指令的 PC + SIMM16×4」计算，s_branch 0 等于 NOP，不会死循环。 这再次说明：lane 分歧绝不能靠 s_cbranch 实现，否则 32 条线程会一起跳走。

6. 嵌套、循环、waterfall

6.1 嵌套 if：SGPR 当 mask 栈

没有硬件 reconvergence stack。编译器把每一层的「进入前 EXEC」和「else-mask」放进 SGPR。 嵌套两层就占两个标量槽（wave32 下各 32-bit）。深度过大或 SGPR 不够时，才会溢到 scratch。

图 5. 嵌套分歧 = 把 EXEC 一次次 AND 窄化，用 SGPR 记住每一层被切掉的人，结束时从内向外 OR 回去。

6.2 循环：活着的人越来越少，直到 EXECZ

while (cond) { … } 编译成：循环头向量比较 → s_and_saveexec 关掉退出的 lane → 体 → s_cbranch_execnz 跳回。已经退出的 lane 仍跟着波转，只是一直 NOP，直到全员退出才真正离开。 这就是「一条线程死循环会拖死整 wave」的硬件原因：PC 只有一份。

6.3 Waterfall：把「每 lane 不同标量」串行化

有些操作必须 wave-uniform（例如用 SGPR 做 descriptor）。ISA 给出的标准瀑布循环（§15.3 注释）： 

; v0 = 每 lane 的 index
s_mov_b64 s2, exec          ; 最终要恢复的 EXEC
s_mov_b64 s4, exec          ; 尚未处理的 lane
loop:
  v_readfirstlane_b32 s0, v0   ; 取出当前还活着的最低编号 lane 的 index
  v_cmpx_eq s0, v0             ; EXEC ← 所有 index 相同的 lane
  <OP>                         ; 用这个统一的 s0 做标量/资源操作
  s_andn2_wrexec_b64 s4, s4    ; 从「剩余集合」里抠掉刚处理的人，写回 EXEC
  s_cbranch_scc1 loop          ; 还有剩余就继续
s_mov_b64 exec, s2

不同 index 的 lane 被分成若干批、批与批串行。这是 mask-SIMT 的极端形式： 当数据相关无法向量化时，用 EXEC 做软件调度器。WREXEC 把原来的 andn2 + mov exec 收成一条。

7. CDNA5 相对前代改了什么

文档开篇写明：「This document may make reference to "wave64" but this device supports only wave32。」 目录里也不再有 RDNA 那种「§2.1 Wave32 and Wave64」。和 CDNA1–4（GCN 系 4×SIMD16）对比：

CDNA1–4（GCN 系）CDNA5（本 ISA）
波宽Wave64 为主仅 Wave32，Wave64 废弃
SIMDCU 内 4×SIMD16，一条 Wave64 分 4 拍WGP 内 4×SIMD32，一条 Wave32 一拍
EXEC64-bit 全用仍是 64-bit 寄存器，硬件只看 [31:0]
VGPR典型每 lane 最多 256每 lane 最多 1024（文件仍约 128 kB / SIMD，波宽减半故可编址加倍）
双发射无 VOPD§7.8 Dual Issue VALU（VOPD / VOPD3）
矩阵MFMAWMMA；EXEC==0 时 WMMA 不跳过
新层次无 clusterWorkgroup Cluster：跨 WGP 的屏障与 multicast load

废弃 Wave64 的工程理由（与公开访谈一致）：Wave64 在 SIMD32 上要拆成高低两半， 分歧时浪费更大，寄存器压力也更高。CDNA5 把 SIMT 宽度钉死在 32，和 VALU 物理宽度对齐， mask 操作全部走 *_B32 即可。

机制本身没变：从 GCN 到 CDNA5，SIMT 始终是「共享 PC + EXEC + 编译器改 mask」。 变的是波宽与 SIMD 宽度对齐的方式，以及 SAVEEXEC/WREXEC 等标量辅助指令的完备程度。

8. 和 NVIDIA 比：差别与好处

数据通路两边其实是一类东西：都是 32 宽 SIMD + 活跃掩码。真正分叉的是 PC 归谁管、uniform 值放哪、控制流有没有单独的标量核。 AMD 把「线程独立」尽量下放到编译器和一张 EXEC 上，把省下来的面积做成 SALU / SGPR； NVIDIA 从 Volta 起把「线程独立」做进硬件（每线程 PC），换的是前向进度和分歧调用。

8.1 先看两边相同的部分

一条 warp / wave 发射时，硬件仍然只取一条指令，按 mask 决定哪些 lane 写回。 不活跃 lane 不会变成真正的多发射标量核。所以「SIMT」在两边都是编程模型，不是 32 套完整流水线。 分歧时 then/else 的向量工作仍然要分时占用同一套 SIMD。

8.2 真正的三点不同

AMD CDNA5NVIDIA（Volta 及以后）NVIDIA（Pascal 及以前）
PC 整 wave 一份。分歧只改 EXEC，then/else 必须整段串行跑完 每线程一份 PC + 调用栈。调度器按「当前停在同一 PC 的子集」发射 整 warp 一份 PC + 硬件 SIMT 栈（reconverge PC / 活跃 mask）
汇合谁负责 编译器：SAVEEXEC 把 mask 压进 SGPR，结束时 OR 回来 硬件按 PC 聚类；warp 内原语仍要 __syncwarp 编译器插汇合点，硬件弹栈
uniform 与控制流 独立 SALU + SGPR：一份值、一条标量指令、可与 VALU 同拍发射 没有对等的标量寄存器堆；uniform 通常在 32 份线程寄存器里各存一份 同左
分歧时的进度 先跑完 A 再跑 B。A 里若空等 B，会死锁 A、B 可交错发射，warp 内锁 / 生产-消费能向前走 与 AMD 类似：路径串行，同样有 intra-warp 死锁坑
分歧函数调用 wave 一份返回地址；分歧调用要 mask / waterfall 每线程栈，调用可以各走各的 锁步调用，分歧调用受限制

8.3 分歧时序：串行 vs 交错

同一段 if (cond) A(); else B();。假设 4 条 lane 走 A、4 条走 B，A 和 B 各 3 条向量指令。 SIMD 总功一样都是 6 次发射；差在中间能不能换路径。

图 6. 分歧并不会让 32 路变成 32 个独立标量核。NVIDIA 多出来的是调度自由度，不是额外的 ALU 宽度。

8.4 AMD 这套设计的好处

好处几乎都来自「故意不把线程做成硬件实体」，把预算给标量核和更简单的调度。

1. SALU + SGPR：uniform 只算一次、只存一份

循环下标、kernel 参数、描述符、wave 内相同的地址基址，都进 SGPR。 NVIDIA 同类值往往在 32 个线程寄存器里复制 32 份。 结果是：占用更少、功耗更低，而且 SALU 可以和 VALU 同一拍发射（控制流不堵数据通路）。

2. 标量访存（SMEM）一次打整波

常量、内核参数走 scalar data cache → SGPR，不是 32 条向量 load。 这是 GCN 系相对 CUDA 核「看起来寄存器少、却能撑很高占用」的重要原因。

3. 硬件更简单，调度确定

不必为 32 个 PC / 32 份调用栈做记分牌和选取逻辑。 EXEC 对编译器完全可见：s_cbranch_execz 剪空块、DPP / permute / ballot 在锁步下语义干净，不必到处插 __syncwarp。

4. 编译器能「标量化」控制流

证明整波条件相同后，走 SCC + s_cbranch，连 EXEC 都不切。 NVIDIA 也能优化 uniform 分支，但没有对等的标量条件码与标量 ALU 作为一等公民。

图 7. AMD 把「wave 内相同」从向量世界里抠出来：这是相对 NVIDIA 最硬的微架构好处，和 EXEC 模拟 SIMT 是配套的——既然 PC 已经共享，值也该共享。

8.5 好处的代价（也就是 NVIDIA ITS 赢的地方）

  • warp 内握手：if (lane==0) produce; else spin until ready; 在 AMD 上，else 要等 then 整段结束才开始。若 then 里的人反过来等 else，直接死锁。Volta 的独立调度就是为这个前向进度加的。
  • 分歧调用 / 间接跳转：每线程栈让 CUDA 的 divergent call 自然成立；AMD 要靠 mask 或 waterfall，编译器更累，间接调用开销更明显。
  • 不可约 CFG：硬件按 PC 聚类能「碰到谁算谁」；AMD 必须由编译器排出合法的 mask 栈，复杂控制流容易多切几次 EXEC。
  • mask 栈占 SGPR：嵌套分歧越深，标量寄存器越紧。NVIDIA 把汇合状态放进硬件，不跟用户 SGPR 抢。
对 CDNA 这类训练/推理负载，uniform 地址、统一控制流、矩阵核占主导，SALU/SGPR 的收益通常大于「分歧交错」。 图形和带锁的不规则计算更吃 NVIDIA 的每线程 PC。CDNA5 把波宽收到 32，是在 不改「一份 PC」这个前提下，把分歧浪费从 64 路降到 32 路，向 NVIDIA 的 warp 尺寸靠拢，而不是改成 ITS。

9. 对性能意味着什么

  • 分歧的代价是串行发两遍（或多遍）向量指令，不是「部分 lane 自己跑去别处」。then 和 else 一样长时，吞吐近似减半；再嵌套就按活跃子集继续串行。
  • 全波 uniform 的 if 应落成 scc + s_cbranch，不要走 VCC/EXEC，避免无谓的 mask 切分。
  • EXEC 全 0 要尽快剪掉：编译器插 s_cbranch_execz，硬件再对 VALU 做 opportunistic skip。漏掉就会对着空 mask 烧周期。
  • 一条 lane 不退出，整 wave 不能走。循环、锁、warp 内同步都必须按「共享 PC」来想。
  • 访存仍走 EXEC：不活跃 lane 不应发有效 global/LDS 事务；这也是为什么 VMEM skip 要看 outstanding 计数。
  • CDNA5 把波宽缩到 32，同样的 if/else 最多浪费 32 路而不是 64 路，对 AI 里常见的短分歧更友好；但 32 路仍是锁步，算法层面的 warp divergence 并没有消失。
