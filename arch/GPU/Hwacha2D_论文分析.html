中心假设：时域向量取指微架构，特别适合在已有可编程数据并行机上做多维特化。解耦让软件本来就不指望低延迟握手；运行时可重配让特化可以挂在 vsetcfg 上；时域执行让第二维可以沿时间展开，而不必改整条控制通路。

这篇论文有两半：前半是 Hwacha 在硅上怎么活下来（Hurricane-1/2、Eagle、EagleX，以及 Hammer 物理设计生成器）；后半才是二维扩展本身。读的时候不要把它当成又一篇「向量 vs GPU」——那部分 Lee 已经写过。这里的新东西是：把连续若干向量寄存器当成子矩阵，用 Latch（转置广播）和 Reuse（局部归约）少碰 SRAM。

2. 为什么一维向量做 GEMM 会丢上下文

高维运算都能拆成一维甚至标量，硬件因此总能算。代价是上下文丢了：机器不知道自己在处理矩阵的一行、张量的一片。能利用这些模式的地方——不物化中间结果、少发内存请求、寄存器文件少激活——全部消失。

图 1. 一维向量能算 GEMM，但把「同一列共享 A 的一个元素、C 沿 k 累加」拆没了。Tensor Core / VNNI / TPU 脉动阵列就是在买回这个上下文。Schmidt 想在 Hwacha 上用更轻的方式买回来。

DNN 其实还是这三类

卷积常被 im2col 成 GEMM；pooling 是局部归约；逐元素非线性挂在向量流水线上。网络形态一年变几次，固定功能 ASIC 容易过时。

二维加速器谱

Eyeriss / TPU：解耦、可编程性弱。CE：片上、C 内联。Tensor Core：GPU 里的固定尺寸矩阵 FU。VNNI：AVX 里把一串已有操作收成一条。

本文的落点

可编程性靠近 VNNI（以前能做的事，现在更省）；耦合比固定延迟 FU 更松，才能做 Latch/Reuse 这种跨拍优化。

3. 时域向量：二维叠在时间上，不改控制流

「时域」（temporal）相对空间向量：不是把二维一下子铺满阵列，而是同一套 1R1W 分 bank 数据通路，第二维用连续多拍（nano-op）走完。控制通路几乎不动，只在译码时给指令打上「这是子矩阵、depth 是多少」。

图 2. 空间二维把矩阵铺在 PE 上；时域二维把第二维叠在连续多拍上。Hwacha 的 4 bank SRAM 本来就是时域向量机，加 Latch/Reuse 等于承认「这一排 FMA 其实是一块子矩阵」。

为什么选向量取指做底座：① 解耦——控制核已经跑在前面，特化任务可以更长而不打乱标量软件；② 运行时可配——程序员本来就要 vsetcfg，特化特征可以挂在同一套配置上；③ 时域微架构——第二维沿时间走，不必改正常控制流。

4. 指令一：VTMM（向量-转置矩阵乘）

GEMM 内层那一步：Z = Aᵀ × B + C。不重排 VRF，只把连续若干向量寄存器当成一块子矩阵。

图 3. VTMM 的操作数。A 是「短向量」，B/C 是「depth 个长向量」。寄存器编号连续即可，普通 load 先把数据搬进来，编程模型几乎不变。

5. 指令二：子矩阵 / 短向量访存

三档，可以组合：

VLSM 子矩阵 load/store

连续 seglen（最多 8）个单位步长向量，行与行之间有字节 stride。行主序矩阵的一块直接进 vv0–vv7。基址和 stride 走地址寄存器，VMU 不必等 VXU。

Depth-only 短向量

有效向量长临时改成 depth，只搬 A 真正用到的那几个元素。典型 vl≥32，短 load 明显省带宽、少污染缓存。

VLDSM 两者合一

两维都由指令编码，独立于当前 vl。限制：硬件向量长至少 8（depth 上限）。

图 5. 子矩阵 load。基址 va0、行距 va1。微架构里每条向量访存要占 3 个 sequencer 槽，8 槽机器同时只能飞 2 条普通 load；子矩阵用状态机在 VMU 里重发 segment，让 VTMM 吃得动的数据量对得上发射窗口。

6. 微架构：Latch、Reuse、nano-op

不重排 VRF，实现策略是「当成重复的一维操作」。新控制量叫 nano-operation：子矩阵第二维走了几步。

图 6. Latch 把短向量变成对整行的广播（转置）；Reuse 把沿 depth 的累加留在数据通路上。两者都是通用的操作数修饰，卷积的短 kernel 也可以直接复用 Latch。

依赖怎么跟得上

  • 主 sequencer：额外比较器跟踪子矩阵用到的寄存器集合（不按单个 vv 细拆，按整条指令）。
  • lane sequencer：nano-op 计数、当前该碰哪一个 vv、Latch 锁存的结构冲突。
  • 实现是逐步放宽的：先「同时只能有一条二维指令且必须最老」→ 再「寄存器就绪即可」→ 最后「多条二维指令可重叠」。
  • VMU：短向量复用「不同 vf 块本就可能有不同 vl」的机制；子矩阵多一个状态机，按 segment 重发并做虚地址累加（不必乘法器）。
调度代价：一条子矩阵 load 可能对应上千次内存请求、占 sequencer 上万拍。依赖可以跟到「这一行已经回来」，但第一轮仍要用更小的 depth 让计算先进窗口；双缓冲比预想中更有用，因为超长占用的访存几乎能和计算完全重叠。

7. 四颗芯片与评测数字

前半论文是把时域向量机真正做进硅里。没有这部分，二维扩展只是 RTL 故事。

芯片工艺 / 规模要点测到的效率
Hurricane-1 28 nm FD-SOI Hwacha 谓词寄存器拥塞；片上 DC-DC + 自适应时钟 前作同系列的向量能效探索
Hurricane-2 28 nm，DDR4 PHY 把芯片拉得很瘦高 SERDES/DDR 基本没能当主存用；测 DVFS。L2 计数器 AVS 比看功耗最多再省 14% 最优点 780 mV / 115 MHz：22.3 DP / 36.5 HP GFLOPS/W
Eagle TSMC 16 nm，8 核，24 mm²，每核 1 lane Hammer 首次流片；簇共享 L2 + 大 L3。L2 半频，Hwacha 带宽只到理论 50% 0.55 V / 339 MHz：DGEMM 56.5、SGEMM 92.3、HGEMM 209.5 GFLOPS/W（约峰值 34%）
EagleX 16 nm，22 核 / 20 应用核，56 mm² 同片再放 Gemmini 16×16 Int8 脉动阵列，方便和固定功能比。20 核跑起 SMP Linux 频率范围与 Eagle 相近；详细扫频当时未完成

图 7. 评测在 Intel 22 nm（16 nm 趋势相同）。门数大约 +10%。短向量赢在利用率，长向量赢在 SRAM。窄 B 矩阵（32×16、8×16 列）时，子矩阵扩展的相对收益随 vl 变短而变大。

Eagle 若把 L2 端口加宽、去掉半频限制，长向量能效大约还能翻倍。当时发表时，它是带可编程精度的 RISC-V 数据并行扩展里报告过的最高能效。

8. 放在 Tensor Core / TPU / VNNI 谱上

图 8. 和当代二维加速器对齐。VNNI 把已有 AVX 操作收成一条；VTMM 把已有 FMA 收成一条，并多了 Latch/Reuse 这种固定延迟 FU 做不到的跨拍省 SRAM。

未做完、但路径清楚的后续

  • 一维卷积：短 kernel 当 Latch 操作数，几乎只加译码表。
  • Pooling：沿 depth 可复用 VTMM 局部归约；沿 vl 且落在同一 slice 内则要新数据通路，不一定值得。
  • 更窄精度：若最高只支持 32 位，depth 可放到 16，SRAM 节省再翻一倍。
  • 多领域扩展能否叠在同一底座上而不互相拖后腿；同一套 Latch/Reuse 能否接到别的 DLP 底座（不只 Hwacha）。
读完两篇可以串成一条 Berkeley 向量线：Lee 证明「编译器标量化 + 解耦向量取指」能达到 GPU 级可编程、更省硬件；Schmidt 证明「同一套时域微架构承认二维」能在不另做脉动阵列的情况下，让 GEMM 少搬寄存器、短向量打得更满。EagleX 把 Gemmini 放在旁边，等于在同一块硅上摆了两种答案。
