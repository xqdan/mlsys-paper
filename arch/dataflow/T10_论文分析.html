1. 一句话结论与研究定位

Graphcore IPU 这类芯片已经把核间全互连做成事实：每核可直读别核 scratchpad，全芯片聚合带宽远高于 HBM。现有 DL 编译器却仍用「虚拟全局内存」把这套硬件伪装成 GPU，于是核间通信乱、片上容量被复制吃掉。T10 的主张是：不要再假装有一块全局内存——用 rTensor 把张量切块、绕环旋转，把算子编成可预测的 compute-shift 计划，再在容量与通信之间做全局权衡。

这不是又一篇 TVM/Ansor 式的共享内存 tiling 论文。它针对的是一类正在扩散的架构——IPU、SambaNova SN10、Cerebras WSE、Tenstorrent Grayskull，以及 GPU 上开始出现的 SM 簇互连（Hopper thread block clusters）。编译对象从「如何从全局内存取数」变成「如何在核间按环搬运 tile」。硬件 abstraction 只有三条：allocate、compute、shift。

2. 硬件背景：核间互连 vs 全局共享内存

为了跟上深度学习的算力需求，AI 芯片塞进大量并行核，每核带一小块 SRAM scratchpad。传统路径（TPU、GPU）靠一块全局共享内存（cache + HBM）做核间同步：编译器只负责把计算切到各核，数据一律从全局内存进出。问题是全局带宽增长赶不上算力。核间直连让核可以直接复用彼此本地内存里的数据，把片上复用从「经 HBM 绕一圈」变成「邻居直接给」。

图 1. 论文 Figure 1 的结构对照。TPU / GPU 是全局共享内存；IPU 把每核 SRAM 经片上互连聚成一块分布式片上内存。

IPU MK2 的关键数字：1472 核，每核独立线程 + 私有 624 KB scratchpad，合计 896 MB 片上内存；每核访问另一核本地内存 5.5 GB/s，all-to-all 约 8 TB/s，远高于 A100 的 1.94 TB/s HBM。核可以单独访问别核数据，不必争抢一块全局总线。片上互连因此把「很多小 SRAM」聚成「一块大、而且带宽很高的分布式内存」。

IPU 几乎没有可用的片外带宽，模型必须尽量塞进片上；这也是为什么「容量浪费」会立刻变成「模型装不下 / batch 上不去」。同类架构还包括 SambaNova SN10、Cerebras WSE、Tenstorrent Grayskull。论文的论点是：硬件已经投了大钱，缺的是能吃到核间带宽的编译器。

3. VGM 为何既费带宽又费容量

现有编译器（Roller、改过的 Ansor）和厂商库（PopART）的做法是：在每核本地内存里划出一块，拼成「虚拟全局内存」（VGM）。权重、激活都放进 VGM。当前算子被切成子算子，每核从 VGM 把需要的数据拉到本地「子算子区」，算完再写回 VGM。这就是 GPU 上那套 load-compute-store。

图 2. 论文 Figure 2 的结构重绘。VGM 让同一份数据占两块 SRAM，核间访问还不均衡；compute-shift 把活跃区还给子算子，通信变成环形邻居交换。

通信上的两个病

访问不均衡 + 单核带宽争抢

一份张量分区只存在某一个核上，却常被多个核用。有的核能本地命中，有的核必须远程取。执行被远程核拖住。若多个核同时打同一个核，就会挤在那 5.5 GB/s 的单核链路上。

取一份完整张量要跟很多核对

VGM 把张量切碎散落到各核。一个核要凑齐一块数据，必须向许多核各取一小片，产生冗余的多对多通信，而不是一次有规律的邻居交换。

用 Roller 这种 VGM 编译器拆时间：核间访存占端到端 50%–74%（论文 Figure 13）。

容量上的病：活跃算子被复制一份

子算子从 VGM 把数据再拷到本地，同一份数据同时占 VGM 区和子算子区。VGM 还要给空闲算子（已驻片上但没在跑）留位置。结果是每核能留给当前子算子的空间变小，计算强度下降，同样计算需要更多次搬运。去掉 VGM、把活跃区并进子算子区，子算子尺寸可增大 22%–180%（Figure 2b：BERT-BS8 MatMul 29.2%，ViT-BS128 22.0%，ResNet-BS128 Conv 60.4%，NeRF 138.5%，OPT-13B 一层 179.8%）。

行业在 IPU / WSE / SN10 上砸了数亿美元，却因为编译器仍按 GPU 共享内存去编，核间互连芯片打不过传统全局内存加速器。T10 的问题陈述就是这句话。

4. 核心思想：compute-shift 范式

去掉 VGM 的办法，是把 DNN 计算映射成 compute-shift：每一步，每个核用刚从上游邻居收到的数据独立算一个子任务，再把数据 shift 给下游。可行性来自一个观察——绝大多数 DNN 算子可以切成规则任务，各自加载/产出输入输出张量上连续的 tile。

图 3. 论文 Figure 3 的 MatMul 例子。两种计划都合法，差别只在容量–通信权衡。T10 的工作就是在这个空间里系统搜索，而不是手写一种切法。

系统流水线（Figure 4）是：DNN + 硬件规格 → 用 rTensor 枚举 compute-shift 计划 → 算子内 Pareto 前沿（时间 vs 内存）→ 算子间全局调和 → 三条设备接口落到 IPU 内核。

图 4. 论文 Figure 4 的编译流水线。先把组合爆炸收成每个算子一条 Pareto 曲线，再在整网上调和 idle/active 内存，最后落到三条设备原语。

5. rTensor：分布式张量抽象

RotatingTensor（rTensor）在普通 shape / dtype 之外，再描述这块张量如何被切开、贴到哪些核、以什么步长在核间旋转。一组 rTensor 配置就是一份 compute-shift 执行计划。

符号 名称 含义
fsX 空间划分因子 把张量 X 切成子张量，对应「哪些核组各自持有一块」
ftX 时间划分因子 把子张量再切成分区，在共享它的核之间轮转
rp 旋转步长 每步沿各维移多少元素，用来对齐计算与数据相遇的时机
Fop 算子划分因子 沿张量表达式的全部轴，把整个算子切成子算子

一个切法例子（Figure 6）

形状 [6, 8] 的张量，落到 8 个核上：fs = [2, 1] 沿 m 切成 2 个子张量，每个形状 [3, 8]，各由 4 个核共享。再设 ft = [1, 2]，每个子张量沿 k 切成 2 个 [3, 4] 分区，形成 2 个 2 核旋转环。把 ft 改成 [1, 4] 则变成 1 个 4 核环。同一套划分上，rp = [0, 2] 每步移 2 个元素、4 步一圈；rp = [0, 1] 则 8 步一圈。环越长、步越小，容量越省、通信越多。

图 5. 论文 Figure 6：空间因子决定谁持有子张量，时间因子决定环有几条、每条几核，旋转步长决定每步搬多大 tile。

从张量表达式推 rTensor

C[m, n] += A[m, k] · B[k, n]

Fop 是沿 [m, k, n] 的整数向量，乘积等于子算子数（也就是用掉的核数）。例如 Fop = [2, 1, 3] 得到 6 个子 MatMul，每个形状 [M/2, K] × [K, N/3]。空间因子由数据依赖直接推出：fsA = [2, 1]，fsB = [1, 3]，fsC = [2, 3]。

若某张量缺了 Fop 里的某根轴，这块子张量就要被沿该轴的多个子算子共享。共享核数 P = |cores| / ∏ fs。时间因子决定把子张量切成几份、形成几个环：∏ ft 必须整除 P，环数 = P / ∏ ft。多个环意味着复制多份，占内存，但每核每步能算更大的子任务、旋转步数更少——这就是算子内的容量–通信杠杆。

旋转必须对齐，否则数据依赖会断

Figure 7 里 A、B 都沿 k 做时间划分，但 ft 不同。若两者沿 k 的 rp 不一致，某核上会出现「该乘的 A 块和 B 块不同时在场」。T10 强制两条约束：

  1. 沿同一轴旋转的 rTensor 必须共享该轴上的 rp。
  2. 每个 rTensor 的 rp 不能超过其在该维上的子张量分区长度，保证每步子任务能在本地算完。

为拉高计算强度，T10 把 rp 取成各相关分区长度的最小值。每步子任务由 Fop 和各轴 rp 共同决定；子算子用嵌套循环扫完所有子任务，循环到哪根轴，就沿那根轴旋转对应 rTensor。

图 6. 旋转对齐。T10 用两条硬约束保证每步子任务能在本地算完，否则 compute-shift 会算出错结果。

rTensor 相对 SPMD 切分（GSPMD / Alpa / Megatron）的差别：后者通常是「切完再插一次 AllReduce」，计算与通信分两段优化，并且常靠复制来保证每份任务输入完整。T10 把一次算子编成多步交错的 compute 与 shift，复制与否、环有多长，都进同一个代价模型。

6. 算子内 / 算子间两级权衡

单算子的 fs / ft / rp 组合已经是组合爆炸；整网再乘上算子数。T10 拆成两级，避免直接搜笛卡尔积。

算子内：时间因子换通信

更小的 ft → 环更短、复制更多 → 通信 hop 少、内存贵。对每个算子搜出时间–内存的 Pareto 前沿：同样内存下更快，或同样时间下更省内存。

算子间：把内存补给「最划算」的算子

不同算子的内存–延迟斜率不同。同一算子还可以在空闲时用省内存计划、执行前再切到快跑计划（setup 阶段用核间传输改布局）。

6.1 代价模型为什么能准

核间互连 + 软件显式管理传输，让访存不再是「下层 cache 会不会 stall」那种不可预测事件。给定划分，每核计算量、每步通信量、内存占用都可以静态算出来；每步计算只吃本地 SRAM。做法：

  • 对每种算子，随机生成不同形状的子任务，在单颗 IPU 核上实测，用子任务形状拟合线性回归得到计算时间；
  • 通信时间用传输量再拟一条线性回归；
  • 用户自定义 kernel 可自己提供代价函数。

Figure 8：多数算子近乎完美拟合。例外是 convolution——走厂商闭源 kernel，有黑盒优化，仍足以选出好计划。作者设想厂商若把 T10 收进工具链，应能给出精确模型。

搜索剪枝：并行度与 padding

完整空间会到 1019（ResNet 里 7 维卷积）。两条可配置规则先滤掉明显差的计划：

  • 并行度约束：算子占用核数下限（例如 ≥90%），丢掉欠并行的 Fop。
  • padding 约束：为对齐 AMP 等矩阵单元而填充时，原始尺寸 / 填充后尺寸低于阈值（如 0.9，即最多约 11% 浪费）的计划丢弃。

过滤后通常 <104 个计划；每个计划在单 CPU 核上评估 <100 ms，32 核约 30 秒扫完。Pareto 点多数算子不到 50 个，相同算子可缓存复用。约束收得越紧，编译越快；多数模型一分钟量级的严格约束已经接近最优延迟（Figure 19）。

6.2 算子间内存调和（Algorithm 1）

策略仍是「尽量把多个算子留在片上，只让模型 I/O 走片外」，这样相邻算子的中间张量可以全速在片上复用。每个算子持有两份计划：

  • idle：执行前尽量省内存；
  • active：执行时尽量低延迟；
  • 从 idle 切到 active 要付 setup 时间（核间搬数据改划分）。

贪心过程：先给所有算子最省内存的 idle 计划，剩余空间当 active 内存。每步挑 −ΔTsetup / ΔMidle 最大的算子，给它更大的 idle（setup 更短），active 池相应缩小，再为每个算子选「能塞进当前 active 内存的最快计划」，估端到端时间。搜索复杂度从各算子 idle 计划数的乘积降到求和。最后取整条轨迹上端到端时间最短的那一步。

图 7. 左：每个算子只保留 Pareto 点（论文 Figure 17）。右：同一算子两份计划，setup 用核间传输把紧凑布局展开成低延迟布局（Figure 9 / Algorithm 1）。

Figure 20 的直觉：Roller 往往停在「idle 最小、setup 最痛」的最左方案。T10 会把 idle 扩到大约 58% 片上容量（ResNet-BS64 例子），因为许多算子 active 时最多只要 40%。把 setup 提前做在关键算子上，比把全部内存留给当前算子更划算。

7. 映射到硬件：allocate / compute / shift

目标架构被收成统一抽象：多核、每核私有本地内存、高速片上网络。三条接口：

  1. allocate：编译期给张量分区分配地址，并做 liveness，让前后算子复用同一块 SRAM。
  2. compute：按划分配置和张量表达式，用预定义模板生成单核计算（IPU 上叫 Vertex）。
  3. shift：运行时把子张量发到指定邻居核。

初始放置（Figure 10）

不仅要让「现在」每核上的 A、B、C 块满足依赖，还要保证沿各轴按升序排好，这样每转一步依赖仍然成立。3×3 MatMul 的放置顺序：先按划分放下全部 C；再沿时间维放下第一组 A，由当前 A 与 C 反推第一行核上的 B 对角块；再沿列依次放下其余 B；最后反推其余 A。这是在「旋转环」上解一个初始相位，而不是随意 scatter。

图 8. 先放下全部 C，再由数据依赖反推 A/B 的初始相位，并沿各轴升序排列，保证每转一步依赖仍成立。

循环次序

每核上是交错的 compute / shift 嵌套循环，一层对应一个时间划分维。内层选较小张量所在的维，因为内层执行次数多，这样总通信体积更小。

8. 实现细节：代码生成与伪 shift

独立编译器，输入 ONNX，解析成算子图（每算子一张量表达式），做算子内/间优化，吐 IPU 可执行代码。优化 pass 约 4K Python；代码生成约 4.5K Python + 1.5K C++ / IPU 汇编。总共约 10K 行。 

Vertex conv(out=C, in=A, kernel=B);
for (i = 0; i < num_core; i++) {
  C[i].mapToCore(i);
  A[i].mapToCore(i);
  B[i].mapToCore(i);
  compSet.addVertex(conv, core=i);
}
program.addStep(run(compSet));
program.addStep(shift(A, "left"));
program.addStep(shift(B, "right"));
program.addStep(run(compSet));

同一步里所有 Vertex 同构，组成 ComputeSet。shift 之后用新的本地数据再跑同一套 ComputeSet。算子结束后若下一算子布局不同，插入一次 all-to-all 改布局；中间张量通常远小于执行中的 shift 体积，开销相对小。

IPU 没有原生 shift：用缓冲做伪旋转

源（要转出的数据）和目的（要转入的数据）在内存上重叠。每核留一块临时缓冲（默认 8 KB）做中转：缓冲越大越占 SRAM，越小就要多轮 shift。8 KB 的同步开销可忽略，大小可配。

图 9. 伪 shift：先拷进每核 8 KB 临时区，再发给邻居，避免源与目的在同一块 SRAM 上互相覆盖。

复合轴

二维卷积 O[b,f,h,w] += I[b,c,h+kh, w+kw] * C[f,c,kh,kw] 里，h+kh 这类复合轴被拆成基本轴分别划分。Sort 等无法写成张量表达式的算子走厂商库。

9. 评测：延迟、规模、GPU 对照与 LLM

平台：真实 Graphcore IPU MK2。基线：PopART、改到 IPU 的 Ansor、基于 VGM 的 Roller。模型：BERT 340M、ViT 86M、ResNet 11M、NeRF 24K，以及 OPT / Llama2 / RetNet 的部分层。batch 从 1 倍增直到片上装不下。只测推理——手上这颗 IPU 片上容量有限，也主要用于推理。T10 只做无损变换，与 Roller / PopART 在同一套预训练参数下精度差可忽略。

算子内搜索空间（Figure 17–18）

T10 的 Pareto 集里几乎总能找到又比 PopART 快、又更省内存的点。Roller 总想用满每核本地内存找最快计划，但 VGM 占了一截，上限更低，也不能在算子之间做全局交换。过滤把 1019 量级空间收到 104，代价模型再收到几十个 Pareto 点。

核数扩展（Figure 21）

用 V-IPU 把板上 2/4 颗 IPU 暴露成 2944 / 5888 核的「单芯片」，片间 160 GB/s；也用编译器限制核数模拟更小芯片。T10 在各核数上都快于 Roller，核间传输随核数扩展得更好。不少小 batch 场景，T10 用一半核就能达到 Roller 全核的 2×。多芯片时有效核间带宽因 IPU-Link 下降 26–33%，Roller 的时间甚至可能变差（ResNet BS-1），T10 的传输开销不随片间变差而恶化。

对照 A100 + TensorRT（Figure 22–23）

两颗芯片都是 7nm、峰值 FLOPS 接近。小 batch 时 IPU+T10 可快至 2.44×：吃的是 896 MB 片上内存，A100 被 HBM 卡住。batch 变大后变成算力屋顶，IPU 250 TFLOPS 低于 A100 312，且片上更满、通信权衡空间变小，IPU 会落后。作者的判断是：核间互连芯片更适合延迟敏感、小 batch 的推理，前提是编译器真的用上片上内存。

LLM：整模装不进单颗 IPU，所以跑子集层（OPT 1.3B–13B、Llama2 7B/13B、RetNet 1.3B）。层间中间数据很小（Llama2-13B 每 token 约 131 KB），流水线多芯片时片间开销可忽略，单芯片数字可以外推。小 batch 上 IPU+T10 相对 A100 最高 16.38×（平均 3.10×）：A100 的 40 MB 全局 cache 塞不下一个大算子，参数要从 HBM 反复加载。大 batch 再次变成算力比较。

如果给 IPU 加上 HBM（Figure 24，仿真）

真实 IPU 片外只有 8 GB/s，单芯片服务 LLM 会卡在载入参数。作者按 roofline 插入延迟来仿真不同 HBM 带宽，并做 double buffering（执行 596 MB / 预取 298 MB）。两种策略：Single Op（算一个、预取下一个）与 Inter Op（一组算子一起预取，组内用 T10 的算子间调度）。HBM 很窄时大家都被载入卡住，T10 与 Roller 接近；带宽升高后 T10 的算子内计划开始领先。Inter Op 在低带宽时更好，因为不同计算强度的算子可以互相填预取空隙；带宽足够高之后组内抢片上容量，Inter Op 会略慢于 Single Op。

10. 相关工作、边界与可带走的判断

作者自己划的位置

DL 编译器

IR 仍是算子图 + 张量表达式（TVM / Halide / Tensor Comprehensions 一路）。计算模型从 load-compute-store 换成 compute-shift。tiling、polyhedral、稀疏等共享内存技术可以正交叠加（融合、packing、iteration batching）。

分布式切分

JAX / PartIR / GSPMD / Megatron / Alpa / FlexFlow / Tofu 是节点级 SPMD：切完再通信，复制换本地完整性。T10 是芯片内、步级交错，通信模式是旋转环而不是一次性集合通信。

Dataflow

DISTAL / Tenet 要用户写 dataflow 计划；SambaNova 混模型并行与流水线，延迟和复制都会上去。T10 面向上千全互连张量核，自动编端到端 DNN，比固定脉动阵列更通用。

未来工作里已经点名的延伸

  • 多芯片：同一套容量–通信权衡可以拿到片间，让集群用更少芯片跑更大模型。
  • 新 GPU：Hopper 把 SM 连成 thread block cluster，减少片外访问。T10 的 shift 调度可以迁过去，只是互连不再是全连接、带宽也不对称。
  • 核间芯片 + HBM：SambaNova 已有带 HBM 的产品；IPU 也可以把 HBM 控制器挂到片上互连，用与 shift 相同的投递语义给核送数。

论文没完全收口的边界

  • 几乎只谈推理。训练的反向、优化器状态、更大的激活存活区间，会让 idle/active 双计划的内存账本难得多，文中没有实验。
  • LLM 是「若干层」不是整模。整模数字靠流水线外推；真实多芯片负载均衡、pipeline bubble、片间与片内调度如何分层，仍是开放问题。
  • HBM 实验是仿真。延迟按 roofline 插入，没有真实控制器、排队、地址映射。
  • 卷积代价模型不准，依赖厂商闭源 kernel。可移植性绑在「单核 compute 模板 + 可拟合的通信」上；换一台互连拓扑不是全连接的芯片，旋转环可能对不上物理链路，需要另做路由或改抽象。
  • Sort 等非张量表达式算子绕开。动态 shape、稀疏、MoE 专家路由这类不规则通信，compute-shift 的「可对齐旋转」假设会裂。
  • 编译时间数小时对生产部署偏重；虽然约束可换速度，但文中「近优」是延迟意义上的，不是每次都要重编的 CI 友好。
可带走的判断。核间互连加速器输给 GPU，常常不是算力不够，而是软件还在用全局内存的心智模型。T10 把「分布式片上内存」收成三个可搜索的整数向量（空间切、时间切、步长），再加一条很薄的贪心内存调和。这套抽象对 IPU 这类全连接 scratchpad 集群特别贴；对 GPU SM 簇、对带 HBM 的 dataflow 芯片，值得问的下一问不是「要不要 tiling」，而是「旋转环的物理代价函数怎么写」。若你在做片上 SRAM 池化或核间 DMA 调度，rTensor 的 idle/active 双计划比「把 SRAM 当软件管理的 cache」更接近这篇论文真正想卖的东西。
