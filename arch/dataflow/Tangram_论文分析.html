1. 一句话结论与研究定位

网络变大、层数变多之后，加速器不能靠把单个 PE 阵列无限做大。Tangram 的主张是：同样的 tiled 硬件，粗粒度数据流决定缩放效率——层内并行用缓冲共享（BSD）消掉瓦片间复制；层间流水用交替循环次序（ALLO）把中间 fmap 按子集立刻转给下一层；再配上面向 fork/join DAG 的二维分区。相对已经优化过的 tiled 基线，平均 2.0× 性能、能耗 −45%。

这篇工作不发明新的 PE 微架构。每个瓦片仍是 Eyeriss 式 8×8 PE + 32 kB SRAM；细粒度映射沿用 row-stationary 和 Yang 等的循环分块。贡献几乎全在瓦片之间怎么搬数据、怎么切层、怎么搜映射。作者把这套软件优化的能效提升，类比为提前两代工艺节点。

2. 两层并行：引擎内细粒度 vs 瓦片间粗粒度

CONV / FC 可写成对 batch Nb、输入通道 Ni、输出通道 No 的三重循环：每个 ofmap 是全部 ifmap 与对应滤波器卷积再累加。数据远大于片上 SRAM，所以效率取决于循环分块、重排、以及 PE 阵列上的空间映射。Eyeriss 把这一层叫 dataflow；Tangram 把它拆成两层。

O[b][o] = Σi=0Ni−1 I[b][i] ∗ W[o][i] + B[o]     0 ≤ o < No,  0 ≤ b < Nb

细粒度：一个引擎内部

2D 卷积映射到 PE 阵列（row-stationary），寄存器捕获局部性；SRAM 用循环分块吃复用。类比 SIMD / ILP。单引擎做大之后，组播延迟、总线能耗、缓冲到远端 PE 的距离都会变差；小层也喂不满大阵列。

粗粒度：多个引擎之间

瓦片经 NoC 互连并接到片外通道。层内并行：同一层切到多个引擎；层间流水：不同层占不同区域，中间 fmap 片上转发。类比多核。Tangram 只优化这一层。

单片大阵列（论文里 128×128 PE + 8 MB 全局缓冲）在组播总线上可烧掉最多约 20% 能耗，也撑不起层间流水所需的灵活转发。Tiled 是缩放的自然形态：DaDianNao、Neurocube、TETRIS、ScaleDeep 都走这条路。问题是，已有粗粒度方案在复制和流水填充上浪费了本该用来缩放的 SRAM 与利用率。

3. 基线 tiled 加速器卡在哪

基线硬件：16×16 个 Eyeriss 式引擎，合计 16384 PE、8 MB SRAM。细粒度用 row-stationary；缓冲管理用 Yang 等的循环变换。中间 fmap 若能整段落在片上，切换层时不回写 DRAM。层内并行沿用 TETRIS 的混合 output + fmap 切分；共享输入一次从内存取出再广播，输出在引擎间累加后再写回（ScaleDeep 式）。层间流水把网络切成段，按运算量比例给各层分配引擎；只有段首输入和段尾输出走片外。权重若整网能钉在 SRAM 里，支持 model pinning。

图 2. 三种系统用同一套资源（16384 PE、8 MB SRAM）。差异只在组织方式和粗粒度数据流。B 与 T 硬件同构；T 换 BSD + ALLO + DAG 启发式。

基线把每个引擎缓冲当私有缓存，共享数据各留一份。64 kB 数据在 16×16 瓦片上复制就是 16 MB 的有效容量浪费。复制一多，层间 fmap 更塞不进片上，被迫回 DRAM；芯片若靠加大 SRAM 来补，面积先炸。

3.2 层间：整张 fmap 双缓冲 + 填/排空

先前流水工作多假设整网能一次铺上芯片。大网络只能分段。段内相邻层要对整张中间 fmap 做双缓冲以同时读写，容量是几十到几百 MB 量级（见表 2），再叠加层内复制就更糟。段切换时后层要等前层产出，填/排空让利用率掉下去。更早的方案还只覆盖线性链，Inception / ResNet / LSTM 这种 fork–join DAG 不在射程内。

4. BSD：层内并行时共享缓冲、不复制

Buffer Sharing Dataflow 的目标：把分散的私有 SRAM 逻辑上合成一块理想共享缓冲——容量按总和计、正在算的数据永远在本引擎本地、远程只跟邻居换数据。做法是两步：计算错位（skew）+ 数据旋转（rotation）。

以 output 并行为例。基线：所有引擎同一时刻拿同一批 ifmap，各算不同 ofmap，ifmap 复制 po 份。BSD：引擎 x 先从邻近内存通道取不同的 ifmap 子集（累加可交换，错位不影响正确性）；算完后把 ifmap 在引擎间旋转一轮，直到每个引擎都见过全部共享数据。

图 4. BSD 把“每引擎一份副本”换成“全集分片 + 旋转”。混合并行时 ifmap 与权重可同时共享，旋转走两个轴。

4.1 循环变换模型

无 BSD 时，引擎缓冲能装 Ni/ti 个 ifmap、No/to 个 ofmap、batch 的 1/tb。BSD 在 output 并行下让 po 个引擎各持不同 ifmap，ifmap 分块因子除以 po，并插入由引擎下标 x 错位的旋转环 i″0。因为旋转环在 ofmap 环内侧，这批 ifmap 会在片上转 r = to 轮，被全部 ofmap 复用。

i0 = ⌊T / (r p)⌋ · p + (x + T mod p) mod p     0 ≤ T < ⌈t / p⌉ · r · p

N 份共享数据、p 个引擎、每引擎存 1/t，外层决定旋转轮数 r。混合并行时各类共享数据的下标独立算。编译器据此静态生成访存顺序，运行时不必动态调度。

4.2 收益从哪来

  • 少取 ofmap。 无 BSD 时 ofmap 被取 ti 次，每次只碰到 Ni/ti 个 ifmap；有 BSD 后每次碰到的 ifmap 多 po 倍，片外取次数降为 ti/po。
  • 换层复用。 中间 fmap 只要能塞进全部引擎 SRAM 的总和，就不用为“每引擎一份私有副本”而回写。
  • 等价理想大缓冲。 正在算的数据始终本地；旋转走邻居，NoC hop 最少。作者明确类比最优 NUCA，只是用网络结构做静态迁移，而不是硬件缓存协议。

5. ALLO：层间流水时细粒度转发 fmap

层间流水能提高小层在大芯片上的利用率，并让中间 fmap 走 NoC 而不是 DRAM。代价是缓冲整张 fmap，以及长填/排空。简单补丁是把 batch 再切成 tb 份：下一层不必等完整 batch。缓冲和填排空都缩到 1/tb，但 tb 受推理 batch 限制，权重还要取 tb 次，实际只能取 4–8，省得有限。

Alternate Layer Loop Ordering 再往下切一档：不等一个样本的全部 fmap，只等一个 fmap 子集。若 L-1 按 ofmap 顺序产出，L-2 按同样顺序消费 ifmap，L-2 在第一个 fmap 就绪后就能开工；片上只需保留正在交接的那一份，而不是整张图。

图 5. ALLO 要求相邻层对共享 fmap 使用相同的顺序访问模式（红字对齐的外层通道环），分块因子一致。L-2 的 ofmap 仍会被多次更新，必须整缓冲——所以 ALLO 只能隔层使用。

5.1 只能隔层用，但省得比切 batch 多

CONV/FC 不能让 ifmap 和 ofmap 同时顺序访问。一段里有 ℓ 层、ℓ−1 份中间数据时，仍有 ⌊(ℓ−1)/2⌋ 份必须完整延迟并缓冲。两层一段是特例：中间数据可以完全不整缓冲。通道数通常远大于推理 batch（Ni, No ≫ Nb），所以 ALLO 的 ti/to 比单纯 tb 切得更细，填排空和容量都按 t 再缩一档。

ALLO 管层间次序与片外顶层循环；BSD 在顶层之下再加旋转环。二者正交。ALLO 用不上的那一半层，中间 fmap 必须整放——这时 BSD 消复制，整网容量才压得下来。

6. 复杂 DAG：二维分区与启发式映射

ResNet、Inception、LSTM 不是单链。先前 1D 分配（每层占阵列若干列、数据水平流过）对非相邻转发和粗细不均的层都不合适。Tangram 改成 2D 之字形分区：当前行剩不下就折到下一行。分区更细，层的运算量更容易对齐成相近的流水级延迟；非相邻区域（如 R0→R3）的 NoC 距离也更短。

图 6. 二维之字形分区。fork 共享输入的层放进同一段只取一次；映射规则禁止一个区域同时被两条邻居依赖拖住。

6.1 选段

按 DAG 拓扑序往当前段里加层，但必须与段内已有层共享依赖。依赖可以是：吃段内某层的输出（普通流水），或与另一层共享从片外取的同一份输入（fork 特有）。GoogLeNet inception 里 R0/R1/R3/R5 四路共享输入，放进同一段就只取一次。

一层的输出要么被本段消费者独占，要么直接写回内存。只打包一半消费者没有意义——中间结果还是要回 DRAM，不如把消费者收进下一段。LSTM 放宽到最多一个消费者可以在另一段（图中 R2），训练时反向层依赖对应正向 fmap，这条放宽让正向仍能流水。

6.2 映到区域

  • ACT / POOL / 逐元素算子并进前一层 CONV/FC 的区域：无权重、算量小。
  • 线性依赖链可共享同一区域，缓冲里顺序放下各层输出，只暴露给唯一后继。LSTM 的 R2 把三个逐元素算子并进 F-gate 的 FC。
  • 同一区域顺序执行的层，只允许一条来自邻居区域的依赖，作为该区域的时间锚。多条邻居依赖会打架，造成停顿。区域之间可以是链或树，不能是多入边冲突。

6.3 训练

反向 CONV/FC 可改写成不同维度的正向层，BSD 直接套。训练 DAG 更长，用 6.1–6.2 的启发式即可。ALLO 对正向段和反向段都适用。

7. 实现：少量硬件 + 搜索 + 编译

数据流全部静态调度。每个引擎只执行编译器生成的缓冲访问与计算指令，没有动态调度器。

硬件增量很小

缓冲控制器要能向片外和其他引擎的 SRAM 发访问；按式 (2) 错位与旋转；用 ScaleDeep 的 MEMTRACK 跟踪“写够才能读、读够才能覆盖”。按缓冲行传输并预留空行，避免死锁。切分大致均匀则无负载失衡。ALLO 的细粒度转发复用已有层间通路，同步粒度改细即可。DAG 允许一对多转发。

搜索空间要剪

层内混合并行、段深浅、每层引擎数、片外分块、片上 dataflow、DAG 选段与区域映射，组合爆炸。更深的段少回 DRAM，但每层资源变少、单层 dataflow 变差，填排空也更长。工具：层内穷举；跨层按拓扑序动态规划 + beam search。代价模型沿 Eyeriss / TETRIS / Yang blocking。

编译器把 ALLO、BSD、单引擎分块三套循环变换嵌成完整嵌套循环，按这次序发访存指令，并在指定点插入同步。数据进本地缓冲后，PE 阵列怎么算并不变，所以同一套编译器可改靶到不同引擎（TPU 类、Cambricon、ScaleDeep 瓦片）。开源搜索器：stanford-mast/nn_dataflow。

图 7. 三套循环由外到内嵌在一起，编译器按这次序发访存并插入同步。换一种 PE 阵列只需替换最内层。

8. 评测：相对单片、相对 tiled 基线

引擎按 Eyeriss 缩放：28 nm、500 MHz、16-bit MAC 面积 0.004 mm² / 1 pJ；RF 与 SRAM 用 McPAT 1.3；NoC 0.61 pJ/bit/hop。默认 8×8 PE、每 PE 64 B RF、32 kB SRAM。芯片预算约 100 mm² → 16×16 引擎。四通道 LPDDR4-3200，24 Gb、25.6 GB/s。组播按每类数据独立总线、每周期 8 个元素（偏乐观）。性能模型对照 zsim + DRAMSim2 的访存轨迹。默认 batch 64，另扫 1–256。

8.1 主结果：同资源下换数据流

  • 相对单片 M：平均 7.2× 性能、能耗 −41%。单片组播总线又慢又耗电；全局大缓冲复用好，但不支持把多层权重同时钉在片上。
  • 相对 tiled 基线 B：平均 2.0× 性能、能耗 −45%。基线死在复制和填排空，CNN 的中间 fmap 尤其把 DRAM 和 NoC 打满。
  • Tangram：6107.4 GOPS，面积 88 mm²；含片外 439.8 GOPS/W，仅芯片 936.4 GOPS/W。作者对标 14 nm 的 ScaleDeep，称软件数据流约等于两代工艺。
  • MLP-M/L：tiled 能 pinning，单片不能。LSTM-M：Tangram 压低缓冲需求后才 pinning，层间优化带来约 4.6× 能耗下降。LSTM-L 仍然钉不住。

8.2 消融：谁吃哪类网络

BSD（层内）

全部 CNN 都明显受益，因为 fmap 大。MLP-L、LSTM-M 也受益：缓冲压力下降后，流水方案里能选更好的单层 dataflow，总线和 SRAM 访问变少。MLP-M、LSTM-L 几乎没增益。

ALLO + DAG 流水（层间）

AlexNet、GoogLeNet、ResNet、两个 LSTM 省得多：更深的段、更少 DRAM、每层更小区域从而降低层内 NoC，空间 PE 减少反而提高 PE 级复用。VGG 和两个 MLP 是简单线性链，层间优化几乎没贡献。

8.3 缩放：瓦片越多、batch 越大，基线越亏

引擎数从 16 扫到 1024（65536 PE）：单层越来越喂不满全部瓦片，基线的复制和流水问题被放大，Tangram 相对能耗节省最高 67%。大 batch 时 tiled 基线甚至不如单片——数据变大后利用率更差。Tangram 则随 batch 增大而拉大优势。Batch=1（延迟敏感推理）时多数网络相对 tiled 仍大约 10%（AlexNet）；GoogLeNet 因段内共享输入更明显；LSTM-M 靠 pinning 消掉主导的权重访问。

9. 相关工作与边界

细粒度加速器（DianNao 族、Eyeriss、TPU、FlexFlow）解决的是阵列内部。Tangram 站在 tiled 族（DaDianNao、Neurocube、TETRIS、ScaleDeep）上，专门补瓦片间数据流。稀疏（Cnvlutin、EIE、SCNN）主要改引擎内细粒度；作者认为粗粒度仍类似稠密，留给后续。ReRAM 流水（ISAAC、PipeLayer）有层间流水但没有这套循环变换。Fused-layer 用硬连线换细粒度融合，可编程性差。Li 等 FPGA 流水对 FC 有类似 ALLO 的想法，但只覆盖小 CNN。Shen 等异构引擎提高利用率，中间结果仍回 DRAM。Jia 等在多 GPU 上用动态规划搜流水，通常假设整网铺开，也没有系统讨论段深度权衡。

边界要说清。评测是 2019 年 ImageNet CNN / 中等 LSTM，不是 Transformer。静态调度加启发式剪枝，不规则稀疏和控制流不在模型里。MEMTRACK 和邻居旋转假设切分大致均匀。Batch=1 时层间收益缩水。单片基线没有做“全局缓冲再切成多银行去钉多层权重”，对 M 的对比略偏乐观。工具链验证靠解析代价模型加轨迹仿真，不是硅后。

10. 对数据流编译与映射搜索的含义

Tangram 把“加速器编译”明确切成三层循环变换：引擎内分块（Yang / Eyeriss）、瓦片间旋转（BSD）、层间顶层次序（ALLO）。后面 Timeloop、MAESTRO、Interstellar、自研映射器，多半还在把这三层揉进同一个嵌套循环空间。值得从这篇抽出来的，不是 8×8 Eyeriss 瓦片，而是容量按总和计、正在用的数据必须本地、层间只转发子集这三条不随微架构过时的约束。

值得迁移

共享数据不要按私有缓存复制，而要按 NUCA 式迁移或显式旋转。层融合不要默认缓冲完整中间激活，先对齐生产者–消费者的通道遍历次序。DAG 选段：共享输入的 fork 应同段；只覆盖一半消费者的段不如拆开。搜索要显式扫“段深度 vs 每层资源”，而不是默认整网铺上或默认一层打满芯片。

不能照搬

BSD 依赖 MAC 累加可交换和静态可知的旋转周期；注意力、MoE 路由、KV 追加不是这种交换律。ALLO 的“隔层才能对齐”来自 CONV 不能同时顺序扫 I 和 O；GEMM 风格的 QKᵀ 没有通道环这套语义。2D 之字分区假设均匀 mesh；chiplet / 近存模块是星型或分层拓扑，距离模型要换。Model pinning 对 2016 年 MLP 有效，对现代权重/KV 工作集几乎永远钉不满。

可写成映射器约束的三条

  1. 有效 SRAM = 总和 − 复制。任何把同一 ifmap/权重复制到多个计算单元的映射，代价函数里应直接扣容量，而不是只扣 NoC 能量。BSD 说明：扣掉复制之后，许多“必须回 DRAM”的层切换会重新变成片上转发。
  2. 生产者–消费者对齐是一等公民。相邻算子的外层循环次序应作为搜索维度，而不是融合之后再做缓冲分配。对齐成功则缓冲从 O(整张激活) 变成 O(一个 tile)；对不齐则必须整缓冲，并应优先把 BSD 用在这一侧。
  3. 段深浅与 DAG 切割一起搜。更深不一定更好。目标函数要同时看见：少一次中间 DRAM、每算子可用 PE/SRAM 下降、填排空气泡、以及 fork 输入是否只取一次。LSTM-M 的 4.6× 来自“浅到能 pinning”，不是来自无限加深。
和 TOM 对照：TOM 问的是 GPU 上哪段代码该靠近哪一栈数据；Tangram 问的是 tiled 加速器上哪一层该占哪些瓦片、共享数据如何在瓦片间走。两者都把“计算放哪”和“数据如何共址”拆开，并且都坚持程序员不标、编译器/搜索器给方案。对象从 CUDA 指令块换成 NN DAG 的循环嵌套，问题结构仍是同一张图：异构执行引擎、互相冲突的带宽目标、以及必须静态可验证的数据所有权。
