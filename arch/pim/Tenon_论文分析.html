1. 一句话结论

商业 PIM 已经覆盖近 bank SIMD（Samsung HBM-PIM）、bank 级 GDDR 加速器（SK Hynix AiM）、可编程 DRAM 核（UPMEM）和 bit 级 SRAM 向量处理器（GSI），但各家编程模型和数据布局约定互不通用。Tenon 的判断是：这些后端虽然 ISA 不同，却共享一个更强的不变量——计算单元只直接够到自己绑死的存储分区，布局因此既决定合法性，也决定要搬多少数据。它把工作负载、编译目标和代价写成三套可替换的 Python 接口，推广 GPU 编译器里的 F2 线性布局代数，自动构造搬移最少的合法布局，再交给各后端的 lowering。五个商业后端上，它达到或超过各家的厂商、专家或编译器基线，几何平均加速最高 1.20×，单核最高 3.65×。在学术 HBM-PIM 后端 AttAcc 上，Tenon 编译的 GPT-13B 解码在全部三个 batch-4 配置里比 DCC 快 1.2–1.3%。这个端到端数字来自 Ramulator2-AttAcc 仿真再叠加 DCC 的分析 GPU roofline，不是硅片墙钟。

2. 问题：栈是碎的，布局却是一等约束

PIM 正在从原型走向可部署的异构系统：访存密集的层，包括 batched LLM 推理，适合交给近存设备。论文对照的商业形态包括 Samsung HBM-PIM 的近 bank SIMD、SK Hynix AiM 的 bank 级 GDDR6 处理器、UPMEM 的可编程 DRAM 核，以及 GSI 的 compute-in-SRAM 向量处理器。它们的指令、存储层次、并行度和主机接口都不一样。

编程栈仍然是碎的。程序员面对的东西从 PCU 操作码流、AiM 的 ISR 命令轨迹，到 UPMEM 的每 DPU C 内核，再到 GSI 的设备 C / 张量库，各写各的。CINM 用 MLIR 跨过一批 compute-in-memory / compute-near-memory 目标，但设备方言和 lowering 仍然是按后端分的。要在多个 PIM 上评估同一个内核，还得重复做映射和优化。

第二个难点是数据布局。把元素分到哪个 bank、要不要复制操作数、向量寄存器里怎么排，先前工作报告过数量级的性能差：例如 PIMnast 的 GEMV 相对宿主 SoC 有 6.86×，OptiPIM 相对一种 HBM-PIM 映射启发式有 72.8×，GSI 上的二进制矩阵乘有 18.9×。原因很硬：一个 PIM 计算单元只能直接访问自己的存储分区，布局同时决定了“谁能算”和“要不要显式搬家”。现有 PIM 编译器多用设备相关的地址公式和专家调度来编码这些决定，缺一个跨架构的公共表示。

论文认为，一般张量加速器要把循环顺序、多层 tiling、空间 dataflow、分配、路由和流水线分开协调；PIM 反而有更强的共性：计算和一块静态可识别的存储分区绑在一起，跨分区访问通常很贵，甚至必须经过主机。于是计算映射和数据布局收成一个受约束的放置与搬移问题。

3. 做法：三套语言加 F2 最小搬移布局

Tenon 提供三套很小的 Python 接口，用来构造编译器 IR：目标语言描述这台 PIM 能做什么，工作负载语言描述要算什么，代价语言描述生成出来的实现有多贵。编译时再把逻辑工作网格映射到物理目标网格，并插入合法的数据搬移。

目标语言

@tn.unit 描述嵌套的计算/存储轴；tn.mem / tn.reg 声明单元拥有的存储；tn.op 和 tn.move 声明本地运算与显式搬移路径。

工作负载语言

@tn.work 在逻辑工作网格的每个点上跑同一段计算体。一份工作负载描述可以对着不同目标编译。

代价语言

@tn.rule 把物理事件映射成延迟和资源占用。换成另一套代价程序，就可以改变调度排序，而不必改工作负载。

布局为什么能写成代数

规模为 2d 的规则轴只需要 d 个比特来定位。线性布局用二元矩阵 M 把物理坐标比特映射到逻辑张量下标比特，算术在 GF(2) 上进行：加法是 XOR，乘法是 AND。bank 交错、tile 切分和操作数复制都可以写成同一张图；代数检查负责覆盖和冲突。和 GPU 上的 swizzle 不同，PIM 布局还指明“哪个绑定的计算单元拥有这个操作数”，因此也决定了哪些运算和搬移是合法的。这条契约会一直带到 packing、lowering 和代价评估，不再为每个设备单独写地址公式。

论文用两个具体例子把布局选择说清楚。Samsung HBM-PIM 上做 y = Wx 时，沿 k 切 W 会在每个单元留下部分和、又没有单元间数据通路来合并；沿 m 切则可以在本地做完每个输出，但要复制 x。复制代价随 k 涨，归约代价随 m 涨，所以高矩阵和宽矩阵的偏好是反的。GSI Gemini-I 上则是“沿 m 切、在 lane 间做很贵的组归约”和“沿 k 切、留下空 lane”之间的权衡：代价程序在 m = 256 时把前者排在后者前面 128×，到 m 等于 lane 数时只剩 1.4×。

最小搬移布局怎么找

编译器在满足运算、容量、对齐和连续性约束的合法布局里，最小化搬移代价。输入为复制付费，输出为合并部分和付费；所有布局都要付的公共搬移被省略。四个比特的一一映射已经有 20,160 种，穷举不现实。Tenon 先搜索“局部性链”：代价只取决于哪些迭代共享一个单元，而不是迭代在单元内的具体位置；在四个比特、三层各一比特的计算层次上，候选从 20,160 收到 315 条链。找到候选后再生成完整布局，并用代价程序在并列方案里做最终选择。

自动布局不是无条件的。拆开浮点归约会改变舍入顺序，必须显式允许重排部分和；如果要求严格按源程序顺序归约，优化只能在这个约束满足之后再做。非 2 的幂次轴要先 pad 再加 mask，论文也提醒：假设“所有坐标都活跃”的代价公式，不能直接拿 pad 后的结果当合法下界。

调度搜索复用同一套流程：枚举、合法性检查、代码生成、代价评估。tn.compile 完成映射和排序。新后端仍要自己写代码生成、调用约定和运行时，Tenon 不生成、也不在后端之间共享这些部分。

4. 实验怎么做的

论文在六个 PIM 目标上做评测：五个商业后端，加上 AttAcc。加速比是基线延迟或周期除以 Tenon 的对应测量。工作负载套件和计时边界按后端不同，只做组内比较。

5. 结果怎么读

商业后端上的内核性能

  • Samsung HBM-PIM（仿真）。Tenon 的 GENERIC_REDUCE lowering 重建了标准 GEMV 命令序列，与厂商路径完全一致。该对照允许重排部分和，计时包括放置、执行和读回。
  • SK Hynix AiM（仿真）。相对 CENT 专家轨迹，注意力在上下文长度 128 / 4,096 时分别快 1.30× / 1.68×。Softmax 和 FFN 两边延迟相同，所以映射后的整个 PIM block 在长度 4,096 时只快到 1.09×，全表几何平均 1.10×。这些轨迹提供时序对照，但省略了操作数值、列地址和累加器分配。
  • UPMEM（仿真）。图 7 的 16 个内核上 Tenon 全部最快，相对最快可运行基线的几何平均是 1.20×。收益集中在搬移更重的 GEVA、histogram 和 k-means（1.70–3.65×）；稠密矩阵核与最快基线相差不超过 2%。在 1–32 个仿真 DPU 上做主机侧划分时，固定 391×65 GEMV 的最慢 DPU 延迟从 1,149,430 降到 38,484 周期，但这些是设备侧数字，不含主机传输和合并开销。
  • GSI Gemini-I（物理卡）。五个 Phoenix 内核上相对专家实现的几何平均是 1.013×，工作负载描述代码量明显更少（例如 MatMul 从 333 行降到 33 行）。这是专家级对齐，不是大幅度超越。
  • GSI Gemini-II（物理卡）。计的是流水线运行中的周期中位数，按 20 个 batch 摊销，并且排除数据传输。最大收益是 GESUMMV 的 1.67×，来自两个矩阵向量乘带来的图级布局、融合和驻留选择；更接近单条厂商调用的内核只有 1.07–1.12×。引言里对 Gemini-II 的几何平均是 1.19×。

布局搜索和 AttAcc 上的 LLM 解码

在共同的代码生成、算术和计时下，68 个映射、六个 GEMV 的直接对照里，Tenon 赢 1 次、平 4 次、输 1 次，相对重训后的 DCC 几何平均 1.007×。五个 DCC 选择和训练集聚焦，论文自己限制了对未见工作负载的推论。

500 个 AttAcc 实例包括 batch 1 和 4 的 QKV / 输出投影 GEMV，以及每个 batch 248 种形状的注意力打分。Tenon 在 398 个实例上撞上参考仿真器的最好时序，DCC 是 326 个；直接对比是 123 胜、316 平、61 负，全部落在注意力上。这些失败里，相对 DCC 的中位变慢是 7.1%，相对参考最好时序是 9.4%。注意力参考搜索用“代价模型高估有上界”的假设提前停止，所以这些“最好时序”并不是被证明的全局最优。

GPT-13B 解码延迟把 Ramulator2-AttAcc 的 PIM 时序和 DCC 的分析 GPU roofline 拼在一起，并且排除 prefill。两个编译器都把 QKV / 输出投影、注意力和 softmax 放在 PIM 上，其余算子在 GPU 上，差别只在 PIM tiling。FFN 并行和按头流水（包括 softmax）是建模出来的，不是测到的并发执行。六个配置里，batch 1 的加速比精确到两位小数与 DCC 相同（其中 Tenon 有一次很小的落后）；batch 4 上 Tenon 把延迟降低 1.2–1.3%。收益主要来自 QKV：在 batch 4、128 个输入 token、2,048 个输出 token 时，QKV 延迟从 1.2799 ms 降到 1.2332 ms，总延迟从 3.9933 ms 降到 3.9431 ms。两边的 FFN 和其他阶段代价相同，所以应用层收益被卡住了。

不要把“相对 DCC 快 1.2–1.3%”读成新的端到端系统突破。它说明在同一套 AttAcc 仿真和同一份 GPU roofline 里，换一套解析 tiling 选择器可以略优于 DCC 的 XGBoost 预测器，而且省掉大约 6 小时的离线训练扫描；500 个内核的工作负载描述少 66% 行，编译快 2.2×（24 s 对 53 s）。真正拉开差距的，仍是商业后端上那套可重定向的布局和 lowering。

代价校准和虚拟后端

在 Gemini-I 的概念验证里，论文用 Codex 工具和 GPT-5 系列模型，从 15 个物理组件微基准拟合代价，再组合去预测三个未用于校准的 record-frequency 内核形状，把平均绝对延迟误差从 10.67% 降到 1.29%。把拟合后的程序复用到另外八个 record-frequency 和八个 histogram 方案（每类 64 次物理启动、不再拟合），误差分别从 7.41% 降到 1.23%、从 25.92% 降到 0.41%。这是代价接口的可校准性，不是端到端自动调优系统。

虚拟后端只编译、估计代价，不调用设备运行时。对 Llama2-7B 的三个 FFN 投影，论文同时扫 AiM 的行载荷和 Global Buffer：单独加大任何一边都不会改善延迟，两边一起加倍时，预测加速 1.30×、仿真加速 1.27×；四倍则是 1.547× 和 1.482×。引言把这个拐点写在 4 KB Global Buffer。这些都是未流片变体，并且假设更大的 tile 能使用更宽行的前缀；收益以这些架构和时序假设为条件。

6. 和已有 DCC、PIMphony 笔记的关系

仓库里的 DCC 笔记已经把“Host 和 PIM 要的布局是反的、不能先调计算再补重排”讲清楚了。Tenon 不是再做一个只面向 AttAcc / HBM-PIM 的数据中心编译器，而是把同一类问题做成可重定向的框架：一份工作负载对着 Samsung、AiM、UPMEM、两代 GSI 和 AttAcc 编，布局用公共代数表示，代价程序可以换。和 DCC 的直接交锋集中在 AttAcc 仿真上，端到端差距只有百分之一点几，内核选择互有胜负。

Tenon 也把 PIMphony 的 token 划分写成“通道放置加部分结果归约”。在 8 个仿真通道上，对 1/2/4/8 路划分搜索，九个测量最小值里命中七个（最大差距 2.63%）；对一个头、4,096 个 token，比只按头放置改进 1.071×。这九个负载覆盖 1/8/32 个头和 128/512/4,096 个上下文 token，头维度 128。计时包括打分、全局 softmax、value 求和、主机阶段和归约，链路按 32 GB/s、固定延迟为零；输入已驻留，cache append、投影和 PIMphony 的其他优化都不在对照里。它验证的是“已有 PIM 系统里的划分能被写成 Tenon 布局”，不是复现整篇 PIMphony。

7. 落地可能性

落地的有利条件比较具体。第一，GSI 两代卡是物理设备上的周期，Gemini-I 达到专家内核的 1.013× 几何平均，说明这套布局和 lowering 至少在 SRAM-CIM 向量机上不是只会仿真讲故事。第二，程序员写的工作负载描述明显更短，AttAcc 上还少了 DCC 那约 6 小时的预测器训练。第三，目标加代价程序可以当虚拟后端，在没有仿真器或硬件时先探结构，例如 AiM 的 Global Buffer 拐点。第四，可执行的代价程序给了一次用语言型号拟合组件代价的接口，Gemini-I 上误差下降是测到的。

要把它接到生产编译栈，缺口同样清楚。可移植性只共享工作负载 / 目标 / 代价接口和部分搜索基础设施，不共享调度代码、ABI 或运行时；新的数据格式仍要写代码生成和启动代码。原型没有通用的分配和 spilling，装不进寄存器的值不能自动换出。不支持的运算只能回退到设备或主机。加权搬移还可能在代价排序前剪掉运行时其实更快的布局——论文在 Gemini-I 的 tile 64 对 tile 256 上给出过 3.845% 的反例。文中也没有公布开源仓库，复现和对接要另做。

若只关心 LLM 解码，Tenon 今天最有用的不是那 1.2–1.3%，而是：同一套描述能编到多类 PIM 上，并且在 AttAcc 上可以和 DCC 并排放进同一套仿真协议里比较。若关心商业 PIM 软件栈，更值得看 UPMEM 和 Gemini-II 上那些靠布局去掉搬移、保住驻留的内核，以及 AiM 上注意力相对 CENT 专家轨迹的加速。

8. 局限

  • 解析模型仍需验证。AttAcc 的选择是和参考 Ramulator2-AttAcc 时序比的；注意力参考搜索用模型误差上界提前停止。Gemini-I 只在两个工作负载家族上验证了物理点预测，不足以证明更广泛的调度排序能力。
  • AiM 结构探索假设命令时序固定，不能据此声称硅片性能、面积、功耗或时序收敛。
  • 非 2 的幂次形状依赖 padding 和 mask；用恰好可表示的整数输入做的测试，不能证明任意浮点输入下的等价性。
  • UPMEM 的多 DPU 扩展数字排除了主机传输和合并；Gemini-II 的对照排除了数据传输。读加速比时要顺着计时边界走。
  • 和 DCC 的部分 GEMV 对照里，有些 DCC 选择与训练集聚焦；端到端收益被两边相同的 FFN 和其他阶段限制住了。
