1. 一句话结论

边缘设备上的 4D Gaussian Splatting 被两件事拖住：时域过滤发生在完整记录已经从 LPDDR5 读进来之后，73.3%–86.8% 的传输随后用不上；相邻帧的活跃集和深度关系高度重叠，按帧孤立执行又会在工作集超过片上缓存时反复装同一批属性。GSPIM 在 bank 侧用一套可编程的多态近存（PPIM）按不同 4DGS 表示做本地活跃判定，再经层次化压缩互连（HCF）把有效数据排成连续块，GPU 才去读完整属性。时间窗口内复用活跃属性和稳定的深度顺序，混合调度让近存准备和下一次 GPU 渲染重叠。评测平台是校准到 Jetson AGX Orin 64 GB 的 GPU–PIM 模型，近存电路用 Chisel 写、在 1z DRAM 工艺上做了综合与布局布线。三个 4DGS 方法和六个动态场景上，相对充分优化的逐帧 GPU 基线，几何平均加速 5.36×、系统能效 4.99×；场景级 PSNR 最多差 0.006 dB。这些吞吐和能效不是一块已封装的 PIM 内存条在 Orin 上量到的墙钟时间。附加电路在 32 个 die 上的物理面积是 18.7172 mm2，有功能耗 3.8363 W。

2. 问题：时域过滤太晚，帧间还不复用

4DGS 在 3D Gaussian Splatting 上加入时间维，用来做动态场景的新视角合成，服务自由视点视频、移动 XR 和边缘上的自治系统。论文覆盖的三类显式表示——显式 4D 分布、关键帧插值和锚点绑定——都会先根据每条记录的时域字段判断是否活跃，再加载几何和外观去做逐帧渲染。

边缘 GPU 通常和 CPU、多媒体引擎共享 LPDDR，带宽和片上缓存都紧。论文在 Jetson AGX Orin 上拆基线后看到两个访问问题：

  • 过滤发生在加载之后。时域判定只需要少量本地字段，却控制着大得多的属性是否该被访问。GPU 侧先把完整记录搬进来再过滤，会让 73.3%–86.8% 的 LPDDR5 传输在后续计算里用不上。时域过滤占基线执行时间的 52.4%–63.3%，排序和光栅化合计 26.5%–34.8%，算术强度都落在相应 roofline 脊点之下，过滤最低。
  • 按帧孤立执行，浪费帧间重叠。相邻帧的活跃集和深度关系高度重叠，但逐帧路径会反复装共享属性，工作集一旦超过片上缓存就更明显。现有专用加速器会利用空间或帧间相关性，却没有把共享源属性组织成多帧 batch。

近存计算适合这类“先用很小的本地字段做决定，再决定要不要搬完整属性”的模式。GSPIM 把决定和压缩留在 bank 侧，把渲染仍留给 GPU。

3. 做法：多态近存、多帧数据流、混合调度

图 1（示意）：近存先筛选和压缩，GPU 再按时间窗口做生成、稳定集排序复用和渲染。

多态近存 PPIM

不同 4DGS 表示的字段布局和选择过程不一样，但活跃与否都由有界的本地算术或区间测试决定。PPIM 用共享的 bank 侧数据通路适配这些差异，在 GPU 访问完整属性之前给出选择结果。

层次化压缩 HCF

选择结果驱动 bank 级和 die 级压缩，去掉不活跃属性，把有效数据排成连续块，减少无效的 LPDDR5 传输和零散访问。

多帧数据流

把共享属性收成能放进 L2 的 batch，窗口内复用属性和稳定图元的排序结果，只对深度变化大的图元按帧排序。双缓冲让近存准备和 GPU 多帧渲染重叠。

运行时用混合数据流调度：近存侧的 PIM_SELECT / PIM_REORG 与 GPU 的生成、排序和渲染按窗口和 batch 重叠，减少串行等待。硬件配置里，8 个 LPDDR5 封装、每封装 4 个 die、每 die 16 个 bank（12 个 PIM、4 个保留），一共 384 个 PIM 单元，PPIM 跑在 200 MHz；GPU 侧按 AGX Orin 的 16 个 SM、4 MB L2、204.8 GB/s 和 64 GB 容量来建模。

稳定性阈值默认 τs = 0.98，对应论文中归一化深度变化均值的上界约 0.0202。更低的阈值允许更大深度变化，更高的阈值会降吞吐，换来最多约 0.01 dB 的质量。敏感性扫描里，0.98 距离峰值 FPS 不超过 0.6%，距离全排序 PSNR 不超过 0.012 dB。

4. 实验怎么做的

工作负载是三类 4DGS：4DGS-1K、Ex4DGS 和 Anchored 4DGS，分别代表活跃掩码过滤、关键帧插值和锚点绑定。场景来自 N3V 和 EasyVolcap，覆盖室内外、局部非刚性和遮挡变化，一共六个动态场景。

GPU 对照在 NVIDIA Jetson AGX Orin 64 GB 的 MAXN 模式上跑，GPU 和内存频率固定。逐帧路径和多帧路径共用优化过的 CUDA 后端：CUB 做过滤、前缀和分段基数排序，gsplat 做投影和光栅化，并按方法调过线程配置和 batch 大小。“AGX Orin + GSPIM Dataflow”是纯软件实现完整多帧数据流的版本；Full GSPIM 保留这条多帧路径，但把选择和数据重整卸载到 PPIM 和 HCF。

专用加速器对照包括 3DGauCIM、QI-4DGS 和 Relay-GS。论文从架构和电路数据重建周期/功耗模型，并复现原文工作负载和参考配置，吞吐和功耗的最大相对误差低于 1.5%。等面积比较把 ASIC 面积用 DeepScaleTool 等缩放到 8 nm，并计入外部存储和共享控制/互连。

哪些是测的，哪些是仿的

  • PPIM、HCF 以及 DRAM 侧命令和状态电路用 Chisel 实现，Verilator 周期模型接入 Ramulator 2.0，按 LPDDR5-6400 计时，刷新是每 3.9 μs 持续 280 ns。
  • 时序模型用 Orin 的带宽微基准和 Nsight Compute 访存轨迹校准，匹配负载下带宽和访存延迟的最大相对误差分别是 1.4% 和 1.2%。
  • 窗口执行时间按帧摊销，计入任务依赖、测到的 GPU 阶段时间、仿真的 PIM 时间、刷新停顿，以及 PIM 流量和刷新给 GPU 访存增加的等待。
  • GPU 侧能量来自重放执行和等待期间的板载 GPU / SoC 轨道测量；PIM 能量结合 1z 开关动态能量和全程泄漏；LPDDR5 的读、写、刷新和背景能量由命令和状态轨迹决定。
  • 附加 DRAM 侧电路用 1z DRAM 外围逻辑库做综合、布局布线；功耗基于周期仿真的工作负载 VCD，1.05 V、TT、25°C。Icepak 对四层叠 die、PCB 和模组散热做 3D 热分析，入口空气 40°C、1 m/s。

5. 结果怎么读

相对优化逐帧 GPU

只上软件多帧数据流，已经有 2.40× 几何平均加速，P95 / P99 分别降 46.8% / 48.2%。GPU 自己做选择和压缩仍要扫描全集并写中间结果，准备阶段偏长。完整 GSPIM 把准备和 GPU 生成、渲染重叠后，几何平均加速到 5.36×；相对软件数据流，摊销后的平均帧时间、P95 和 P99 再降 55.2%、44.2% 和 43.5%。在 Actor1_4 这种强非刚性运动上，Anchored 4DGS 的 P99 从 7.81 ms 降到 4.77 ms。

阶段拆解里，GSPIM 把占软件数据流时间 36.1%–47.5% 的 S1 卸载到 PIM，再靠 HCF 重整减少 S3 和 S5 的 GPU 工作，GPU 各阶段执行时间之和降 54.1%–61.1%。PIM 任务总时间相当于软件数据流的 16.2%–21.1%，并且和 GPU 执行重叠。争用停顿平均占 GPU / PIM 任务时间的 1.8% 和 7.7%。相对关闭刷新，吞吐损失平均约 0.25%，最高 0.35%。

能效上，软件数据流的几何平均提升是 2.08×。只看测量到的 GPU 任务重放，PPIM 和 HCF 把它做到 5.07×；把 PIM 的动态和泄漏以及 LPDDR5 的主动和背景能量算进去，系统能效是 4.99×。

等面积下的专用加速器对照

在相同系统面积下，GSPIM 相对 AGX Orin 的原生 4DGS 吞吐几何平均是 3.43×。相对 3DGauCIM，吞吐高 32.9%、能效高 6.4%；相对默认打开 AQFI 的 QI-4DGS，吞吐高 39.8%、能效高 11.8%。关掉 AQFI 后，QI 的几何平均吞吐是 1.57×，GSPIM 在同一条原生生成路径上是它的 2.18×。相对 Relay-GS，吞吐高 18.7%、能效高 24.4%。Flame Steak、Dance3 和 Actor1_4 上的时域稀疏或较大活跃集会放大收益，Dance3 达到 3.98×；Cook Spinach 和 Sear Steak 上，更大的逐帧生成和光栅化更有利于专用算术。

质量和消融

表 III 里，软件数据流和完整 GSPIM 相对 Orin 基线，场景级 PSNR 最多差 0.006 dB，SSIM 最多差 0.0001。另用一套原生 4DGS 模型和专用加速器对比时，GSPIM 的差异峰值是 0.010 dB 和 0.0003，都低于 0.04%。最坏情况分析在 Dance3 的 24 帧相机运动序列、4DGS-1K 上：相近的稳定高斯仍可能交换深度顺序，单帧 PSNR 损失峰值 0.030 dB（第 11 帧），LPIPS 增加约 0.0013。

消融显示：数据流和近存合在一起、但不做窗口和 batch 重叠时，加速是 3.10×–4.87×；再加上重叠，额外获得 1.18×–1.60×，达到相对 Orin 的 3.75×–7.78×。PPIM 选择加 HCF 压缩让 GPU 可见的 DRAM 流量和事务平均减少 69.2% 和 62.7%。

扩展到 3DGS 和其他平台

在静态 3DGS、六个 Tanks and Temples 场景上，软件数据流和完整 GSPIM 的几何平均加速分别是 1.54× 和 2.96×；完整路径比 3DGauCIM 的 2.52× 再高 1.17×。跨平台时，完整 GSPIM 在 Nano / NX 上是 4.52× / 4.63×；在 RTX 4090 / H100 上报告的是仅数据流的能效收益 1.65× / 1.52×，不是把 LPDDR5 近存硬件搬到了桌面或服务器 GPU。更大场景和分辨率（含 MatrixCity 的 2,370 万高斯，以及 720p / 1080p / 4K）上，软件数据流和 GSPIM 相对 Orin 的几何平均是 1.93× 和 3.66×。

6. 落地可能性

和很多只停留在架构模拟的近存工作相比，GSPIM 多做了两件对落地有用的事。第一，近存附加电路在 1z DRAM 工艺上走完了综合和布局布线：32 个 die 的物理面积 18.7172 mm2，折合每 die 0.5849 mm2，约为 60.92 mm2 的 16 Gb LPDDR5 参考 die 的 0.96%；有功能耗 3.8363 W（动态 3.2582 W，泄漏 0.5781 W），每 die 0.120 W，每个四 die 封装 0.480 W。掩码列选择逻辑增加 0.28 ns，论文称仍在列访问时序裕量内，不改变外部读写延迟和列命令间隔。热分析给出约 70°C 的稳态峰值封装壳温，比 85°C 的 WT 级工作上限低约 15°C。第二，仿真器已开源（MAdrid1011/GSPIM），并且 Orin 侧有校准误差上限。

要变成可买到的边缘模组，仍差完整的内存产品化：不是一块已经和 Orin 封装在一起、能直接量墙钟的 PIM LPDDR5；端到端倍数依赖校准模型、Ramulator 时序，以及 GPU 阶段重放与 PIM 仿真的拼接。PPIM 针对“记录里带本地时域字段、用这些字段决定窗口活跃性”的表示，换一套完全不同的 4DGS 时间模型可能要重新写近存微程序。桌面和服务器 GPU 上，论文只把软件多帧数据流做了外推，带宽更高时，属性复用带来的相对能效会变小。

如果做边缘 4DGS 或 3DGS 渲染，值得同时看两条可分开落地的线：一条是不用改内存、只上多帧数据流和稳定集排序复用（Orin 上已经有 2.40× / 2.08×）；另一条才是改 LPDDR5 外围、在 bank 侧做筛选和压缩。前者可以先在现有 Orin 类平台验证，后者才需要存储厂商配合。

7. 局限

  • 端到端 5.36× 和 4.99× 来自校准仿真加 GPU 重放，不是 PIM 内存模组在整机上的实测墙钟。
  • 专用加速器对照是重建的周期/功耗模型并缩放到 8 nm 后的等面积比较，不是同一块硅上的对打。
  • RTX 4090 / H100 上的数字只覆盖软件数据流的能效，不能读成这些卡已经接了同样的近存硬件。
  • 最坏情况下单帧 PSNR 可差 0.030 dB；稳定集复用把误差限制在 alpha 合成顺序里，但高对比重叠处仍可能被放大。
  • 近存筛选假定活跃性可以从记录内的本地时域字段判定；表示一变，PPIM 程序和压缩收益也会变。
