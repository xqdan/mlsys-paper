DATE 2027 arXiv:2611.32223v1 模拟存内计算 · CIM 北航 × 港大 × 北大 16 芯片混合实测 + 校准仿真，不是完整模型上板

Beyond Autoregression：模拟存内计算更需要扩散式生成，而不是再把 AR 解码做硬

AIMC 的权重扰动在自回归解码里会被写进因果上下文并级联；扩散语言模型把不确定的 token 留到更晚再提交。论文用对照实验排除“多轮噪声平均”，并在校准噪声模型和 16 芯片 eFlash AIMC 集群的混合测量里，给出 1.4–3× 的可容忍噪声差距。

1. 一句话结论

模拟存内计算能把矩阵向量乘放在阵列里做，但编程偏差、电导漂移、读噪声和外围电路非理想会扰动有效权重。自回归模型每个 token 一生出来就被写进因果上下文，一次被扰动翻错的 token 会改变后面所有预测。扩散语言模型迭代地去噪、先提交有把握的位置，把不确定的位置留到上下文更清楚再决定。论文在规模对齐的模型和公开检查点上观察到 DLM 在持续权重扰动下退化更缓，并用对照实验表明：这不是多轮独立噪声被平均掉，而是延迟提交和逐步补全上下文。去噪步数还可以当成 DLM 特有的“延迟–鲁棒性”旋钮。在按片上 MVM 误差校准的扰动模型下，8B 量级、八个基准的仿真里，σ=0.3 时 DLM 均值在所有基准上都超过 AR 均值，差距从 20 个百分点（ARC-C）到 45 个百分点（GSM8K）。16 芯片 28 nm eFlash AIMC 集群上的混合测量给出：在暂定 2% 相对损失阈值下，DLM 可容忍的有效噪声是配对 AR 的 1.4–3 倍，从 45M 的 1.4× 扩到 8B 的 3×。混合测量里，注意力/FFN 的 MVM 在 AIMC 上，其余计算在数字侧。

2. 问题：AR 会把一次扰动写进后续所有步

AIMC 把 MVM 留在存储器阵列里做，减少数据搬运，这是它被拿来做语言模型推理的原因。代价是有效权重会被器件和电路非理想扰动。对判别式网络或单次 token 精度，已有不少硬件感知训练、校准和补偿。论文关心的是另一件事：这些扰动如何在生成轨迹里被放大。

自回归解码从左到右，每个生成出来的 token 立刻成为后面所有步的上下文。扰动只要在靠前的位置把 token 翻错，后面的预测就在错误上下文上继续，形成级联。因此 AIMC 上的 AR 鲁棒性，不只是单次 MVM 误差有多大，而是一次局部错误会不会被不可逆地提交。

扩散语言模型走另一条生成过程：对部分掩码的序列做迭代精炼，可以先确定把握大的位置，把不确定的位置留到后面。图 1 用深度 32、宽度 4096、词表约 128k 的 LLaDA-8B 和 Llama-3-8B 对照——后者预训练 token 数多 6.5 倍，但在权重扰动下 LLaDA-8B 退化更缓，并在中等噪声下于 GSM8K 上反超 Llama-3。论文据此认为，这是生成方式本身的特性，不是训练规模带来的。

3. 做法：机制分析，再校准到 AIMC

这篇不是新的 CIM 宏或编译器，而是把生成范式放到 AIMC 的误差模型里检验。工作分成三步：先在受控扰动下比较 DLM 和 AR，再做提交时机和上下文解析的干预实验，最后把扰动模型校准到真实芯片的 MVM 误差，并在 16 芯片集群上做混合测量。

持续扰动，而不是每轮重采样

默认设置把一次采样出的误差图固定下来，在整条 AR 解码或全部去噪轮次里复用，用来模拟一次编程后的器件失配，而不是每一步独立的读噪声。GPU 扫描取权重主导极限，等效为乘性高斯扰动；嵌入和语言模型头保持数字，不注入扰动。校准后的物理模型是按权重大小加偏置项的加性高斯，用来对接后面的片上误差。

机制：延迟提交，不是噪声平均

一个容易想到的解释是：DLM 多轮去噪，把相互独立的参数扰动平均掉了。但默认设置里扰动是共享的、整条轨迹不变，这个解释本来就不成立。论文仍显式比较了“共享扰动”和“每轮重采样”。若平均是主因，重采样应当系统更好；结果显示没有这种系统优势。他们进一步把强制提交的轮次提前或推迟：在提示、噪声种子和总去噪预算固定时，把提交从第 0 轮推迟到第 8 轮，事后不匹配在 45M 模型上从 0.835 降到 0.265，在 125M 上从 0.85 降到 0.30。上下文解析实验里，参考 token 的对数概率裕度随已解析上下文比例单调上升；权重噪声造成的最大裕度下移是 −0.541 nats，小于上下文补全带来的裕度增益。这些实验支持“先提交有把握的位置、用更完整的上下文挡住翻转”，但论文自己写明：这不是唯一来源，也不能说自然 rollout 的上下文都有 oracle 质量。

硬件平台

原型是 28 nm eFlash AIMC，四核，带 DAC/ADC，和 12 nm 逻辑裸片混合键合成三维堆叠，经 PCIe/DDR 控制。16 枚芯片组成集群。映射对象是每个 Transformer 块里的线性算子（注意力投影和 FFN 权重）：权重大阵切成阵列块，有缺陷的列用备用列重映射。论文特地提醒：部署图描述的是被测量的线性 MVM 如何路由，不能读成完整模型都在这些裸片上执行。

4. 实验怎么做的

数字要分三层看。第一层是 GPU 上的受控扰动和公开检查点扫描，用来谈机制。第二层是用片上 MVM 误差校准后的扰动模型，在 8×L20 服务器上对 8B 量级模型做仿真。第三层是 16 芯片集群上的混合测量：注意力/FFN 的 MVM 在 AIMC 上，其余计算在数字侧。混合工作点写作 σeff=0.15。表 I 的“Max σeff”是暂定 2% 相对损失阈值，不是器件规格书上的保证噪声容限。

公开检查点方面，GSM8K 用完整测试集 1,319 题，七个噪声水平、三个噪声种子；PIQA 用完整验证集 1,838 例。LLaDA 和 Llama 分别跟各自发布的 5-shot 和 8-shot 协议。规模对齐的小模型另有对齐的训练和评测设置，避免把干净精度差异当成鲁棒性。校准跟随 NoiseGuard，拟合后的 MVM 误差边缘分布相对测量直方图的 KL 为 0.003，未校准高斯为 0.246，文中写作 82× 的 KL 下降。8B 仿真比较两组 DLM（LLaDA-8B、Dream-7B）和两组 AR（Qwen2.5-7B、Llama-3.1-8B），σ ∈ {0, 0.1, 0.2, 0.3}，八个基准。

5. 结果怎么读

机制和受控比较

公开 DLM 检查点在 PIQA 上随 σ 上升退化较缓；论文把 σ=0.2 处的差异拆成“干净模型本来就有的差距”和“扰动额外带来的退化”，避免把绝对精度差直接叫做更鲁棒。规模对齐的 AR 与 MDLM 比较里，MDLM 的相对验证损失上升更小，说明这不是某个检查点或干净精度更高造成的。增加去噪步预算会缩小干净和含噪之间的差距，因此多出来的轮次不只是提高干净生成质量，也为在最终决定前纠正或推迟不确定预测提供了机会。

校准仿真（8×L20，不是板上）

AR 模型在 σ=0 时干净精度更高，但优势在 σ=0.1 已经消失，并在更大扰动下反转。σ=0.3 时，DLM 均值在全部八个基准上都超过 AR 均值，差距从 20 个百分点（ARC-C）到 45 个百分点（GSM8K）。这是校准模型上的仿真扫描，用来把前面的趋势推到 8B 量级，不是 16 芯片集群的墙钟精度。

去噪步是 DLM 特有的旋钮。LLaDA-8B 在 64/128/256/512 步时，相对退化从 40.4% 降到 21.7%、10.5%、3.9%，延迟为 0.73 / 1.42 / 2.81 / 5.58 s，能量为 410 / 801 / 1590 / 3150 mJ，代价大致随步数线性增加。标准 AR 解码没有这一档“多走几步换鲁棒性”的控制。这些延迟和能量是混合测量边界内的生成代价，不是完整 8B 模型全部在 AIMC 上的系统能耗。

6. 和已有近存笔记的关系

仓库里已有的近存笔记大多针对数字 DRAM/HBM PIM、近 bank 计算、PIM 编译或 CXL/HBF 近存系统。这篇走的是模拟 CIM：阵列里做 MVM，误差来自器件物理，对策是换一种生成范式，而不是再加一套 bank 级 ISA 或编译器。它和 PIMphony、DCC、Tenon、Synapse、ANOR 不重复，补的是“语言模型如何在不理想的模拟阵列上生成”这一层。

贡献的重心在算法–硬件协同，不在新的 CIM 宏电路。如果只关心 bank 级 PIM 系统实现，这篇不会直接给出可综合的引擎。如果关心模拟 CIM 能不能承接生成式模型，它提供的是目前比较少见的、带校准和混合实测的证据：问题可能出在 AR 的提交方式，而不只是阵列精度差一点。

7. 落地可能性

有利条件比许多纯仿真 CIM 论文具体。第一，有 28 nm eFlash 原型和 16 芯片集群，校准对着测到的 MVM 误差，KL 从 0.246 降到 0.003，不是随手加的高斯。第二，混合测量把“哪些算子上板”写清楚了，并且明确警告部署图不能当成完整模型上板。第三，去噪步数是一个可以在部署时调节的旋钮：512 步能把 LLaDA-8B 的相对退化收到 3.9%，同时也把延迟和能量带到大约 5.58 s 和 3150 mJ，成本和收益可以放在同一张表里看。第四，工作已被 DATE 2027 接收，材料完整度高于同期一些未标注会议的预印本。

要落到可用的 AIMC 推理系统，缺口同样清楚。完整的注意力 softmax、采样、KV 管理和语言模型头仍在数字侧，8B 的上板结果不能外推成“8B DLM 已经在这套集群上端到端推理”。阈值 2% 是论文自己定的工作定义，换成别的质量门槛，1.4–3× 会变。延迟随步数线性上涨，说明鲁棒性不是免费的；在低延迟场景里，64 步时 LLaDA-8B 相对退化仍有 40.4%，并不比 AR 自动更香。扰动默认是一次编程后的静态误差图，不覆盖运行中的漂移和逐次读噪声叠加。小模型上的提交干预支持机制，但作者不把它写成唯一原因。

今天值得记下的是那条硬件含义：如果鲁棒性来自延迟提交，DLM 可以容忍更大的持续权重误差，从而放松阵列保真度，而不是先把 AIMC 的编程精度做上去再硬跑 AR。这条判断目前由校准仿真和混合测量支撑，还差完整模型上板和更真实的器件动态误差。

8. 局限

  • 8B 公开检查点的提示协议并不对齐（5-shot vs 8-shot）；规模对齐比较主要在小模型上。
  • 自然 rollout 的上下文实验表明随机上下文会把裕度打到 0.02，但 oracle 上下文并不等于真实生成上下文。
  • σ=0.3 时 20–45 个百分点的优势来自 GPU 校准仿真，不要和混合测量表 I 混抄。
  • 延迟和能量只在混合边界内、按每次生成报告，没有和同等质量的 AR 系统做端到端能效对比。
  • 没有把阵列面积、功耗或吞吐作为一阶指标，因此不能直接回答“这块 AIMC 宏有多好”，只回答“这种生成方式更能扛这块阵列的误差”。
