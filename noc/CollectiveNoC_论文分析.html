1. 一句话结论

当一颗芯片上已经能放下成百上千个计算集群时，GEMM、注意力融合和各类分发/规约，看起来就很像过去在机柜里做的集合通信——只是现在发生在 NoC 上。这篇 MLSys 2026 论文把组播、规约和屏障做进开源的 FlooNoC，并且提出 Direct Compute Access（DCA）：路由器不在自己里面堆宽位浮点树，而是直接借用本 tile 里已经付过面积的 FPU 来做网内规约。TSMC 7nm、1 GHz 下，全套集合扩展只增加 16.9% 的路由器面积、tile 级开销低于 1%。在 1–32 KiB 上，硬件组播和规约相对最好的软件实现几何平均快 5.3 倍和 2.8 倍。用已校准的模型外推 GEMM：SUMMA 靠组播可以在直到 256×256 的 mesh 上仍保持计算绑定（软件组播在 16×16 就掉进通信绑定），最高估得 3.8 倍；融合的 Concat+Linear 靠规约最高 2.4 倍；能量最高约 1.17 倍。论文把「大加速器的 NoC 应该会做集合通信」从口号写成了可综合、可对照软件基线的设计。

组播原语数字来自周期精确 RTL 仿真；GEMM 的 3.8× / 2.4× 和能量数字是「用已验证的通信模型 + 既有计算模型」做的分析估计，不是在 256×256 网格上跑出来的全芯片 RTL。宽规约每个路由器同时只支持 2 路输入，从 1D 走到 2D 时 32 KiB 传输会慢约 1.9 倍，之后再加行数，硬件时间几乎不再涨。不要把 3.8 倍读成「任意 Transformer 端到端快 3.8 倍」——论文自己把条件写清楚了：通信必须在关键路径上，并且模式要能映射成组播或规约。

2. 问题：上千个 PE 已经把片上当成了分布式系统

作者从一条已经被说滥、但仍在恶化的剪刀差起笔：过去二十年峰值 FLOPS 大约涨了 6 万倍，DRAM 带宽大约只涨了 100 倍（引 Gholami 等 2024）。加速器靠堆 PE 续上算力，片上通信和近存搬运却没有同比例变好。机柜级的集合通信已经有 SHARP、各种通信库；片上却长期默认「程序员或 DMA 自己发起一串单播」。结果是，权重广播和部分和规约会把 mesh 打满，双缓冲也救不回来——论文在 4.3 节观察到，大配置下 GEMM 会掉到通信绑定，256×256 mesh 上利用率不到 50%；把集合原语加速之后，内核时间最高能回来 3.8 倍。

他们还点了一篇 2025 年的 FlatAttention：用协调好的片上集合操作减少出片访存、提高张量单元利用率，相对 FlashAttention-3 最高 4 倍。这不是本文的实验，但说明目标负载已经从「缓存一致性里的小消息组播」变成了「GEMM / 注意力里的突发、软件管理的大块搬运」。

相关工作里有一句很关键的判断：传统观点认为片上不该做 many-to-one 的硬件支持，因为面积太贵（Krishna 等 2011）。既有网内规约多半只合并短 ACK，而不是做高吞吐算术规约。商用芯片方面，论文点名 Meta MTIA、SambaNova SN40L、Tenstorrent Blackhole 都有组播能力，但机制和量化都是闭源。作者声称这是第一份面向可编程 ML 加速器、端到端开源、并且拿硬件集合去对优化过的软件基线的设计。这个「第一」依赖他们划的范围（可编程 manycore + 开源 + 软件对照），阅读时当成主张，不必自动写成定论。

3. 思路：在 AXI 兼容的 mesh 上编码多地址

基线系统沿用 FlooNoC（Fischer 等，IEEE TVLSI 2025）：2D mesh 上混合计算 tile 与内存 tile。计算 tile 是 8 个带 64-bit SIMD FPU 的 Snitch 核，共享 128 KiB L1，另有第 9 个核带着 DMA 做 tile 间突发搬运；内存 tile 带 1 MB L2 SPM。DMA 走宽网络，一次传输可写成 T = α + nβ（往返延迟加每拍一拍的 payload）。

集合通信的第一个麻烦是：怎么在一条事务里写出多个目的地。他们沿用 2025 年那篇 AXI 交叉开关组播里的办法——在 AWUSER 里带一个与地址等宽的掩码，置位的地址位视为 don’t care，掩 n 位就能表示最多 2n 个目的地。编码随地址空间对数增长，与目的地个数无关，因此能放到大规模 mesh 上；代价是能表示的集合不任意，只能是对齐的子网格。不满足的集合就拆成多笔事务。

落到 NoC 上，网络接口把地址掩码翻译成 X/Y 坐标掩码，塞进 AW flit 头，并在后续 W flit 上复用。AXI 还把组播和规约绑在一起：一笔组播 AW 会从多个从设备收回多个 B 响应，发起方却只想看到一个 B，所以网内必须把响应规约掉；反过来，多发起方做规约时，目的地的响应又要组播回去。协议上先承认这个对偶，路由器设计才不会把组播和规约当成两个互不相干的补丁。

可集合的区域必须是对齐到宽度/高度（且宽高为 2 的幂）的子 mesh。多数不规则地板规划要用「填充」把区域摆正。各节点地址空间还被假定成等大小、按 2 的幂对齐、沿 Y-major 连续映射，这样掩码翻译能收成位选择。这些约束是为了规模，不是为了通用 CMP。

4. 关键机制：组播分叉、两类规约、DCA

组播：在 xy_route_fork 上选多个出口

原来的 XY 路由只算一个出口。现在根据目的坐标和 X/Y 掩码，fork 可以同时选中多个输出端口，再由 stream_fork 保证所有被选出口都就绪才接收输入 flit——这是树形组播，不是在源端把同一块数据发很多遍。1D 硬件组播的时间被写成 T_hw = α + (n + c − 1)β：付一次启动延迟，然后 payload 与沿途的集群数流水铺开。

窄规约：每个出口一套并行归约器

为了合并组播的多个 B 响应，每个输出端口本来就需要一点规约能力。他们把这条路做成可并存的并行规约：同步模块根据掩码算出还要等哪些输入，多路规约用前导零计数器仲裁，交叉的规约路径也不会死锁。本工作实现了三种轻量操作：CollectB（合并组播响应）、SelectAW（聚合规约请求的 AW）、LsbAnd（对最低位做与，用来做屏障）。

宽规约：每个路由器一次只吃两路，并可卸载到 FPU

在宽网络上做浮点、多输入树会很贵。他们改成：每颗路由器只有一份集中的宽规约逻辑，同时只服务一笔、最多两路输入；用 header 缓冲把流水线延迟藏掉，缓冲深度大于功能单元级数时可以达到每拍一笔。两路不够时就在树上多拍，这解释了后文 2D 规约的吞吐打折。

DCA：让网络直接借用已经存在的 FPU

Direct Compute Access 是本文最值得记住的结构想法。计算集群增加三个 512-bit 端口（两路操作数、一路结果），操作类型走控制信号。512 bit 被切成 8 个 64-bit 片，分给 8 个 FPU；DCA 请求与核自己的 FPU 请求用 tag 在流水线里分开。于是宽规约不必在路由器里再造一棵浮点树——算术单元的面积本来就已经在 tile 里了。按 SIMD 宽度，系统每拍最多做 8 次双精度或 64 次 8-bit 浮点规约。核可以被闲置在低功耗状态，由网络把运算推过来。

图 1. DCA 把网内算术规约卸到 cluster 已有的 FPU。本图是示意，不是原文插图。

作者强调这不绑死在 Snitch 或 FlooNoC 上，只要具备三件套：规则 2D mesh 与 XY 路由、tile 内可外借的算术单元、可编程的数据搬运引擎。他们把 Cerebras WSE-3、Tenstorrent Blackhole、AMD XDNA、SambaNova SN40L、Meta MTIA 以及若干学术加速器都列进这个模板。这是类比，不是说这些芯片已经实现了 DCA。

5. 面积、原语与 GEMM

面积与时序

NI 和路由器、以及完整 cluster tile，在 TSMC 7nm、Fusion Compiler 2024.09、1 GHz、最差角（SS，−40°C，0.675 V）下综合，作者称没有时序退化。逐步加功能的路由器开销是：

原语：对着优化过的软件打

性能用 QuestaSim 2023.4 做周期精确 RTL 仿真。软件基线不是 naive 单播循环，而是带着硬件屏障和 DMA 的流水顺序组播 / 双缓冲树规约，并且按模型选最优分块。作者给出的公式与测得周期吻合。

  • 1D 组播：硬件相对最佳软件在 1–32 KiB 上快 2.3–3.2 倍。
  • 1D 规约：同样尺寸上快 2.0–3.0 倍。
  • 2D 规约：因为每路由器只合 2 路，第一列部分路由器要吃三路输入，32 KiB 时相对 1D 慢约 1.9 倍；但再增加行数，硬件时间几乎不变，软件则规模性很差。4×4 mesh 上 1–32 KiB 规约的几何平均加速为 2.8 倍。
  • 摘要中的 5.3 倍是组播（含 2D）的几何平均。

GEMM：通信一旦离开关键路径，倍数就消失

SUMMA：双缓冲后稳态时间是 max(T_comp, T_comm)，通信是对 A 的行组播加对 B 的列组播。假设簇 L1 里能放下的最大方形子问题（16 KiB）以及 98.1% 的计算利用率（来自他们另一篇 RTL 实测的中位数，已含 DMA 与计算争用）。硬件组播让内核在直到 256×256 的 mesh 上仍计算绑定；软件组播在 16×16 就已经通信绑定。加速范围 1.1–3.8 倍。

FusedConcatLinear：每个 cluster 算一个注意力头，最后沿 K 维规约才能融掉 concat 和线性层的出片访问。规约发生在计算之后，不和 DCA 抢同一拍 FPU。最高估得 2.4 倍。

能量来自把 0 号 tile 换成后仿网表、用 PrimeTime 在典型角（TT，25°C，0.75 V，1 GHz）抽活动因子，再按原语次数外推到整网。16×16 上的记账很能说明组播为什么省能量：SUMMA 的 DMA Store 从 983 降到 66（单位为 kB 传输计数）。计算仍然主导总能量，所以 256×256 上 SUMMA 也只到 1.17 倍；FusedConcatLinear 最高 1.13 倍，来源是少搬数据，以及核可以在 DCA 期间保持低功耗。

6. 落地意义

对做 AI 芯片 NoC 的人，本文最有用的不是「再快几倍」，而是把三条常常混在一起的事情拆开了。

第一，AI 流量的集合通信是突发、规则、软件可见的，和缓存一致性里那些任意目的地、短消息的组播不是同一个设计点。为了规模可以接受「只能打对齐子网格」这种编码，换来对数增长的头部开销和简单的 XY 树。

第二，网内算术规约之所以显得贵，常常是因为人们默认要在路由器里再造算术单元。DCA 的反驳是：算术单元已经在 tile 里，缺的是一条带背压和 tag 的卸载口。16.9% 的路由器开销、tile 级不到 1%，让「片上不该做 many-to-one」这句话至少在这个模板下不再是教条。

第三，加速能不能反映到内核上，有两个与内核无关的条件：通信是否在关键路径，模式能否映射成组播或规约。双缓冲内核只有在 T_comm > T_comp 时才吃得到组播的好处；规约若是加性项，则总会吃到，幅度取决于它占壁钟的比例。这比再发一篇「我们的 NoC 在某几个网络上延迟更低」更接近芯片团队真正要做的权衡。

和 Tenstorrent 的矩形广播、Cerebras 的 color 通道、Hopper 的 SM-to-SM / DSM 放在一起看，产业界已经从不同方向承认：AI 芯片的片上网络必须会做一对多和多对一，而不能只做 cache line 单播。本文的贡献是把这件事做成了可综合的开源实现，并且用软件对照把倍数钉在原语和 GEMM 模型上。

7. 局限

  • 大 mesh 上的 GEMM 与能量是模型估计，不是 256×256 的全系统 RTL 或硅上测量。通信模型在 4×4 量级的原语实验里对得很好，外推仍有风险。
  • 没有端到端网络或完整模型（GPT、MoE）的评估。作者引用文献称 GEMM 类算子可占推理时间的大约 42.8%–96.6%，因此「预期」会反映到端到端，但本文没做。
  • 宽规约每路由器 2 路，2D 规约会在部分节点掉到每 2 拍才出一个完全规约 beat。更大扇入或更不规则的 MoE 流量不在实验里。
  • DCA 与核的 FPU 请求会争用同一套算术单元；本文评的融合内核把规约放在计算之后，避开了争用。重叠通信与计算时，情况会更复杂，作者自己写了这一点。
  • multi-address 编码要求 2 的幂对齐子网格，任意目的地集合要拆事务。对稀疏专家分发是否仍然划算，本文没有直接实验。
  • 对比的是「同一套 NoC 上的优化软件集合」，不是和其他硬件组播 NoC（商用或学术）做头对头。和闭源芯片的优劣无法从本文读出。
