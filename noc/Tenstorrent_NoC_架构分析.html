1. 一句话结论

Tenstorrent 把整颗芯片——Tensix 计算 tile、GDDR、Ethernet、PCIe，在 Blackhole 上还有 L2CPU——都挂在同一套可编程的 2D torus NoC 上，核与核、核与存储、核与片外接口都走显式的读写/原子/广播事务，而不是先写进共享缓存再靠一致性协议扩散。每颗芯片有两张物理上独立、流向相反的 NoC；Blackhole 相对 Wormhole 把 flit 从 256 bit 加到 512 bit、时钟从 1 GHz 加到 1.35 GHz，地址从 36 bit 加到 64 bit。路由器到邻居每拍走 1 个 flit、延迟 9 拍。硬件保证常见单播和预约路径的广播无死锁，但链接虚通道、不预约的广播、提高仲裁优先级时，软件要自己保证不把网络卡死。这套设计的价值不在「又一个 mesh」，而在于它把 AI 负载里真正高频的权重/激活分发，做成了可以对准一个矩形、一次发出去的广播，并且把文档公开到了可以对照硅实现来写内核的程度。

2. 问题：AI 芯片上的通信本来就该是一等公民

GPU 上，一块激活要从一个 SM 走到另一个 SM，默认路径是 L1 → 片上互连 → L2（或再出 HBM）→ 再回来。编译器和内核作者能控制的是访问模式和缓存提示，改不了那一层互连的事务语义。Tenstorrent 走了另一条路：每个 Tensix tile 里的 baby RISC-V 通过 MMIO 发起 NoC 事务，数据从本 tile 的地址空间直接写到目标 tile 的 L1 或 GDDR。通信是指令流的一部分，不是缓存系统的副作用。

这对矩阵/张量数据流很重要。权重要广播给一整行或一整块计算 tile，激活要沿着另一维移动，规约或部分和要写回，MoE 的 dispatch 还要按专家矩形撒数据。如果每次都先变成单播再在软件里复制，链路上会留下大量重复 payload。文档里把「可选地广播到一个矩形」写成写事务和原子事务的一等选项，说明这件事在微结构里是先想好的，不是后来用软件树拼出来的。

同一张 NoC 还要服务完全不同的端点：计算 tile、GDDR tile、Ethernet、PCIe，以及空 tile（只有 router 和 NIU，地址空间里几乎只剩 CSR）。换句话说，片上网络不是「核与核的专网」，而是这颗芯片的系统总线。主机经 PCIe 进来的事务会被译成 AXI 再译成 NoC；软件应预期大于 128 字节的请求往往会拆成多笔 PCIe 事务——文档把这个限制写得很直白，避免有人以为 NoC 上的大消息会原样穿到主机。

3. 拓扑：两张方向相反的 2D torus

每张 NoC 是由路由器和 NIU 构成的 2D torus：左右、上下边互相接上。包从 NIU 发出，在路由器之间移动，在 NIU 终止。NoC #0 与 NoC #1 连接同一组 tile，但物理上分开，并且流向相反——通常把 NoC #0 画成向右、向下，把 NoC #1 画成向左、向上。两张网不是互为备份的影子通道，而是两套可以同时打满的物理链路；流向相反也让一对 tile 之间的往返不必在同一张单向 torus 上绕远路。

图 1. 双 2D torus 的流向示意。环回边表示 torus 而不是 mesh。本图是示意，不是原文插图。

Moreh 的系统说明把这一点落到芯片地面：所有 tile 之间的数据搬运——Tensix 到 Tensix、Tensix 到 GDDR、Tensix 到 Ethernet、甚至 GDDR 到 Ethernet——都走这张统一 NoC。Wormhole 被写成 10×12 网格，其中 80 个 Tensix、18 个 GDDR、16 个 Ethernet、1 个 PCIe、1 个 ARC，另有空位。NoC Router 0 负责 +X/+Y，Router 1 负责 −X/−Y，与官方「流向相反」的说法一致。

4. 事务、广播与虚通道

一笔 NoC 事务由一个或多个包组成；每个包恰好一个 header flit，后面最多 256 个 data flit。Blackhole 上每个 flit 固定 512 bit（64 字节）。事务类型并不复杂，但对 AI 数据流刚好够用：

Read / Write

从接收方地址空间读回一块连续数据，或把发起方数据/32-bit 立即数写过去。写可以 posted（不回 ACK），可以按任意子集写满 64 字节以内的数据，也可以广播到一个矩形。

Atomic

对接收方 L1 里 128 bit 做原子操作，32-bit 结果通常写回发起方 L1。同样可以 posted，也可以向一个矩形广播。计算侧同步不必先绕到存储器控制器。

矩形广播

矩形可以跨过任何种类的 tile，但每个 router 用 ROUTER_CFG_1/3 的坐标掩码决定是否把包交给本 tile 的 NIU。固件默认只让 Tensix 接收，DRAM / L2CPU / Ethernet / PCIe / 被harvest 的列被掩掉，避免广播写穿到 GDDR 或卡在已关钟的 tile 上。

非 posted 广播完成的判据很工程：回来多少个 ACK，软件就要数多少个。打开 NOC_CMD_PATH_RESERVE 时还有更严的规则——预约树还在飞行中，同一 NoC 上经过这些路由器的广播必须是这一笔。代价是数据要等树上所有路由器声明就绪才能离开发起 tile；失败则指数退避重试，广播延迟会上去。

虚通道

相邻路由器（或路由器与 NIU）之间，每个包占用一个 4 bit 虚通道号，过完该跳就释放（链接多包事务除外，它们在该跳上独占同一 VC 直到全部请求包走完）。4 bit 拆成：1 bit dateline（在路径上预定位置翻转，用来破 torus 环）、2 bit class、1 bit buddy。class 由硬件强制：

Class用途（文档原意）
0b00 / 0b01单播请求，两种 class 都可以用
0b10广播请求
0b11响应（即使在响应广播，响应本身也是单播）

buddy 位默认可按拥塞在每一跳改变；请求包也可以由软件锁成静态，换更强的排序、可能更高的延迟。默认排序偏弱，要更强的保证去看 Ordering 专章。RISC-V 经 MMIO 发起的事务相对内核是异步的，完成靠计数器或中断。

5. 性能数字

Blackhole README 给了一张很干净的性能表，单位是「每张 NoC」：

跳类型吞吐（每 NoC）延迟
NIU → 直接相连的路由器每拍 1 flit（512 bit）约 5 拍
路由器 → 邻居路由器每拍每轴 1 flit（512 bit）9 拍
路由器 → 直接相连的 NIU每拍 1 flit（512 bit）约 5 拍

拥塞会拉高延迟。若软件打开 NOC_CMD_VC_LINKED 或 NOC_CMD_VC_STATIC 来强制排序，即使链路上还有空带宽，包也可能被卡住等待。有效吞吐还取决于 header 与 data 的比：极短包可以用单个 header flit 带走 4 字节；极长包用 1 个 header + 256 个 data flit 带走 16384 字节。

相对 Wormhole，文档把 Blackhole 的升级总结为三点：时钟 1 GHz → 1.35 GHz，每拍带宽加倍（256 bit → 512 bit），地址 36 bit → 64 bit。同时写下一处回退：NOC_CMD_WR_INLINE 不再能安全地写 L1 地址。若按官方 flit 与时钟推算，单轴单向峰值是 32 B × 1 GHz = 32 GB/s（Wormhole，与 Moreh「32 bytes/cycle」一致）以及 64 B × 1.35 GHz = 86.4 GB/s（Blackhole）。芯片上有两张 NoC，且每个路由器有两个轴向，聚合算法因映射而异，文档没有给出「整芯片对剖带宽」这种单一广告数字，这里也不编一个。

6. 软件责任：死锁、排序、harvest

多数常见事务由硬件保证无死锁。文档点名三种要把部分责任交给软件的高级特性：

  • 一笔事务包含多个请求包（NOC_CMD_VC_LINKED）；
  • 广播但不做路径预约（不置 NOC_CMD_PATH_RESERVE）；
  • 仲裁优先级不是 0（NOC_CMD_ARB_PRIORITY）。

这是一种很务实的分工：默认路径给编译器和运行时一个「不容易卡死」的子集；要吞吐、要无预约的灵活广播、要插队，就自己证明安全。对做内核的人来说，这意味着不能把「硬件无死锁」理解成「任意组合的 flag 都安全」。

另一处几乎一定会被踩到的是收获（harvest）与关钟。固件会关掉熔断 Tensix 列的时钟；若某颗关钟的 tile 仍在广播矩形里且没有被掩码排除，广播会在那里停住：每个接收者只拿到部分数据，事务永远完不成——预约或不预约都一样。坐标翻译开启时，熔断列会被挪到翻译空间的末尾，但矩形仍是 NoC 坐标上的范围，跨过熔断列的矩形在硅上依旧覆盖那一列，真正让它安静的是掩码。软件如果改这些掩码，必须把 DRAM / L2CPU / Ethernet / PCIe / 熔断列继续挡住。

7. 落地意义

对做 AI 芯片或 GPU 片上互连的人，这套 NoC 提供了三条可对照的经验。

第一，把计算、近存、片外接口放进同一张可编程网络，比「计算阵列一张网、存储另一张总线」更容易做权重流式搬入和激活就近交换。代价是 GDDR 和 Ethernet 也成为 NoC 端点，广播默认必须被掩码保护，否则一次组播就能写穿存储。

第二，双物理网、流向相反，是在 torus 上同时要带宽、要往返短路径、要用 dateline 破环的一种具体解，不是概念图里的「再加一条 VC」。class 位把单播请求、广播请求和响应从硬件上分开，直接对应「不要让响应被请求堵住、不要让广播和单播抢同一类缓冲」这种老问题。

第三，矩形广播加路径预约，说明他们认同一件事：AI 流量里大量是规则的一对多，值得为矩形（而不是任意目的地集合）做硬件。任意集合可以拆成多个矩形或多次单播，这和 ETH Zurich 后来在集合通信 NoC 里用可扩展的 multi-address 编码，走的是同一类取舍——为了规模，先牺牲完全任意的目的地集合。

从软件看，MMIO 发起、计数器完成、弱排序默认、同步靠原子和计数，这更接近显式消息传递，而不是缓存一致性。编译器（TT-Metal 一类）必须把数据流编成事务序列，并决定用哪一张 NoC、要不要预约、要不要静态 VC。2026 年 Taylor 等人把数值核搬到 Wormhole 上的经验，也是在验证这条「空间计算 + 显式 NoC」能不能服务非神经网络负载。

8. 局限与文档没写清的地方

  • 这是架构与编程手册，不是带应用加速比的论文。文档不给出端到端 GEMM、注意力或 MoE 的 NoC 利用率，也没有功耗数字。
  • 「每拍 1 flit」是无拥塞的链路能力。实际有效带宽还取决于包长、排序开关、广播预约和热点（例如多核同时打同一个 GDDR tile）。
  • 路由算法的细节在 RoutingPaths 等子页，本笔记没有逐页展开所有路径与拥塞案例。
  • 片间互连走 Ethernet tile，机柜内再组成 mesh；那一层不是本 NoC。不要把 Galaxy 服务器里的 8×4 芯片阵列写成片上网络。
  • Moreh 文中的 tile 计数和字节/周期是理解布局的有用对照，但不是 Tenstorrent 签字的数据手册；若与 ISA 冲突，以 ISA 为准。
