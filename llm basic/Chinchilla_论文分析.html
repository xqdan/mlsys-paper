1. 一句话结论

给定训练 FLOP 预算，模型参数 N 与训练 token 数 D 应近似同比放大：模型翻倍，token 也翻倍。当时的 GPT-3、Gopher、Jurassic-1、MT-NLG 都大约只训了 300B token，相对自己的规模严重欠训。用 Gopher 同一笔算力训一个 70B、1.4T token 的 Chinchilla，全面超过 280B 的 Gopher，也超过更大的 175B–530B 模型，推理还便宜四倍。

与 Kaplan et al. 2020 的共识是：大模型不要训到最低损失才算算力最优，固定算力应提前停。分歧在停之前预算怎么分。Kaplan：算力 ×10，模型 ×5.5、token ×1.8。这里：两边都大约 ×√10。口号从“大模型比大数据重要”改成“高质量数据必须跟规模一起涨”。

2. 问题：固定 FLOP 怎么拆成 N 和 D

加速器数量和能跑多久通常事先已知，超大模型往往只能训一次，所以要在开训前选定 N 和 D。目标是：

Nopt(C), Dopt(C) = arg minN,D L(N, D)　s.t.　FLOPs(N, D) = C

他们用平滑后的训练损失当测试损失的无偏估计——因为所有缩放实验都不到一个 epoch（“无限数据”体制）。FLOP 按完整前向+反向计，包含嵌入，参数计数也含嵌入；大模型上嵌入占比很小。与 Kaplan 的 C≈6ND 相比，他们的精确计数只差几个百分点（表 A4 比值约 0.99–1.10），不改变结论。Gopher 用更精确算法约 6.3×1023 FLOP，文中投影仍常用 5.76×1023。

实验：400+ 个 dense Transformer，约 70M–16B 参数，5B–500B token，每种配置多个训练地平线。学习率余弦在目标步数上衰减 10×；周期比实际步数长超过 25% 会明显变差（附录 B）。因此 Kaplan 那种“所有模型共用收到 130B 的日程、再读中间点”会系统高估短训损失。

3. Kaplan 错在哪

作者认为差异主要来自实验设计，不是“幂律这个想法错了”。

学习率日程与中间点

Kaplan 对所有模型用固定 token 预算和同一套余弦。中间损失是“日程还对准更长地平线”时的损失，会高估短训效果，从而低估“少数据、把模型训完日程”的收益，推出 N 应比 D 涨得更快。

模型太小、前沿有弯曲

Kaplan 多数 run 远小于 100M；这里大多数 >500M，最大 16B。FLOP–损失前沿在高端有轻微凹性，用很小的模型外推会高估超大模型的最优规模。

在 1021 FLOP 上头对头：Kaplan 配方给出约 4.7B，Approach 1 给出约 2.8B；同深宽比下他们的预测终点损失更好（图 A4）。C4 与 GitHub 上的 IsoFLOP 得到几乎同一对指数（0.50/0.50 与 0.53/0.47），说明结论不太绑死 MassiveText，前提是仍不超过一个 epoch。

4. 三种估法，同一条前沿

1. 训练曲线包络

70M–10B，每个规模 4 个余弦周期（token 地平线差 16×）。平滑插值后，每个 FLOP 取最低损失的那条曲线，再对 N(C)、D(C) 拟合幂律。得到 a=0.50，b=0.50。选中点几乎都在训练最后 15%。

2. IsoFLOP 剖面

9 个固定 FLOP（6×1018–3×1021），改模型大小、令 token 使总 FLOP 恒定，余弦对准该预算。损失对 N 呈山谷，二次拟合找谷底。a=0.49，b=0.51。模型用到 16B。

3. 参数化损失

把 Approach 1+2 的终点损失拟合成 L̂(N,D)。Huber+L-BFGS，小 FLOP 点当离群。前沿 a=0.46，b=0.54，大算力时主张更小的模型。Gopher 预算被投到约 40B。

5. 参数化损失与约 20 token/参数

风险分解：贝叶斯风险（文本熵）+ 有限假设空间的函数逼近 + 单 epoch、有限步的优化次优。于是

L̂(N, D) = E + A / Nα + B / Dβ

经验拟合 E=1.69，A=406.4，B=410.7，α≈0.34，β≈0.28。两指数都低于常见 1/2 下界，作者认为更好的架构/优化应把它们抬上去。约束 FLOPs≈6ND 后，最优前沿是 log-log 直线，两项（容量项与数据项）被配平。

没有约 1026 FLOP（Gopher 的 250 倍以上），1T 参数模型几乎不可能算力最优。175B 应看约 4×1024 FLOP 和 4T+ token，而不是 300B token。

后来有工作指出 Chinchilla 的“参数”定义有几种读法（差到约 15%），三条方法的外推也不完全重合。但“同比放大、大约二十个 token 换一个参数”在扰动下仍然稳，已经成为训练配方的默认尺，而不是方法 3 里那组很紧的 α、β。

6. Chinchilla：70B × 1.4T

Gopher 预算下最优规模落在 40–70B。他们选区间上沿 70B、训 1.4T token：数据集效率与算力效率的折中（方法 3 更偏向 40B）。与 Gopher 同架构家族，关键差别：

  • 同一 MassiveText，采样略改以支撑更多 token；MassiveWeb 与 Wikipedia 超过 1 epoch（表 A1：Web 1.24 epoch，Wiki 3.40）。缩放律实验本身仍是单 epoch。
  • AdamW 替代 Adam：约在余弦 80% 处才反超，终点明显更好。
  • SentencePiece 不做 NFKC，94.15% token 与 Gopher 相同，数学/化学表示更好。
  • 前向 bfloat16，优化器里存 float32 权重副本（ZeRO）。
  • 70B：80 层，64 头，dmodel=8192，max LR 1e-4，batch 1.5M→3M token。Gopher 280B：80 层，128 头，dmodel=16384，max LR 4e-5，batch 3M→6M。两边都在中途把 batch 加倍。

训在 TPUv3/v4 + JAX/Haiku。更小模型让微调与推理的内存和算力大约降到 1/4，这才是“算力最优”的第二笔账：训练 FLOP 相同，但生命周期成本低得多。

7. 下游结果

评测对齐 Gopher（Rae et al. 2021）。语言建模上 The Pile 全部子集 bpb 都更好；WikiText-103 困惑度 7.16 vs 7.75。作者提醒 4× 数据可能有泄漏，所以更看重 MMLU、BIG-bench、闭卷 QA。

8. 局限、毒性与数据

  • 大尺度只有 Chinchilla 与 Gopher 一对对照，没有中间规模的第二次检验。
  • 前沿被写成幂律，但高端已有凹性，可能仍高估超大模型的最优 N。
  • 分析几乎全是单 epoch；多 epoch 体制留给后续。Chinchilla 自己已对部分子集走了多 epoch。
  • 无提示生成的 PerspectiveAPI 毒性与 Gopher 几乎相同（均值 0.087 vs 0.081）。更好的损失不等于更毒，也不等于更安全。
  • 万亿 token 会放大有毒文本、偏见和隐私泄漏的绝对量。作者强调下一步瓶颈是高质量数据收集与查重，而不是只堆参数。

MoE / 检索被放在相关工作里：路由模型的算力优势随稠密规模增大而减弱（Clark et al. 2022）；RETRO 一类检索相当于把“看见的 token”再放大约 10×，侧面支持“数据比原先以为的更重要”。

读这两篇时不要混用两条 D(N)。Kaplan 的 N0.74 是“再加大模型而不明显过拟合需要多少数据”；Chinchilla 的 ~20 token/参数是“这笔 FLOP 买最大下游能力时 N 和 D 怎么配”。前者允许数据涨得比模型慢；后者要求一起涨。GPT-3 之后那一代按前者配了 300B token，所以被这篇判定为欠训。

对系统/近存方向：Chinchilla 把瓶颈从“训练时的峰值算力”部分挪到“数据管道、重复使用、高质量语料”和“更小模型的推理带宽”。同算力下选 70B 而非 280B，激活、KV、权重搬运都按约 1/4 降，这比单纯把 Kaplan 的大模型再做近存更划算。
