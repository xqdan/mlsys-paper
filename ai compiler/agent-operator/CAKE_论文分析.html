1. 一句话结论与研究定位

GPU 内核智能体把编译器当黑盒，编程语言又不是为智能体设计的——专家内核掉在这条缝里。CAKE 的主张是：不要只改搜索算法，要改智能体所写的表示、以及环境回给它的证据。智能体写带类型、硬件决策写在明处的 CAKE IR；编译器在生成代码前返回能指出出错位置的正确性与性能诊断；反复出现的失败再变成新的验证规则、IR 原语、代价模型校准和可复用战术。环境本身也是演化对象。

2. 问题：语言与智能体各自进化

专家写高性能 GPU 内核时，脑子里有三样东西：工作负载的紧凑模型、显式硬件资源、以及内核之间可复用的规则。现有系统把这三样拆开了。

内核智能体把编译器当黑盒

提议、变异、排序都在进步，但环境只回编译错误、对错和端到端时延。一次崩溃不会指出违反了哪条同步或硬件契约；一个延迟数字也不会说明是哪次调度决策造成流水停顿。前沿工作负载一旦暴露缺失能力，信号不会随之增长。

语言也不是为智能体准备的

Tile 级 DSL（Triton、Helion、TileLang、cuTile）藏起 warp 专业化、屏障编排和存储层级放置——而这正是「专家内核」和「仅仅正确」的分界。低级 DSL（CuTe）给出控制，但要求布局代数，智能体一旦写错，错误既容易发生又难以定位。

图 1　论文开篇的缝：Tile DSL 对智能体友好但藏硬件；CUDA/CuTe 暴露硬件但难诊断。CAKE 要填的是「可写专家调度、可在编译前分析、失败可沉淀」这一格。

编译器里其实已经有把这套专家过程从默会知识变成可检查对象所需的大部分机制：结构化操作词汇、资源模型、合法性检查、静态分析、代价模型、lowering 规则。CAKE 问的不是「再做一个更好的变异算子」，而是：如何让智能体用得上这些机制，以及当前沿工作负载暴露缺口时，如何把它们继续改进。

3. 三个承诺：IR、诊断、环境可演化

系统有两条入口，对应内核工作真实到来的两种方式：从 FlashInfer / CUTLASS 一类生产内核继续演化；或者从高层描述 / Triton 干净起步（不看专家实现、只看规格），由智能体在 CAKE IR 里选择 warp 专业化、布局和流水结构。

① 写类型化 IR，不写裸 CUDA

硬件决策在代码生成前可检查。调度声明「发生什么」，lowering 推导屏障地址、相位位、TMEM 偏移、描述符编码和 warp 身份。

② 能指出出错位置的诊断，不是只返回通过或失败

廉价分析在消耗 GPU 时间之前过滤候选。发现绑定到受影响的资源、角色或流水阶段，而不是后端报错或挂起。

③ Harness 本身是演化对象

反复失败变成验证规则、校准任务或新原语，由内核回归测试卡住。CAKE IR 自底向上从生产内核集合里由智能体发现抽象；人只决定合不合入。

第三个承诺才是这篇论文真正的机制贡献。KernelBlaster 积累 CUDA 知识库，KernelEvolve / AVO 演化搜索过程，CUDA Agent 演化模型权重——它们都保留既定 DSL 和评测环境。CAKE 改的是被搜索的表示，以及回给智能体的结构化编译器证据。

4. CAKE IR：显式机器调度，不做布局代数

CAKE IR 记录机器该如何被驱动：哪些 warp 承担哪些角色、缓冲分几级暂存、哪道屏障门控哪次交接、哪种指令形态消耗哪个操作数。程序由显式操作、声明资源、warp 角色、网格与流水配置组成。

4.1 真正起作用的四条性质

性质含义对智能体的后果
类型检查词汇 计算、访存、同步、数学、warp 控制用固定 IR 词汇，不嵌 C / PTX 非法组合在构造期被拒绝，而不是跑到 GPU 上才崩
声明式资源 存储区、同步状态、流水线声明一次；IR 知道每个缓冲的形状、dtype、生命周期 分析可以指向「哪块 smem / 哪条 pipeline」
显式角色 warp group 命名；跨角色交接全部可见，不是隐式约定 生产者–消费者错误可定位到角色对，而不是「某个 barrier 挂了」
自动推导元数据 屏障地址、相位、TMEM 偏移、warp 身份由 lowering 计算 智能体写调度意图，不写地址、相位这类程序性簿记；簿记错不再是搜索噪声

4.2 故意不把布局做成一等对象

CuTe 的布局代数、Triton 在 F2 上的 linear layouts、Axe 的命名轴，都把布局做成显式代数对象。CAKE 走相反方向：智能体写下具体承诺——SMEM 视图偏移、操作数字节偏移、TMEM 列范围、swizzle 标签、TMA 描述符坐标——由编译器判定这些承诺是否合法、是否沿数据流互相一致。

这不是「布局不重要」，而是把布局正确性从智能体必须操作的语言挪到编译器必须检查的契约。诊断指向相关 IR 决策和一个宽的失配类别。新原语可以扩展验证覆盖，而不强迫智能体再学一门布局语言。 
@cake.schedule()
def fmha_fwd(lm, Q: LM.tma3d, O: LM.tma2d, seqlen_q: LM.i32):
    # 声明资源：命名区域，不是裸地址
    pool = lm.smem(98304)
    smem_q = pool.view(offset=0, shape=(128,128), dtype=lm.bf16, stage=3)
    tmem_acc = lm.tmem(cols=0, width=128, shape=(128,128), dtype=lm.f32)

    # 声明角色：warp group 与工作分配
    load = lm.role(warps=[0])
    mma  = lm.role(warps=[1])
    pipe = lm.pipeline(stages=3)
    q_full = lm.barrier(count=3, prod=[load], cons=[mma],
                       init_count=1, pipeline=pipe)

    with load:
        for stage in lm.range(0, 3):
            smem_q.tma_load(Q, coords=(0,0,stage), stage=stage, barrier=q_full)
    with mma:
        for stage in lm.range(0, 3):
            lm.wait(q_full, stage=stage)
            lm.fence_proxy()
            lm.mma(tmem_acc, smem_q[stage], smem_q[stage], init=(stage == 0))

图 3 对应的调度片段：资源与角色被声明；生产者–消费者交接是显式屏障；地址、相位、warp 身份由 lowering 推导。

4.4 架构覆盖：结构可移植，指令能否用则因目标而异

同一套角色–屏障–流水语言覆盖 Ampere 到 Blackwell。结构可移植，指令准入和 lowering 按目标分化。编译器要求精确目标匹配，不支持就显式报告，不静默降级到另一架构。时序模型只在有校准的目标上给估计：B200 是实测基线，H100 独立校准，其余目标报告覆盖限制而不继承估计。

5. Harness：廉价分析过滤候选

Harness 是 CAKE IR 外围、面向智能体的环境。人给高层分析意图，智能体在验证约束下实现、维护、精炼。内核演化期间，廉价分析在昂贵 GPU 运行之前排序并过滤候选。

类别处置目的
程序安全编译前拦截同步、排序、内存使用危害
硬件符合性编译前拦截支持的资源、指令、架构契约
数据一致性编译前拦截数据流与生产者–消费者表示兼容
调度语义编译前拦截已声明调度的结构不变量
数值验证运行时关卡与权威外部参考比较输出
性能分析报告估计代价并标识宽的瓶颈类别
优化指引提示建议有希望的修订，不阻塞编译
对外接口是契约，不是内部 pass 列表：卡住的检查会指出是哪一处、哪一类问题；报告描述可能的性能上限；提示建议可以做、但不拦编译的优化。静态分析只在其建模范围内充当编译前拦截，不证明整卡程序一定正确，也覆盖不了全部微架构行为。误报和漏报都会有；片上实测和 profiler 仍是最终依据。

6. 双重演化：内核内环 × 编译器外环

这是系统图（论文 Figure 1 / Figure 4）真正要表达的：内核演化消耗结构化编译器证据；编译器演化是外环。

图 2　双重回路。内环消耗结构化证据以演化内核；外环把反复失败沉淀为编译器知识。两条编译器路径互相耦合：新原语暴露更多硬件事实，新分析反过来约束未来原语的设计空间。

6.1 编译器演化的两条路径

  • 自顶向下（内核集驱动）。智能体检查生产内核和硬件文档，发现缺失的 Blackwell 模式——新指令形态、资源类型、描述符变体、同步写法——再对照八条原则提案。
  • 自底向上（失败驱动）。不透明运行时崩溃变成验证规则；反复非法 lowering 变成静态检查；系统性误预测变成校准目标。

原语与分析必须一起演化：没有效应和合法性规则的语法会让 IR 更难分析；没有内核集验证的新规则会把本来合法的内核误杀掉。

6.2 IR 抽象发现过程（附录 A）

  1. 从 FlashInfer、CUTLASS、DeepGEMM、FlashAttention-4、Alpha-MoE 等收集高质量 CUDA 内核；其他 DSL 先由智能体译成带内联 PTX 的 CUDA。
  2. 抽取反复出现的调度：屏障编排、流水分级、warp 角色划分、TMA 描述符、TMEM 累加器生命周期。
  3. 人把抽象往 Blackwell 编程模型上收：TMEM 作为一等资源、warp 专业化作为主并行方式、异步屏障作为同步原语、cluster 范围操作用于多 SM 协调。
  4. 对照八条原则验证；违规则精炼或拒绝。
  5. 持续移植新内核：成功则验证抽象，失败则暴露缺口并扩展 IR 或 lowering。

7. Agent 工作流与实验协议

外部工作负载约定是不变的权威：形状、对照实现、容差、硬件、允许看的参考。一次运行四步：生成结构不同的 CAKE IR 候选；用 IR 构造检查、验证器硬关卡、代价模型排序过滤；活下来的对照外部参考做基准和 profiler；再按诊断把证据送到候选、验证器、代价模型或 IR 词汇。

7.2 测量口径

  • 全部：片上正确性检查 + CUPTI 计时，B200，每次计时样本前冲洗 L2。
  • 干净起步对照：固定编码智能体、scaffold、模型与推理强度、任务陈述、正确性 oracle、基准 harness、单一目标形状。
  • 报告提供者 token 消耗和主动演化时间。摘要用中位 [最小, 最大]。

8. 评测主结果

评测问三个问题：harness 能否驱动反复干净起步越过调优基线；CAKE 能否在没有低层实现参考时合成前沿内核；它能否对照 SOTA 基线复现专家内核。

8.1 Flash-KMeans 干净起步（核心对照）

Flash-KMeans 是精确 k-means，动机来自 Sparse VideoGen2 的语义感知 token 置换。一次 Lloyd 迭代由两个 BF16 内核主导（超过端到端时间的 95%）：assign（计算到全部 K 质心的平方欧氏距离并 arg-min）和 centroid_update（按簇归约 token 为和与计数）。两者画像不同：assign 是计算受限的 BF16 GEMM-归约，centroid_update 对带宽和原子争用敏感。实验聚焦 assign，在 B=32, N=65,536, K=1024, D=128、BF16 输入、FP32 累加器上锻炼张量核流水和标量 epilogue。性能相对调优 FlashML KMeans Triton 实现归一化，该实现测得 0.938 ms。

表示80M token 内平台期主动演化（小时）80M 时最优
CAKE IR 3/3 1.89 [1.02, 2.33] 1.144× [1.041, 1.205]
直接 CUDA/PTX 0/3 3.73 [3.59, 4.34] 0.928× [0.852, 1.151]

轨迹（论文 Figure 5）：CAKE IR 均值在 5500 万 token 越过调优 FlashML 基线并继续改善；直接 CUDA/PTX 均值在 8000 万截止时仍低于基线。中位主动演化时间 1.89 对 3.73 小时——更快，且最终更高。

CUDA/PTX 臂的最大值到过 1.151×，与 CAKE 中位接近，但 3/3 未达平台期、中位仍低于基线。结论不是「CUDA 写不出快内核」，而是：同样模型和 scaffold 下，结构化表示让越过调优基线这件事可重复。

8.2 前沿内核合成

这里的「前沿」是操作定义：智能体必须在不检查低层目标实现的情况下发现物理调度。已有实现仍可作为黑盒评测基线。共演化 IR 在这个体制下最该帮忙——搜索无法锚定到已知好设计；harness 也最暴露——缺失能力会表现为智能体根本写不出的调度。

工作负载体制数字落地
Kimi Delta Attention prefill 干净起步；FlashKDA 仅作黑盒计时 六档 B200 BF16 形状上几何均值 2.05×；bitwise 正确；SGLang 上 Kimi-K3 端到端验证 FlashInfer PR #4262
KDA decode 独立 decode 路径 30 个公开 API 形状上相对上游 FlashInfer 几何均值 1.14× FlashInfer PR #4279
Gated DeltaNet prefill + speculative-decode 提升性能同时保留模型循环状态 调度家族，非单内核
MiniMax 稀疏注意力 prefill + decode 同一表示支撑稀疏注意力家族 多种物理调度挂在一个逻辑入口后
TinyGEMM 从 FlashInfer 的 TRT-LLM 派生小 M BF16 内核继续演化 35 个规范形状上内核时间几何均值降 18–23%；GPT-OSS greedy 保持 bitwise 相同；SGLang GPT-OSS-120B 并发 128、TP1 输出吞吐最高 +7.6%，TP4 在测量噪声内 FlashInfer PR #4274
Alpha-MoE W8A8 Hopper 实现改写到 Blackwell 相对 FlashInfer 预路由 API：N=256 时 API 级 6.204×、N=512 时 4.025×；GPU-span 重测为 1.215× / 1.170× FlashInfer PR #4287
KDA 为何是好测试。它不像「GEMM + epilogue」：循环状态必须跨 chunk 保持存活，直接考验调度表示能否表达跨阶段存活的状态。生成的 CUDA 进了 FlashInfer，下游用户不依赖 CAKE。

Alpha-MoE 的两个数字不要混用。API 级 4–6× 主要来自 launch/schedule 融合和更简单的 workspace：参考发射 5 个 GPU activity，Alpha-MoE 一次复位加一个 megakernel。GPU-span 1.17–1.22× 才隔离有效 GPU 执行的改善。附录 D.3 的 1.137× 几何均值是相对「第一个正确 CAKE 检查点」的内部演化度量，不是对 TensorRT-LLM 的比较。

8.3 已知内核复现

对照 TensorRT-LLM、CUTLASS、DeepGEMM、FlashAttention-4、FlashInfer 的 LLM 关键路径。十一个已测固定比较中，十条达到或超过所列参考，剩余一条达到参考的 96.5%。最强是两个 MQA indexer，约 1.27×。全部通过内核特定正确性门，使用中位 CUPTI GPU span。

两件事决定这些数字该怎么读：

  • 低于参考的变体，一般反映编译器集成成熟度，不是换了算法目标：内核想要的特性还在往编译器和代码生成器里接，提交物用最接近的已支持策略。
  • 最强 indexer 赢面不是忠实转录。移植时智能体探索了原实现没有的优化，保留通过正确性和基准的变体。超基准条目反映搜索，而不只是转录保真。

行数只是描述性的，不是跨语言生产率或可读性度量。每份 CAKE IR 都短于审计的参考设备核心，但语言和计数范围不同。它只说明：被评测的硬件调度可以在 CAKE IR 里紧凑表示，同时保留分析和 lowering 所需的决策。

8.4 内核组合

验证集含 400+ 静态与编译用例、399 个 GPU 正确性用例，约 28 个家族：注意力、稠密与稀疏 GEMM、MoE、量化、归一化、状态空间模型、KNN、KMeans，含 Ampere 到 Blackwell 的架构特定路径。超过 100 个 TensorRT-LLM 移植覆盖注意力、MLA decode 和 MoE。

组合性是这批内核的另一条区分性质。角色、屏障、缓冲被声明而非暗示，通常会拆成多个内核的调度可以写成一个设备程序：BatchAttention 把 decode 和 prefill 合在一起；Alpha-MoE / mega-MoE 融合路由、专家计算和输出累加，不写出中间结果。

9. 从单 shape 到库：dispatcher 阶段

前面优化的是一个形状。库接受调用者传入的任意形状。补上这个缺口不是把内环在更多形状上再跑一遍；它是目标、排序信号、失败模式都不同的单独阶段，CAKE 也把它当单独阶段。

分开的目标

精确形状给内环一个明确的对比基准，允许放手做特化。用覆盖面给这个环打分，信号会被冲掉。泛化只在已经有强的逐形状种子之后开始，按「含分发器、固定工作负载」上的性能打分。不正确或慢的种子退回内环，而不是藏在路由后面。

构建并验证组合

把测得的种子分到形状桶，产生特化或共享变体，在显式回退之后排列守卫。调优可以改实现参数，不能改输入形状。报告聚合之前，验证覆盖代表与留出输入、边界与尾部、重叠或缺失守卫、以及回退路径。

防止评测泄漏

有效形状域在调优前声明。分发器谓词可以划分该域，但不能额外塞进方便的新评测行。覆盖通过同一来源的确定性未见分片扩展。这阻止分发器在用来声称泛化的集合上被调优。

一条策略限制泛化的实际成本：尽可能在形状域上复用单一物理调度，只有域要求实质性调度变化时才引入另一条。路由复杂度必须由测得的工作负载收益证明。每条路由是独立的 CAKE IR 程序，替代方案可独立分析和基准。

10. 相关工作、局限与对近存内核生成的含义

10.1 在文献里站哪一格

谱系代表CAKE 的差异
GPU 编程系统 Triton、Helion、TileLang、cuTile、CuTe、Gluon 与智能体共设计 IR：细粒度控制、无布局演算、IR 随不可表达模式一起长
编译器分析与调度 TVM、XLA、MLIR、TensorIR、Ansor、MetaSchedule、Graphene、Twill、Tawa 共享「结构化程序使分析有用」；把编译器发现放进智能体演化环，并让反复内核证据演化 harness
内核智能体 KernelBench、KernelBlaster、KernelEvolve、EvoEngineer、AVO、K-Search、AutoTriton、CUDA Agent 那些方法演化搜索、记忆或权重，保留既定 DSL 与环境；CAKE 改表示和回传证据
演化系统 FunSearch、AlphaEvolve、ADAS、Darwin Gödel Machine、Meta-Harness、self-defining systems 被演化的对象不同：编码智能体和基础模型固定，反复内核证据驱动领域编译器环境的变化，受内核集测试和事先约定的合入关卡约束

10.2 作者自己写下的局限

  • 非 NVIDIA 未测。调度语言、角色模型、分析基础可从 Ampere 带到 Blackwell；指令形态、合法性规则、代价锚点仍随架构变。这是迁移成本的老实说法。非 NVIDIA 还要重建后端 lowering。
  • 覆盖不均。多数性能证据在 B200；时序模型只对 B200 和 H100 校准，别处拒绝预测。
  • 静态分析与性能模型故意不完整。演化期间排序和过滤，GPU 执行仍是真相。
  • 编译器演化在合并门仍由人引导。智能体提案，人决定合不合。

10.3 引用这些数字时要注意的口径

  • 干净起步 1.144× 是中位、单形状、80M token 预算、相对 FlashML Triton；不是库级几何均值。
  • KDA 2.05× 是六形状几何均值、相对官方 FlashKDA 黑盒；decode 1.14× 是另一条路径、另一组形状。
  • Alpha-MoE 的 6× / 4× 是 API 级（含 launch 融合）；1.22× / 1.17× 是 GPU-span；1.137× 是相对自身第一正确检查点。
  • KNN/KMeans 1.42–2.12× 是 GB200 上 dispatcher-inclusive 的 Gspan，不能直接和 B200 单形状 Flash-KMeans 对照相减。
  • 已知内核表是固定比较矩阵；重跑改数值，不改被检验的主张。低于参考的条目优先读成编译器缺口，而不是算法失败。

10.4 对近存 / 同封装推理芯片的含义

这篇论文的对象是 NVIDIA GPU 内核，不是 3D-DRAM 近存。但它处理的结构问题，与同封装近存张量模块上的内核生成是同一类：

  1. 表示要比后端更显式。近存侧真正决定性能的是：数据驻留哪一层、哪段计算不下中央裸片、键值头如何映射到模块、归约落在星型节点还是模块互连。若智能体只写「通用 GEMM + Softmax」，这些决策会消失在 lowering 里，诊断也回不到决策点。CAKE 的角色–资源–屏障模型，可以直接改写成近存模块角色、本地缓冲、封装内链路交接。
  2. 布局不要做成智能体必须操作的代数。近存地址映射、bank 交错、通过硅通孔的通道放置，若做成 CuTe 式布局代数，智能体错误会既频繁又难定位。更稳的是：智能体写下具体承诺（哪块权重分片、哪段 KV 分区、哪次部分和上送），编译器检查契约。
  3. 单 shape 演化与库级分发必须拆开。专利稿里的预填充双侧投影、第一译码模式（完整键值头映射）、第二译码模式（上下文分片 + 中央合并 Softmax 统计量），本身就是按 shape / 映射制度切换的调度家族。CAKE 第 6 节给出的纪律——先有强种子、再按「含分发器」的性能打分、谓词不得发明评测行——可以直接搬到近存运行时。
  4. 环境要能长。近存指令集、TMEM 类累加器、模块间归约原语都会随芯片迭代变。把反复失败沉淀为验证规则和新原语，比每次手写一套 CUDA-PIM 模板更接近可维护的编译器路径。合并门仍应留在人手里。
  5. 不要期望 GPU 上的 1.14× 直接变成近存上的 1.14×。CAKE 的收益来自「同一硅上、同一张量核契约下，更好的调度发现」。近存芯片的主收益来自数据不移动。两者正交：CAKE 类 harness 可以帮助发现近存侧该写哪类内核，但不能替代「权重与 KV 驻留近存、历史 KV 不上封装内链路」这条架构主张。
若要把 CAKE 的方法用到同封装近存芯片，最小可行移植不是「在近存上跑 CAKE IR」，而是：定义一套声明式资源（模块本地 DRAM 区、近存逻辑上的矩阵/向量通路、封装内激活通道、中央归约缓冲），配上编译前检查（键值不得上链路、扩展维中间激活不得回中央、第一/第二译码模式的映射不变量），再让智能体在这套 IR 里搜索调度。GPU 后端可以先继续作为对照，近存 lowering 作为第二个目标。
