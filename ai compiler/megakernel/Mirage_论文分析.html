1. 一句话结论与研究定位

现有张量编译器把「代数变换」和「调度变换」拆成两条河：TASO / PET 只在算子图上换等价算法，Halide / TVM / Triton 只在给定算法上搜 schedule。FlashAttention 这类核同时改算法、改核边界、改并行维度——两条河都搜不到。Mirage 的主张是：用一张分层图把 GPU 的 kernel / thread block / thread 三级写成同一套 μGraph，然后在这张图上做超优化，顺带发明新的自定义核。

这篇论文本身不是 megakernel 运行时。它解决的是「单个（或一小簇）自定义核怎么自动生成」。后续 MPK 把 Mirage 生成的 SM 级任务塞进一张 persistent mega-kernel；Event Tensor 再给这张任务图加上动态 shape 与数据依赖。读 megakernel 线，Mirage 是代码生成底座。

2. 两类编译器各自漏掉什么

今天的 DNN 框架把计算写成张量程序：DAG 的节点是 matmul、conv 这类代数算子，边是张量。落地到 GPU 有两条自动化路线，都还要人先指定「有哪些核」。

调度路线（Halide / TVM / Ansor / Triton）

算法固定，搜 tiling、并行、流水。漏掉的是：同一份数学可以换成完全不同的算子分解，以及「把标准核拆开、只融合其中一部分」这种新核。

代数路线（TASO / Grappler / Tensat / PET）

在算子图上做等价替换、融合、重排。漏掉的是：每个算子的实现仍是人手写的库核，跨 kernel / block / thread 的协同调度不在搜索空间里。

FlashAttention 同时做三件事：算法层重排（代数）、把计算重新切成新核（发明自定义核）、按 GPU 层级改并行策略（调度）。Triton 上手写 FlashAttention-2 要 700+ 行。Mirage 要自动搜出这类 μGraph，并验证它和原程序等价。

图 1 · 两条河各自只搜一半。FlashAttention 同时改算法、核边界和并行轴，只有 μGraph 把三件事放进同一搜索空间。

论文的搜索空间比 TASO / PET 大一个数量级：后者只在 kernel 级、固定核集合上搜；Mirage 同时搜三级，并且允许生成 graph-defined 新核。这迫使它发明剪枝和概率验证，否则搜不动。

3. μGraph：核 / block / thread 同一套图

GPU 计算按 SPMD 组织：一个 kernel 是一整个 GPU 上的函数；kernel 里是 grid of thread blocks，每个 block 跑在一颗 SM 上，线程共享 shared memory；每条线程有私有寄存器。输入输出都在 device memory。μGraph 把这三级写成嵌套图。

图 2 · μGraph 与 GPU 存储层次一一对应。graph-defined 核是「发明新核」的入口。

分区语义：imap / omap / fmap

这三张映射把调度空间写进图里，而不是写进另一套 schedule 语言。

映射作用对象语义
imap block 图的每个输入 grid 维 → 张量某一维（均分）或副本维 φ（复制）
omap block 图的每个输出 grid 维必须映射到数据维；各 block 的输出沿该维拼接
fmap for-loop 的 input iterator 循环维 → 数据维或 φ，控制每轮从 HBM 装哪一块到 shared memory

图 3 · 论文 Figure 4 的分区语义。imap 决定哪个 block 拿到哪一块；fmap 决定 for-loop 每一轮从 HBM 搬哪一片。φ 表示复制而非切开。

for-loop body 用 accumulator（求和 / max）把多轮中间结果攒在 shared memory，循环结束后再做后处理（例如求平均时除以 n）。合法 μGraph 还要求：每条从输入到输出的路径恰好经过一个 iterator、一个 accumulator、一个 saver；各级张量装得进对应存储。

与 Welder / ASPEN 的 tile-graph 对比：那些工作主要做调度。μGraph 同时表示代数变换（换算子、换结合顺序）和调度（grid / for-loop / 布局），并且允许生成标准库里没有的 graph-defined 核。论文里的多数加速都落在这第三类。

4. 案例：RMSNorm + MatMul 如何被融进一核

RMSNorm 是近年 LLM 的标配归一化。它后面几乎总跟着一次线性层：

Yij = Xij Gj / RMS(Xi),   RMS(Xi) = √( (1/d) Σj Xij² )

两次 reduction 卡在不同维上，现有编译器通常打两个核，中间结果 Y 必须落 device memory。Mirage 搜到的最优 μGraph 做了四件现有系统不会一起做的事：

  1. 利用 matmul 与逐元素除法的交换律，把 RMSNorm 的除法挪到 MatMul 之后（代数）。
  2. 把 RMS 的累加 Σ X² 和 MatMul 的累加 Σ XGW 放在同一个 for-loop 里并行跑（调度），避免把累加结果写回 HBM。
  3. 把 Mul / Sqrt / Div 融进一张 thread 图，中间量只活在寄存器里（调度）。
  4. 整段计算变成一个 graph-defined 新核（发明核），省掉 launch 和 Y 的物化。

图 4 · RMSNorm+MatMul。左边两次核、Y 落 HBM；右边一张自定义核里并行累加，后处理只走寄存器。

相对手写核：A100 上 1.5×，H100 上 1.9×。单独做代数或单独做调度都到不了这张图。

5. 搜索：抽象表达式剪枝

完整搜三级会爆炸。Mirage 用两条策略压空间。

混合生成

kernel 和 block 级穷举（到给定算子个数上限）；thread 级只用规则融合。理由：HBM / shared memory 比寄存器贵几个数量级，性能关键决策在上两级。生成时只产出 canonical form（算子按 rank 递增），避免同构图重复。

抽象表达式

每条边对应一个「忽略同张量元素差异」的一阶逻辑项。例如 Matmul(X,Y) 的抽象是 sum(k, mul(E(X), E(Y)))，行和与列和会撞成同一个表达式，但保留 reduction 长度 k——这对剪枝至关重要。

剪枝规则：若前缀的抽象表达式不是输入程序抽象表达式的「子表达式」（在公理集 Aeq ∪ Asub 下），就丢掉。直觉：搜 X·Z + Y·Z 时，X·Y 剪掉，X+Y 留下，因为 (X+Y)·Z 等价。

图 5 · 抽象表达式解决「还没搜到完整图，怎么判断前缀有没有用」。子表达式测试在抽象里做，避免鸡生蛋。

定理 1：若某等价 μGraph 的抽象表达式在 Aeq 下等于输入，则它不会被剪掉。Aeq 故意不含消去律（如 div(mul(x,y),y)=x），否则「一切都是一切的子表达式」，剪枝失效。这是最优性与可搜性之间的显式折中。评测里这个折中够用：RMSNorm 需要 block 图 11 个算子，关掉抽象剪枝后 6 个算子就要搜超过 10 小时。

6. 验证：有限域上的概率等价

张量可以有上百万元素，穷举对拍不可行。Mirage 把候选限制在 LAX 片段：多线性算子 + 除法 + 指数，且每条输入到输出路径上指数最多一次。LAX 覆盖 matmul / conv / 归一化 / 激活里常见的那一段，也是概率验证能给出理论保证的条件。

LAX 程序每个输出元素可写成「多项式 × 指数」的分式。把多项式恒等测试（PIT）推广到这类式子，需要两个有限域：素数 p 管指数外，素数 q | (p−1) 管指数内，并用 Zp 中的 q 次单位根实现 exp。

非等价 μGraph 通过一次随机测试的概率 ≤ 8 d k⁴ / q + q−1 / k²

重复测试可以把误接受率压到任意 δ。实现上用能塞进 16-bit 的最大 p、q（p=227, q=113）在 GPU 上跑，目前只做一次随机测试；作者称实践中没见过假阳性，计划只对最终最优图做完整理论保证的多轮测试。浮点溢出另用一次浮点对拍过滤。

非 LAX（如 ReLU）走另一条求解器验证：用户给算子的一阶性质，再用定理证明器推等价。这条路径更通，但每个新算子要手写公理。

7. 后处理：布局、调度、内存规划

这三项不影响正确性，所以放在验证之后，避免搜索时把「同一拓扑、不同布局」当成不同候选。

布局 ILP

每个张量每个候选布局一个布尔变量。cuBLAS 等库核带来线性约束。代价函数刻画 bulk copy 能否走。Z3 求最优组合。

算子调度

按「到任意输入的最长路径」标 depth，升序执行，使 block 内 __syncthreads 次数最少。

内存规划

三级中间张量的偏移做成动态存储分配，穷举找最优。

GQA、bs=1、A100 上逐项关掉：thread 图构造 −18%，布局 −60%，调度 −70%，内存规划 −5%。布局和同步次数不是装饰。

8. 评测主结果

基准全是 LAX 子图，对应真实模型里的热路径。对比 TASO/PET、FlashAttention / FlashDecoding、TensorRT / TensorRT-LLM、PyTorch（torch.compile + FA）、Triton。半精度，CUDA Graphs 开着。

基准来源模型Mirage 做了什么相对最强基线
GQA LLaMA-3-70B 自动搜 grid 维（吃满 108/132 SM）；按场景在 sample / KV-head / Q-seq / KV-seq 里选并行轴；HBM 访问最多降 7× 最高 2.2×
QKNorm Chameleon-7B 把 Q/K 的 LayerNorm 融进 attention 自定义核，中间不落 HBM 最高 1.4×
RMSNorm LLaMA-2-7B 见第 4 节，单核融合 A100 最高 3.2×，H100 1.9×
LoRA GPT-3-7B-LoRA 代数恒等式把三次 MatMul 收成两次 block 级 MatMul，Concat 只改 shared memory 偏移 1.1–2.4×
GatedMLP Falcon-7B 两次 MatMul 在同一 block 图并行，SiLU 与逐元乘做 post-processing A100 1.5×，H100 2.7–3.3×
nTrans nGPT-1B 三次 Norm 融进一核。仍慢于 TensorRT：轻计算核被「每张量都进 shared memory」拖累 相对 TensorRT 约 0.3–0.4×

端到端把 Mirage 核插进 PyTorch：Chameleon-7B 最高 1.9×，LLaMA-3-8B / nGPT-1B 约 1.4×，LoRA 模型 0.9–1.2×。搜索一次性、最长约 4 小时。

关于 GQA：TensorRT-LLM 在 bs=1/8 用 grid (8,2,1) / (8,2,8)，吃不满 A100/H100 的 SM。把 Mirage 最优图强行换成同一 grid，性能掉 18%。FlashAttention 固定沿 sample/head/query 并行，FlashDecoding 沿 sample/head/KV-seq——对头数很少的 GQA 都不是最优。Mirage 按 shape 换 μGraph。

9. 局限、与 megakernel 线的关系

这篇论文不解决什么

  • 不是端到端 mega-kernel。输出仍是一串（更少、更好的）CUDA 核。核间屏障、launch、跨算子流水仍在。
  • LAX 边界。超优化主路径要求线性 + 除法 + 至多一次指数。ReLU 等走求解器，公理要手写。
  • 轻计算核。nTrans 暴露了「凡事进 shared memory」的税。作者计划支持绕过 shared memory 的加载路径。
  • 搜索预算。kernel 图最多 5 个算子、block 图最多 11 个。更大子图要先人工切 LAX 片段。

在 megakernel 文件夹里它扮演什么角色

MPK 把算子切成 SM 级任务后，每个任务的 CUDA device function 仍要人写或编译器生成。MPK 明确写：compute task 交给 Mirage 超优化器搜 thread-block 图再降到 CUDA。没有 Mirage，MPK 只是一个调度壳。

反过来，Mirage 单独部署已经能在「仍用 kernel-per-operator」的世界里拿到 1.5–3×。megakernel 要解决的是 Mirage 刻意留在图外的那一层：跨核流水、细粒度算通重叠、动态 shape 下一张 persistent kernel 打天下。

图 7 · 同目录四篇的分工。Mirage 停在「更好的核」；后面三篇把核边界拆掉，分别补动态、补 chiplet。

可带走的判断：张量编译的下一个搜索空间不是「再多一种 schedule 原语」，而是「允许发明新核，并且核的内部结构与图级代数写在同一套 IR 里」。μGraph 是这个判断的具体化。后续 Event Tensor 把「事件」也做成张量，走的是同一条「把并行原语升成一等 IR」的路。
