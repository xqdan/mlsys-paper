1. 一句话结论与研究定位

CUDA/HIP 的执行层次仍是 thread → wavefront → workgroup → grid，按单片 GPU、统一 L2 设计。MI300/MI350 是 8 个 XCD、每 die 私有 4 MB 非一致 L2；Blackwell 是 2 die、L2 分区。编程模型看不到 chiplet，LLM decode 这种访存型负载就会把同一行权重从 HBM 搬进多个 L2。Fleet 加了一层 Chiplet-task：活和数据绑到一颗 die 的 L2 上，persistent kernel 里按 die 调度。

Fleet 不是从零写 mega-kernel 运行时。它扩展 Mirage Persistent Kernel：在 AMD MI350 上加上 chiplet 感知和分层同步。Mirage 决定融什么，Fleet 决定调度到哪颗 die。评测只有 Qwen3-8B 稠密、单卡 MI350，没有 Blackwell 实测。

2. Chiplet 把 L2 从「设备范围」撕开

单片 GPU 上任意 CU 访问 L2 延迟带宽相同，程序员不用想数据缓存在哪。Chiplet 之后，封装内出现了以前只在多卡之间才有的 NUMA。

Chiplet / XCDL2—Chiplet-task

MI350：8 XCD × 32 CU = 256 CU，每 XCD 私有 4 MB L2（合计 32 MB），共享 256 MB Infinity Cache（L2 的 victim），HBM3 > 5 TB/s，288 GB。HBM 是统一地址空间，任意 die 都能访问任意 stack。默认 load/store 是 wave scope（SC1=SC0=NT=0）：L2 把数据当成本 XCD 私有，不发跨 XCD 探针。XCD i 的脏数据要让 XCD j 看见，生产者必须 buffer_wbl2，消费者必须作废过期行。device/system scope 会走一致性协议，延迟更高。

对 LLM decode 的后果：默认指令加载的权重在每个 XCD 的 L2 里各缓存一份。两个不同 die 上的 CU 读同一行权重，HBM（或 LLC）要供两次。Qwen3-8B 每层权重 368 MB（bf16），均分到 8 XCD 仍是 46 MB，远超 4 MB L2。线性层占 decode 时间 95%，attention 5%；无合作调度时 bs=1 的 L2 hit 只有 16.4%。再叠加每 token ~250 次 kernel launch、核边界冲刷 L2——这就是为什么要 persistent + chiplet 感知。

CUDA/HIP Graph 减 launch，但按 batch 各捕获一张图，节点仍是核粒度顺序执行，核边界冲 L2。persistent mega-kernel 只 launch 一次，L2 状态跨算子保留。这是 MPK 已经讲过的；Fleet 加的是「保留在哪一颗 L2 里」。

图 1 · MI350 把 L2 撕成 8 份互不共享的 4 MB。无感知调度等于同一份权重买 8 次 HBM 带宽。

3. 四级任务：缺的那一层叫 Chiplet-task

设计原则：任务写在与算子资源需求匹配的硬件粒度上。

Wavefront-task

单 wave（AMD 上 64 线程），寄存器 + LDS。SiLU、残差加、RoPE、逐元乘。

CU-task

单 workgroup，LDS + L2。单个 attention head、RMSNorm、argmax/sampling。

Chiplet-task

一颗 XCD 上全部 worker（MI350：32 CU 里 31 个，1 个给 scheduler），显式 L2 预算。GEMM 把权重切成 cache-friendly 片。

Device-task

8 个 Chiplet-task 集体完成一个算子。屏障语义：8 个都完成才算完。各 XCD 按 stride 写共享输出缓冲，就地拼接，不必 reduction；若沿 K 切（split-K），完成后再做一次归约。

依赖用 event 表达。Chiplet-task 把一颗 die 上的 worker 收成一个单元，每条依赖边每 die 只需一个 event，而不是每 worker 一个。跨 chiplet 同步事件数降 W 倍（W = 每 die worker 数）。

一层 Transformer、bs=1：无感知分解把每个 GEMM 拆成 96–256 个 CU-task，共 1407 个任务；Fleet 每个 GEMM 8 个 Chiplet-task，SiLU 融进 gate+up，共 543 个（2.6× 更少）。

图 2 · 论文 Figure 4(a)。Chiplet-task 把「每 CU 一个 GEMM 切片」收成「每 die 一个合作任务」，同步事件数降 W 倍。

4. 合作 tiling：M-major 把 miss 变成 hit

线性层 GEMM 按输出列切给 8 个 Chiplet-task：每个算独立的 [M, K]×[K, N/8]。Qwen3-8B 的 gate-up 每 XCD 仍是 24 MB，塞不进 4 MB L2。关键是窗口化的 M-major 遍历（灵感来自 HipKittens）：同一 Chiplet-task 内，worker 先把某一列权重 [0:K, n] 配上各行激活算完，再换下一列。并发 worker 在短时间窗口里读同一列权重——第一个从 HBM 装进 L2，后面的 hit。

图 3 · 论文 Figure 2。左边同 die 的人在打不同矩阵，L2 被踩乱；右边每 die 认领权重的 1/8 列，合作只发生在本地 4 MB L2 里。

L2 Hitweight = 1 − 1 / min(W, m_tiles)    其中 m_tiles = ⌈B / TM⌉

图 4 · 同一 Chiplet-task 内的遍历阶。色调表示权重列；N-major 让并发 worker 踩不同列。

两条对照策略：

  • M-tile：8 个 XCD 拿到同一组 M-tile，XCD 内先扫 M 再换权重列。这是合作复用。
  • M-split：每个 XCD 分到不相交的 M-tile，无合作共享。用来把「Chiplet-task 调度」和「L2 合作 tiling」拆开。

bs=1 时模型预测权重复用为零，实测仍有 16.9% hit——来自融合 SiLU：gate 和 up 拼成一张 [W_gate; W_up]，两半共享激活读取。不融合时 bs=1 掉到 ~9%。

三级 cache modifier

  1. 权重 load：streaming（sc1=1, nt=1）。每块权重只用一次，允许短窗口复用后立刻可逐。合作 M-tile 的 hit 发生在逐出之前。
  2. 激活 store：NT=1，绕过 L2，避免 GEMM 输出 / RMSNorm / SiLU 挤掉正在合作使用的权重。
  3. 调度通信：跨 XCD 轮询用 NT load 读 HBM 新值；XCD 内走 volatile、共享 L2。

把 SiLU 融进 gate+up 的 Chiplet-task，bs=1 的 L2 hit 从 9.4% 到 17.4%。融进 CU-task 也能从 8.1% 到 16.5%——收益来自消灭中间缓冲，不只来自 XCD 协同。

N-split（按输出列切 XCD，无跨 die 同步）和 K-split（workgroup 内沿 K 切、LDS 归约）互补：小 batch 调度开销是瓶颈，N-split + 合作 L2 赢；bs≥32 进入 compute-bound，K-split + 自动调 tile 更重要。Fleet 的 persistent GEMM 还没做后者，所以大 batch 会被 hipBLASLt 追上。

5. 分层同步：fence 摊到每 XCD 一次

单片 GPU 上 device-scope 原子便宜，一致性流量留在一片 L2。MI350 上一次 device-scope 原子要跨 8 个 L2 分区，走 die 间 fabric；buffer_wbl2 按脏行数缩放，拖死后继访存。Fleet 按「够正确的最窄 scope」分层：

  1. 任务队列只读。mega-kernel launch 前填好，执行中不变，无需同步。
  2. Scheduler → worker。写本 XCD 的 per-worker 队列，device-scope store/atomic 在本地 L2 完成。
  3. Worker → worker。Chiplet-task 内用 XCD 本地计数器累加完成数，同一 L2，不必 fence。
  4. XCD → 全局。每 XCD 最后一个完成的 worker 才发一次 threadfence + GPU-scope atomic（flat_atomic_add sc0 sc1）。跨 die 一致性成本按 XCD 摊，不是按 worker 摊。全局计数到阈值后，把 event 入队给负责的 scheduler。

Chiplet-task 的两级计数：每 event 每 XCD 至多一次 fence；该 event 没有任务的 XCD 零次。线性 event 恰好 8 个 task（每 XCD 一个），总共恰好 8 次 fence。Wavefront/CU-task 只有一个 worker，直接 GPU-scope atomic，不必两级。

图 5 · 论文 Figure 5。die 内原子走本地 L2；跨 die 的昂贵 fence 摊到「每 XCD 最后一个 worker」一次，而不是每 worker 一次。

6. 运行时：每 die 一个 scheduler

一颗 HIP kernel 占满全部 CU。每 XCD 一个 workgroup 当 scheduler（读 HW_ID 认自己是哪颗 die），其余当 worker。MI350 上 8/256 CU（3.1%）不做计算。Scheduler 只做计数读取、队列写入、指针算术，与 worker 执行重叠；短任务时调度开销可能露出来。

Chiplet-task：scheduler 向本 die 全部 worker 广播同一任务，worker 按 stride tile 合作、共享 L2。CU-task / wavefront-task：在本 die 的 CU 上 round-robin。任务队列和 event 计数在 HBM，自然缓存在 XCD 本地 L2；die 内通信借共享 L2 隐式一致，不必 global acquire/release。

代码生成：目前给 Mirage 编译器换一套带 Chiplet-task 节点的输入，不走超优化。每个 GEMM 变成 8 个 Chiplet-task；tile 指针在代码生成时算好（base + k × (N/8) × K × sizeof(bf16)）。核内不必判断自己是哪个 Chiplet-task，只读当前 tile 指针。调用改成 _execute_xcd_task(tile_idx)，库代码按 tile 下标区分 CU 行为。

7. 评测：调度税 vs L2 复用

单卡 MI350X。模型 Qwen3-8B 稠密 bf16。基线：(1) 移植到 MI350 的 Mirage MPK，分层调度但无 chiplet 感知、无合作；(2) vLLM 0.17.2 ROCm，--enforce-eager。64 输入 + 1024 输出，decode TPOT 用核内 s_memrealtime，不含 prefill。GEMM tile 16×64×256 CK，权重 streaming load。

小 batch：几乎全是调度

无感知 MPK 已比 vLLM 快 1.34×（7.83 vs 10.51 ms）——persistent 去掉 launch。Fleet 再收到 6.82 / 6.73 ms（M-tile / M-split），相对 vLLM 1.54–1.56×。bs=1–16 时 m_tiles=1，没有合作复用，两变体几乎一样，相对 Mirage 1.13–1.16×。L2 hit 都在 16–24%，HBM 读几乎相同。收益来自每个 GEMM 8 次 broadcast 而不是 96–256 次 CU 级 dispatch。

bs=32：M-tile 1.27× vs Mirage，M-split 只有 1.17×（和调度-only 一致）。HBM：M-tile 3190 GB vs Mirage 3906 GB（−18%），M-split 无下降。bs=64：四 worker 共享每列，M-tile 1.30×、HBM −37%；M-split 掉到 1.03×，几乎回到 Mirage。Roofline 上 bs=32 的有效算术强度从 32 移到 65 FLOP/byte（AI_eff = B / (1 − L2 hit)）。

bs≥32 时 vLLM 靠 hipBLASLt 的 wave 级 K-split 把延迟打平到 ~11–12 ms。Fleet M-tile 在 bs=32 仍快 1.06×，bs=64 已经更慢——persistent GEMM 还没有 compute-bound 区的 K-split 和 attention 优化。

每 GEMM 的 per-XCD 分区都大于 4 MB L2，但合作 tiling 让活跃工作集保持在「每 worker 一个 K-chunk」量级（约 31 × 32 KB ≈ 1 MB），所以 M-major 在分区超 L2 最多 6× 时仍有高 hit。整层 368 MB 塞不进 256 MB MALL，单 GEMM 的窗口可以。

8. 局限、与 MPK 的关系

评测范围

  • 一个模型（Qwen3-8B 稠密）、一颗 GPU（MI350）。无多卡、无 prefill、无需要 TP 才能放下的模型。
  • 无 Blackwell 数据。抽象按 (X, W, C) 参数化，声称同一任务图能适应 MI300X / MI350，Blackwell 需要平台后端。
  • vLLM 基线开了 --enforce-eager，即没有 HIP Graph。这会放大 persistent 相对「按核 launch」的优势；和论文里批评 Graph 的段落放在一起读，口径并不对称。

Mega-kernel 的寄存器税

所有 task 类型编进同一个 GPU 函数，寄存器取并集，占用落到每 SIMD 单 wave，没有 wave 切换藏延迟。L2 miss 直接堵 MFMA，所以 hit rate 比普通核更致命。按 task 分别编译能减寄存器，但会丢掉单 launch。作者把这视为 mega-kernel 的固有折中；RDNA 式动态寄存器分配可能缓解。

和张量并行的组合

TP 先在多卡间切 N，Fleet 再在单卡内切。TP=4 会让 per-XCD 片变小，可能掉到 L2 容量以下，合作 dispatch 不再必要。两级切分正交，同步路径不交叉。多卡评测留作未来。

和同目录另外三篇的关系：Mirage 搜单个 task 的实现；MPK 在统一 L2 的 NVIDIA GPU 上把 task 图跑成 persistent kernel；Event Tensor 解决动态 shape 与 MoE 路由；Fleet 解决的是 MPK 默认假设已经被 chiplet 打破的那一层存储层次。NVIDIA 侧若只把 MPK 原样搬到 Blackwell，会遇到同一类「分区 L2 上看不见 locality」的问题，只是 die 数是 2 而不是 8。
