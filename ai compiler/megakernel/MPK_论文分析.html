1. 一句话结论与研究定位

现有 serving 系统（vLLM、SGLang）一个算子一个 kernel，核间有隐式屏障。PDL 能部分重叠，但要改核结构；CUDA Graph 能省 launch，但图是静态的。MPK 声称自己是第一套把多 GPU 模型推理自动变成一颗高性能 mega-kernel 的编译器 + 运行时：依赖画在 SM 级 tGraph 上，调度发生在核里面。

用户接口是 torch.compile(backend=MPK)。实现约 44K C++、42K CUDA、10K Python。计算任务用 Mirage 超优化生成 CUDA，通信走 NVSHMEM。手写 mega-kernel（FlashDMoE、HazyResearch 的 LLaMA-1B）证明这条路有性能，MPK 要证明它可以编译出来。

2. kernel-per-operator 卡住的三件事

核屏障杀跨算子流水

同 stream 上后核要等前核全部线程结束。TMA / Tensor Core / CUDA Core 的 intra-task 流水可以做，task 边界上会留 pipeline bubble。PDL 能部分重叠，但要改控制流。

依赖太粗，算通叠不上

MatMul 后面 AllGather / AllReduce 时，通信其实只依赖对应 tile。整核屏障让 AllGather 等到整个 MatMul 结束。细粒度重叠需要 SM 之间的子核同步。

成百上千次 launch

CUDA Graph 能把 launch 从 ~3.8 μs 压到 ~0.8 μs，但图绑死 shape 和控制流。连续批、变长、MoE 路由都要重捕获。

mega-kernel = 一次 launch 打完整模型（含层计算和卡间通信）。好处对应上面三件事：零重复 launch、跨算子 prefetch、tile 级算通重叠。难点是生态碎片——NCCL / NVSHMEM、FlashInfer / FlashAttention、CUDA / Triton 各管一段，很难塞进同一颗核。

3. tGraph：依赖下沉到 SM

tGraph 的节点是两类：task（一颗 SM 上的计算或通信）和 event（跨 task 的同步）。边交替出现：task 只连到它触发的 event，event 只连到依赖它的 task。task 在全部依赖 event 激活后才能跑；跑完通知触发 event。event 收齐通知后激活。

经典例子：MatMul → AllReduce。AllReduce 是逐元素的，每个 AR task 只依赖对应那一块 MM tile。tGraph 在这对 tile 之间插细粒度 event，于是有的 SM 还在做 MM，有的 SM 已经开始 AR。若 event 只捕获算子级依赖，tGraph 就退化成 CUDA Graph。

图 2 · 同一份 MatMul→AllReduce。左边一个 event 等价于核屏障；右边每个 tile 对一个 event，计算和通信在不同 SM 上重叠。

和 CUDA Graph 的关系：结构相似（静态实例化、显式依赖），粒度不同。CUDA Graph 描述 kernel 发射顺序，重叠停在核边界。tGraph 显式建模算子内和算子间的 SM 级依赖，同步走 device memory 原语，全部发生在一颗 persistent kernel 里。

4. 编译器：分解、融合、规范化、线性化

输入是计算图 + 推理配置（batch、GPU 型号）。输出是针对该配置特化的 tGraph，外加每个 task 的 CUDA device function。

  1. 算子分解。按输出张量切 task。默认切分数与 SM 数成比例以均衡负载。启发式：最小化 HBM→shared memory 的装载量。用户可指定各输出维的并行度。
  2. 依赖分析。两算子共享张量时，枚举 task 对；输出区域与输入区域相交就插一个 event。保留全部生产-消费依赖，独立 task 可并行。
  3. Event 融合。后继集相同（同一组消费者）→ successor-set fusion；前驱集相同（同一组生产者）→ predecessor-set fusion。Qwen3-8B：162k 对依赖收成 2366 个 event（68×）；MoE 因 many-to-many 路由，融合达 118×。
  4. 规范化。每个 task 至多依赖 1 个、触发 1 个 event。多扇出/扇入时插入空 task 和中间 event。真实 LLM 图「深而不宽」，评测里 fork/join 组为 0，开销 <1%；有并行分支（未融合的 Q/K/V）时仍需要它来保证定长描述符。
  5. 线性化。BFS：同一 event 触发的 task 在数组里连续，扇出只需存 first/last 下标。device 上后继编码降 4.4–15×（MoE 最高，因为高扇出路由 event 特别吃范围编码）。

线性化后每个 task 只存两个 event id；每个 event 存激活计数 + 任务下标范围。这是核内调度能用原子加法在环形缓冲上跑起来的前提。

Task 实现：block 级超优化，不是 kernel 级。每个 compute task 有一份 PyTorch 参考实现，交给 Mirage 搜 thread-block 图再降 CUDA（软件流水、寄存器复用、bank conflict 布局）。手写核可以包成统一 calling convention 的 device function，和编译生成的 task 走同一套事件调度。

图 3 · 编译器把任意扇入扇出收成定长描述符。规范化用空 task 拆多扇出；线性化让同一 event 的消费者在数组里连续。

5. 核内运行时：worker / scheduler

一颗 mega-kernel 占满 GPU，一直跑到这次推理结束。SM 在 launch 时固定分成 worker 和 scheduler，核内不切换角色。

GPUSM 数WorkerScheduler warp
A10010810416（4 SM × 4 warp）
H10013212816
B20014814416

Worker：每颗 SM 一个任务队列，FIFO 取 task → 算/传 → 通知触发 event。Scheduler：每颗调度 SM 上 4 个 warp，各维护 event 队列，轮询已激活 event，把对应 task 派给 worker。队列是 device memory 里的环形缓冲，入队出队只有 atomicAdd。调度是去中心的：每个 scheduler 用局部状态派活，没有全局锁。

事件驱动还有一个附带好处：同一套 tGraph 能吃异构互连。通信和计算都是 task，谁先触发 event 谁先放行下游。快链路早完成就早放计算，慢链路只拖依赖它的那部分。调度器不需要 NVLink / 跨节点带宽的静态画像。

图 4 · persistent mega-kernel 把 GPU 切成调度器和工人。调度器看 event 队列，工人看 task 队列；通信和计算是同一种 task。

6. JIT 与 AOT 混合发射

JIT：依赖满足后再入队

worker → scheduler → worker 两跳同步。优点：attention 这种耗时随序列长度变的算子，先做完的 SM 可以多接下游 MM / AR，动态均衡。缺点：每 task 发射延迟更高。

AOT：预先入队，本地等 event

只需一跳（event 触发）。延迟低，但静态绑定，不均衡时 SM 空转。适合耗时可预测的算子。

编译期按算子打标签：耗时数据依赖的（attention）标 JIT，其下游保持 JIT，直到碰到「必须被全部上游触发」的全局屏障——屏障会抹掉累积不均衡，之后改回 AOT。同一算子的全部 task 共享发射模式。Worker 有两条队列，永远优先 JIT；JIT 空了再看队首 AOT 的 event 是否已激活。AOT task 在执行前 round-robin 预分配，减轻 scheduler 负担。

7. 分页共享内存与跨任务流水

常规模型里 shared memory 随 kernel 生灭，一核独占。mega-kernel 要在同一颗 SM 上流水「当前 task 计算」和「下一 task 装数据」，两 task 会同时要 shared memory。

MPK 把 shared memory 切成固定页（评测里 32 KB；A100 每 SM 5 页，H100/B200 每 SM 7 页）。Task 按足迹申请页，用完释放；一旦释放过，就不许再申请——单调用法简化调度。当前 task 放出页，立刻可以给下一 task 做 prefetch。

跨任务流水：每个 task 拆成 preload 和 compute。当 (1) 当前 task 已发完自己的数据搬运，且 (2) 有足够页给下一 task 的 preload，就把两者重叠。SM 内插入必要屏障，避免两套搬运打架。Qwen3-8B 最后一层线性：开流水比不开快 1.2–1.3×，甚至超过 cuBLAS 编译核。

另外，task 描述符 352 字节，队列在 HBM；runtime 把即将执行的描述符预取进 shared memory。

图 6 · 核屏障让跨 task prefetch 做不成，因为下一核还没 launch。分页让当前 task 计算和下一个 task 装数同时占同一颗 SM 的 shared memory。

8. 评测：单卡、MoE、多卡、消融

离线批推理，prompt 64、生成 1024，batch 1–16。模型：Qwen3-0.6B / 1.7B / 8B、Llama-3.2-1B、Qwen3-30B-A3B（MoE）。基线：PyTorch、vLLM、SGLang，都开 paged attention 和 continuous batching。关键差异：MPK 把 page 分配和请求调度做进 mega-kernel；vLLM / SGLang 这些在 CPU 上做，带来 host–device 同步。

端到端

单 batch 相对最强基线 1.0–1.7×。增益在小模型和新型号上更大——计算变少、硬件变快之后，三笔开销相对变大：核切换（即便有 CUDA Graph）、流水 bubble、CPU 侧调度。Qwen3-8B A100：14.5 ms → 12.5 ms / token，16 GB 权重按 1.6 TB/s 估的下界约 10 ms。相对原生 PyTorch 超过 10×。

动态性怎么接

连续批和 paged attention：start event 上跑一个 task，踢掉已完成请求、准入新请求、更新 KV 元数据（元数据放 device memory，attention task 直接读）。动态 batch：按 2 的幂预编译多张 tGraph，runtime 按当前 batch 选一张。这不是 Event Tensor 那种符号 shape 一张图走天下，是「代表性 shape 特化 + 运行时切换」。

MoE

路由 / dispatch / expert 计算 / combine 都是同一 tGraph 里的 task，all-to-all 和计算由同一事件调度器重叠。两点 MoE 特化：

  • 混合负载均衡。编译期按 expert 切 task；runtime 用 topk-softmax 的 meta-tensor（每 expert 的 token 数）动态改切分。纯静态在倾斜路由下会饿死 SM，全动态 Grouped-GEMM 同步太碎。
  • 融合 gather-GEMM。Hopper/Blackwell 上 TMA 要连续布局，单独 gather 在 SGLang、bs=1 可占 MoE 时间的 11%。MPK 把异步 token 级拷贝塞进 GEMM 的数据加载阶段。

B200 上 Qwen3-30B-A3B 的 MoE 段，Hybrid 相对 SGLang 约 1.07–1.18×。

多卡

用户在 attention 和 gated MLP 后插 AllReduce。MPK 把集合通信拆成 NVSHMEM nvshmem_signal_wait_until 的传数 task 和本地 reduction task，同步集合变异步 task。8×H100 上 Qwen3-1.7B TP：相对 PyTorch 最高 10×，相对 vLLM/SGLang 1.1–1.4×。细粒度算通重叠本身贡献约 1.1× per-iteration。

9. 局限与和 Event Tensor / Fleet 的分工

资源占用的常见误解

「一颗 mega-kernel 必须在每颗 SM 上预留所有融合算子的资源总和」——MPK 用时间复用避免这一点：SM 只持有当前 task 的资源；shared memory 按页申请释放。例外是寄存器：整颗 mega-kernel 的寄存器用量取所有 task 类型的最大值。这和 Fleet 观察到的「单 wave / SIMD、L2 miss 直接堵 MFMA」是同一类税。

动态 shape 仍是特化多图

按 2 的幂生成多张 tGraph，runtime 选图。这能跑连续批，但 warmup / 编译次数随 shape 集合涨。Event Tensor 论文点名这条限制：MPK（以及 Spector 的手写 mega-kernel）对动态 shape 和数据依赖控制流缺乏一等抽象，往往要按 shape 重编译。

评测口径

  • 离线批、固定 prompt 64 / 输出 1024，去掉了在线到达造成的空转。这有利于突出 GPU 效率，不反映调度器在真实 trace 上的行为。
  • 大 batch / 大模型上加速收敛到 1.0–1.1×：计算占满之后，去掉 launch 和 bubble 的相对收益变小。
  • bs≥64 的 compute-bound 区，Fleet 在 AMD 上已经看到 persistent GEMM 尚未做 K-split，会被 hipBLASLt 反超。NVIDIA 侧同类风险同样存在。
分工可以记成三句话。Mirage 发明单个 task 的 CUDA；MPK 把 task 图编译进一颗 persistent kernel，并给出去中心事件运行时；Event Tensor 把 event 升成带符号 shape 的张量 IR，一张图覆盖动态 batch 和 MoE 路由；Fleet 在 MPK 运行时上加 Chiplet-task，把调度对齐到多 die 的私有 L2。MPK 是这条线上第一篇「自动 mega-kernelize」的系统论文。
