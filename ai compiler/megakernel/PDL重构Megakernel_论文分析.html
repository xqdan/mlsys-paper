2. 被拆解的对象：Hazy Megakernel

Hazy Research 2025 年 5 月的博文 Look Ma, No Bubbles! 针对 Llama-3.2-1B、batch=1 解码：这是强访存绑定负载，理论上限由权重加载带宽决定。他们测到 vLLM / SGLang 在 H100 上最多只用到约 50% 带宽，根因是一次前向被拆成约一百个小核，中间出现三类「内存流水线气泡」：

  1. Grid 排空等待。后继 CTA 必须等前驱全部 CTA 退出。例如 down projection 有 512 个 CTA、B200 只有 148 个 SM，尾部会空出大量 SM。
  2. Launch / teardown。CUDA Graph 把 CPU 提交压到约 1.3 μs，但 GPU 侧仍有空转。
  3. 权重加载无法跨核重叠。即使有 PDL，他们当时认为 cudaGridDependencySynchronize 太粗：必须等整个 QKV 完成才能开 attention，而非常驻解释器那种「头一就绪就开」。

Hazy 的解法是把整次前向熔进一颗 megakernel，并用三套机制填气泡：

片上解释器

每 SM 预先拿到一串指令（RMSNorm+QKV+RoPE、attention、O-proj、up/gate+SiLU、down-proj、LM head）。Python 侧静态排程，可复用数百次前向。

SMEM 分页

H100 前 213 KB 共享内存切成 13 个 16 KiB 页。指令显式申请/释放，解释器把释放页立刻交给下一条指令去发 TMA。

计数器同步

全局计数器代替核边界。MLP 把 8192 维中间激活分成 4 块，down projection 只等自己那块，不必等整个 up/gate。

结果：H100 上一次 16-bit 1B+ 前向低于 1 ms、约 78% 带宽；相对当时 SGLang 约 1.5×、相对 vLLM 约 2.5×。B200 推到 680 μs 以下。这就是 Qiang 等人要拆开的「持久化神话」——优势到底来自常驻，还是来自解释器内部那套重叠调度。

Hazy 原文其实已经点名 PDL，并认为它不够细。Qiang 的工作不是否定这一点，而是量化：网格级 PDL 已经能追回绝大部分；Hazy 强调的 tile 级计数器，在拆开后的普通核链上反而变慢（见第 8 节 VTP）。

3. 核心问题与实验设计

工程笔记的反问题写得很清楚：

Megakernel 的性能有多少来自「持久化本身」（常驻 CTA、片上分配器、指令派发），有多少可以通过更好的调度，在普通 CUDA 核链上复现？

控制变量

  • 保留：原始 ThunderKittens 算子体——同样的 GEMV、TMA、共享内存流水、规约、BF16 输出；同样的模型几何（16 层 Llama-3.2-1B）。
  • 去掉：常驻解释器、片上 SMEM 分配器、运行时 opcode 派发、跨算子计数器。
  • 唯一差异：CUDA Graph 边语义。默认依赖 = 等前驱 grid 全部完成；PDL 依赖 = 前驱触发后即可准入后继。

每层 5 条活跃指令（opcode 3 在该 decode 日程中关闭），16 层共 80 个 Transformer 节点，加上 LM head 为第 81 核：

1  RMSNorm + QKV projection + RoPE / KV append
2  attention
4  output projection
5  RMSNorm + up/gate projection + SiLU
6  down projection
   -> 下一层 opcode 1
   最后 + LM head  =  81 个核、80 条图边

工作负载与计时契约

  • 单卡 H100 SXM5 80 GB，无张量并行；驱动 590.48.01，功耗墙 700 W，未锁频。
  • P32/D128：32 token 提示，生成 128 token；prefill 产出第一个 token，计时 127 次前向（位置 32–158）。
  • 完整 decode 步包含 embedding、barrier 复位、模型图、argmax、token 写出。
  • Persistent / PDL：三个新进程 × 3 warmup × 10 次计时生成。默认依赖链是同一契约下的单进程对照（190 μs 效应远大于进程间亚微秒抖动，但未做三次重复）。
  • SGLang v0.5.15.post1 用另一套环境（PyTorch 2.11 + CUDA 13），计时是扣基线后的服务端请求 E2E，不能与前三行严格横比。
  • 报告延迟时关闭 timeline / profiler / 设备端计时，避免探针污染。

正确性：确定性单步 token 检查通过；位置 32 / 95 / 158 的中间张量做 graph-vs-eager 校验。自由跑的 128-token 轨迹不做 bit-exact 神谕——两边都用原子加规约，低裕量 argmax 会改后续 token。没有靠放松精度换性能。

4. 记分牌：97.4% 从哪来

头条数字来自真实权重、匹配作用域的完整 decode 步（embedding → 模型 → argmax → 写出），不是合成权重、也不是只比 Transformer 主体。

实现 端到端延迟 相对持久化 计时范围
Persistent VM 983.127 μs 基准 进程内 decode 步
81-kernel PDL 链 1009.711 μs +2.704% 同上，同二进制只改图边
81-kernel 默认依赖链 1169.071 μs +18.9% 同上（单进程对照）
SGLang v0.5.15.post1 1210.353 μs 不可直接比 服务端请求 E2E

吞吐口径：983.127 / 1009.711 ≈ 97.36%，笔记四舍五入为 97.4%。相对默认依赖链，PDL 追回了 (1169.071 − 1009.711) / (1169.071 − 983.127) ≈ 85.7% 的端到端缺口。

匹配作用域分解：损失全在 80 核主体

作用域 Direct-TK PDL Persistent native 差值
16 层 Transformer 主体 809.626 μs 777.123 μs +32.503 μs
主体 + LM head 976.711 μs 946.086 μs +30.625 μs
完整 decode 步 1009.711 μs 983.127 μs +26.584 μs

LM head 增量上，拆开路径反而快 1.877 μs；embedding + argmax + 写出再快 4.041 μs。这两段优势把主体的 32.503 μs 亏空缩小到端到端 26.584 μs。结论：剩余差距是 80 个独立 grid 累积出来的结构成本，不是 LM head、argmax，也不是少写了最后一条 PDL 边。

早期有一版把 native 路径用 eager launch、拆开路径用 per-position CUDA Graph，会低估结构差距。最终对照把 native 也捕获成每位置一张图；同一次三进程里，native 一图一步比 native eager 再快 3.227 μs（983.127 vs 986.354）。

5. 内核边界如何挖出 190 μs 空洞

两边都已经用 CUDA Graph，整步一次提交，CPU launch 不是主因。合成权重 / 匹配主体对照里：默认依赖拆开主体 967.162 μs，配对持久化主体 776.942 μs，空洞 190.220 μs。笔记把它拆成四类硬件侧开销，在约 80 条内部边界上累积：

开销 含义
Grid 准入与排空 CTA 逐 SM 调度进去；结束时必须等所有 CTA 退出。拖尾 CTA 让大量 SM 空转。
CTA / 屏障初始化 每个核重新配寄存器、mbarrier、共享内存与 warp 角色，无法跨核继承。
常驻状态丢失 加载器 warp、SMEM 缓冲、片上分配器在核结束时全部销毁，下一核从头申请。
跨算子权重重叠消失 持久化可在指令 i 还在算时就加载 i+1 的权重；默认依赖要求前驱 grid 彻底结束后才能发后继 TMA。

占比最大、也最可被 PDL 修复的是第四项。前三项才是「持久化本身」的地盘。分析策略因此很干净：先用 PDL 把重叠调度接回去，看还能剩多少；剩下来的才归因给常驻。

6. PDL 两行代码与触发时机

NVIDIA 从计算能力 9.0（Hopper）起提供 Programmatic Dependent Launch：同一 CUDA stream 上，后继核可以在前驱尚未完成时启动，去做与前驱结果无关的前导工作（清缓冲、加载常量/权重），再在真正读前驱输出处同步。CUDA Graph 里把边类型写成 cudaGraphDependencyTypeProgrammatic 即可。官方提醒：重叠是机会性的，不能当成正确性保证；后继必须自己 cudaGridDependencySynchronize（或等价可见性手段），否则可能读到未刷新数据，甚至死锁。 

// 生产者：独立访存发出之后立刻放行，不必等 TMA 到达
cudaTriggerProgrammaticLaunchCompletion();

// 消费者：先发自己的权重 / KV 加载，读前驱激活前再等
cudaGridDependencySynchronize();

放对位置比 API 本身难。对照实验把触发点从「生产者最后一次权重 TMA 到达」前移到「TMA 刚刚 发出」，仅此一项追回 34.032 μs（三次轮换试验样本标准差 0.066 μs）。「早放行」不是核入口就放，而是：发出生产者自己的独立流量 → 释放后继 → 消费者只在真实激活依赖处等待。

依赖方案 拆开主体 配对持久化主体 缺口
默认 CUDA Graph 依赖 967.162 μs 776.942 μs 190.220 μs
全边 PDL 809.626 μs 777.123 μs 32.503 μs

以默认依赖臂的 776.942 μs 持久化值为公共基准，PDL 把 190.220 μs 压到 32.5 μs，追回 82.8%（约 157.5 μs）。这就是微信文「两行代码追回 158 μs」的来源。

逐类边消融：没有一条边独占收益

单独打开的 PDL 边 相对默认依赖节省
QKV → attention20.518 μs
attention → O projection32.673 μs
O projection → up/gate22.417 μs
up/gate → down projection40.610 μs
down → 下一层 QKV42.203 μs
全部 79 条边153.980 μs

单独节省不可加总：每条边都会改变其他边看到的流量和准入环境。重要的是每一类都正向贡献，完整日程能组合起来。跨层边（down → next QKV）和 MLP 内边最大，符合「权重加载最长、最该被藏进前驱尾部」的直觉。

7. 滚动尾波：重叠从哪来

接受配置的核用 208 KiB 共享内存、每线程约 90 寄存器、640 线程 CTA。H100 单个 SM 放不下两个这样的 CTA。那 PDL 的「提前启动」重叠什么？

他们在 CTA 入口、加载发出、触发、依赖等待、CTA 出口插入 %globaltimer / %smid。三次带探针运行观察到：

  • 全部 240 条观测到的核边界，都至少有一个后继 CTA 在前驱 grid 最后一个 CTA 退出之前就已经准入；
  • 同一 SM 上，后继 CTA 一定等前驱 CTA 完全退出才进入，没有双 CTA 共存；
  • 同 SM 退役到准入的最短间隔仅 0.256 μs；
  • 每次运行里，80 条边界中有 63–75 条会在前驱 grid 结束前发出至少一次后继权重或历史 KV 加载；
  • 没有一次依赖等待在前驱 grid 完成之前返回——网格级正确性仍在。

图：滚动尾波。前驱 CTA 陆续退役，后继 CTA 填入空 SM，先发独立 TMA，再在激活依赖点等待。

这就是笔记说的 rolling tail wave。PDL 没有打破 SM 资源上限，而是把集中的启动开销打散到前驱尾部，让权重加载离开关键路径。因此优化必须在全链上评，单核 microbench 看不到这次交接。

8. 三条失败优化

追回 82.8% 之后，剩下的缺口引诱了三个「看起来很对」的补丁。它们全部失败，而且把诊断实验和正确模型核区分开写——这是原笔记比微信文更严谨的地方。

8.1 让相邻 grid 共驻同一 SM

正确 TK 主体是 208 KiB SMEM、三级权重流水。把存储压到 80 KiB 单级可以省空间，但主体从 804.409 μs 慢到 841.180 μs——流水线也被改了，无法单独给「共驻」定价。

于是做了一个故意不正确的机制对照：只算原来 16 个逻辑 K 分区中的 4 个，SMEM 做成循环别名的 4 页布局，加载器仍发完全部 4 块权重 TMA。同一份 device function / SASS，用动态 SMEM 配额控制能否双 CTA 共驻（65 KiB 允许 vs 128 KiB 强迫单 CTA）：

依赖 允许 2 CTA/SM 强迫 1 CTA/SM 挡住共驻的代价
默认依赖 891.970 μs 891.642 μs −0.328 μs（≈0）
全边 PDL 709.015 μs 760.016 μs +51.001 μs（+7.19%）

默认依赖下共驻几乎没价值；PDL 下共驻值约 51 μs。但 51 μs 比正确链剩余的 26.6 μs 还大——因为这个诊断核几乎去掉了算术、CTA 异常短，准入权重被放大。它只证明方向：同 SM 共驻是一项真实机会，正确核因为寄存器和 SMEM 要持有到整个 CTA 退役，摸不到这项机会。

8.2 缩小正确核直到能共驻（micro-tile）

唯一保住正确性的办法是降低核自己的 footprint。对象是 opcode 4（O-proj + residual）：把每 warp 的 128 列片改成 16 列 FP32 寄存器 tile。寄存器从 88 降到 37，零 spill、SASS 无 LDL/STL；H100 按 256 寄存器/warp 粒度，两颗 CTA 需要 51,200 / 65,536，算得过来。插桩回放里，该变体在 1,792 次可能的同 SM 后继进入中记录到 1,714 次；原核是 0。

然后它还是输了。

opcode-4 链（16 层权重） 默认边 PDL 边
原核，1 CTA/SM 101.760 μs 71.024 μs
微块化，允许 2 CTA/SM 105.280 μs 78.608 μs
微块化，同一 SASS，挡住共驻 105.200 μs 75.152 μs

微块化单独就要 3.42% 税（约 0.21 μs/层）。共驻再引入资源竞争（78.608 vs 挡住共驻的 75.152）。正确核付了两次钱，最快的正确配置仍是原来的单 CTA + PDL。

8.3 虚拟张量并行（VTP）把依赖收到 shard

Hazy 原 megakernel、以及后来的 MPK / Event Tensor，都能在算子内部按 tile 同步。笔记把这种单卡、无集合通信、只为收窄依赖边界的模式叫做 virtual tensor parallelism：up/gate 的 8192 维 SiLU 输出切成 4 个 2048 维 shard，down projection 按同一 K 范围 split-K，各等各的计数器。

实现上仍用 PDL 做整网格提前准入；只把激活等待从 cudaGridDependencySynchronize（等整个 up/gate grid）改成轮询对应 shard 计数器。生产者布局两边相同。

匹配生产者，三进程均值 主体延迟 相对持久化主体缺口
整网格 PDL 等待 810.059 μs 32.042 μs
按 shard 信号等待 814.945 μs 37.077 μs

更细的依赖慢了 4.886 μs。原因：PDL 已经让整个 down 网格提前进来、权重 TMA 已经藏掉；shard 轮询是额外开销，而激活就绪并不能再藏更多东西。调度粒度不是越细越好。

三条失败的共同形状：凡是能让正确核共驻或把依赖收到 tile 的软件旋钮（更少页、更少 warp、更少寄存器、更小 tile、更细全局信号），都会改算子自己的吞吐。机会无法在核内部被干净定价；剩下的缺口不能靠再拧软件旋钮补上。

9. 剩余 2.7% 与缺失原语

完整 decode 步仍落后 26.584 μs；主体落后约 32.5 μs，摊到 79 条拆开边界约 0.411 μs/边界。笔记认为这与 PDL 保不住的部分一致：

资源生命周期

寄存器、SMEM、屏障、加载器/消费者角色在每个核边界死亡重建。持久化在同一颗 CTA 内回收这些状态。

持有粒度太粗

流水线前段用完的页/寄存器，也要等到整个 CTA 退役才释放。后继加载器进不来。

重复的 CTA 准入

每个 grid 都要再付一遍调度与 per-kernel 初始化。PDL 只能提前打开程序端口，不能省略这笔税。

调度上下文

后继通过网格级 programmatic port 才有资格；新 CTA 不能继承被它替换掉的那颗 CTA 的常驻调度器上下文。

缺失的硬件/运行时原语：阶段作用域资源生命周期

共驻实验指向一个 PDL 目前没有暴露的原语：phase-scoped resource lifetime。加载器用完某一级 SMEM 或寄存器 tile 之后，应能在消费者/epilogue 仍在跑时退役这块存储，让后继的加载器占用腾出来的容量。这样不必靠压低静态 footprint、破坏多级流水去换共驻。

证据并不能证明剩余 26.584 μs 全部来自「释放太晚」。它只是把「晚释放」从抽象的 launch 开销，变成一项可操作的解释，并且说明：要填完最后几个百分点，需要的不是又一个 cache hint 或自旋循环，而是比网格级 PDL 更细的资源移交。

10. 和 MPK / Event Tensor 的关系

原笔记主动引用同目录下两篇工作，用来标定「细粒度依赖」在编译器路线上的位置，而不是拿它们当基线打榜。

工作 主张 和本文的交点
MPK / Mirage Persistent Kernel 编译器把张量程序降到 SM 级任务图，在一颗 persistent mega-kernel 里去中心调度；相对 vLLM/SGLang 端到端最多约 1.7×。 把 Hazy 手写 megakernel 当成「性能上限 + 工程成本」的动机。本文则说：若目标只是 H100 batch-1 解码吞吐，网格级 PDL 已经能逼近手写常驻，不一定先上解释器。
Event Tensor 把 tile 完成事件做成 IR 里的张量，编译动态 shape / MoE 的 persistent kernel；评测里 serving 基线已经包含 CUDA Graph、PDL、torch.compile。 生产系统确实在用 PDL。本文给出 PDL 能复现多少「手写常驻」的量化上界，以及它做不到的那一段（阶段级资源生命周期、tile 级依赖在拆开核上的负收益）。
Hazy Llama-1B megakernel 常驻解释器 + SMEM 分页 + 四路 MLP 计数器，H100 < 1 ms。 本文的 persistent 对照就是这份代码（fork 自 HazyResearch/Megakernels commit 7309cec，ThunderKittens 钉在 664c108）。

分工可以记成一句话：Hazy / MPK / Event Tensor 在问「如何把整模写成（或编译成）一颗核」；Qiang 等人在问「若坚持普通核模型，调度原语已经值回多少」。两条线不互斥。对可维护、可组合的推理栈，PDL 链是更便宜的 97%；对还要跨 GPU 通信重叠、动态 MoE、符号 shape 的场景，persistent 编译器仍有 PDL 给不出的调度自由度。

11. 结论、边界与可复现要点

分析过程（压缩版）

  1. 锁定 Hazy 的 P32/D128 Llama-1B 工作负载，把常驻 VM 拆成与 opcode 一一对应的 81 个 TK 核，CUDA Graph 一次提交。
  2. 只改图边语义：默认完成依赖 vs programmatic 依赖。两边同二进制、同入口，排除算子实现差异。
  3. 用匹配作用域把空洞定位到 16 层主体（190 μs），确认不是 CPU、不是 LM head。
  4. 把 PDL 触发点从 TMA 到达前移到 TMA 发出；全边打开后主体缺口从 190 μs 降到 32.5 μs（82.8%）。
  5. 用 SMID/时钟探针证明重叠来自滚动尾波，而非同 SM 双 CTA。
  6. 逐类边、issue-vs-arrival、共驻诊断、micro-tile、VTP 全部做对照；失败实验用来划清「调度能买到的」和「持久化才有的」。
  7. 把剩余 26.6 μs 归因到 CTA 级资源生命周期，并提出阶段作用域释放这一缺失原语。

结论

  • 对这个 H100 batch-1 解码，不必上常驻解释器就能拿到绝大部分 megakernel 收益；PDL 把 81 核链推到持久化吞吐的 97.4%。
  • 「几乎」仍然重要。Persistent VM 继续赢。缩小 SMEM、缩小寄存器 tile、更细全局信号，全部填不满最后 2.7%。持久化买到的是更便宜的有状态交接，PDL 没有把它暴露到 grid 之间。
  • 有用的边界：多数场景优先把 PDL 边和触发时机做对，保留普通核的可组合性；不要为了共驻去破坏已经很快的多级流水。最后几个百分点留给硬件/运行时的阶段级资源原语，或真正需要常驻调度器的工作（通信重叠、动态控制流）。

不要过度外推

  • 单卡、无 TP、1B、batch=1、BF16。Hazy 后续的 70B 吞吐型 / 多 GPU megakernel 不在对照里。
  • 默认依赖端到端行是单进程；主体 190 μs 效应很大，但形式上弱于 PDL 的三进程均值。
  • 4 页别名配置是错误机制对照，仓库明确禁止当模型结果引用。
  • CUDA 12.8 是持久化基线的编译约束：CUDA 13.1 的 H100 ptxas 会拒绝 VM 核里的 setmaxnreg。PDL-only 模块可以用 13.1 编。
